# 题单导入接口规范 v1

把一个「出题工程」整包导入评测站（Hydro）。**题单结构完全参照现有出题工程的规范**
（`题目库_规范.md` 的定义），导入器按该结构自动识别题面、测试数据与标程。

---

## 一、题单结构规范

一个题单是一个 **zip** 或一个**目录**，内部按下面两种形态之一组织（都支持）：

### 形态 A：标准出题工程（推荐，即现有 zip 的形态）

```
题单.zip
└── 题目库/                        ← 任意层级的容器目录（可为空，也可叫其它名字）
    ├── _索引.md                   ← 【可选】题单索引表，提供难度与考点
    ├── D01-最小值切分贡献/
    │   ├── 题目.md                ← 【必需】题面（Markdown）
    │   ├── 标程.cpp               ← 【必需】标准程序
    │   ├── 暴力.cpp               ← 忽略
    │   ├── 生成器.py              ← 忽略
    │   ├── D01-洛谷上传.zip        ← 忽略
    │   ├── 大样例/                 ← 忽略（大样例.in/.out）
    │   └── data/                  ← 【必需】测试点
    │       ├── 01.in  01.out      ←   两位数字命名、成对出现
    │       ├── 02.in  02.out
    │       ├── …
    │       └── 样例1.in  样例1.out ←   题目样例：按规范**不参与评测**，自动忽略
    └── G01-加边后最小生成树/
        └── …（同上）
```

### 形态 B：扁平题包（没有分类号时也能用）

```
题单.zip
└── A+B问题/
    ├── 题目.md
    ├── 标程.cpp
    └── data/01.in 01.out …
```

### 字段与命名规则

| 项目 | 规则 | 说明 |
|---|---|---|
| 题目目录 | `<分类号>-<题名>` | 分类号 = 1~3 位大写字母 + 两位数字（`G01`/`DP01`/`ST04`）；题名用中文，不含 `/ \ : * ? " < > \|` |
| **题目标识（pid）** | 取**分类号** | 站点上题目的唯一标识，如 `G01`；形态 B 无分类号时用目录名清洗后的字母数字串 |
| **标题** | 取分类号后的**题名** | 如 `加边后最小生成树` |
| **题目编号**（老师侧） | **系统分配**：`T` + 5 位数字（如 `T00012`） | 导入时定下来、跟着题走；老师只用它定位查找（「T00012 那道题」），**不能自己指定**；学生看不到它 |
| **默认英文名**（学生侧） | `--code [分类号=]英文名`，可留空 | 例如 `--code G01=candy`。只允许小写字母、数字、下划线；**学生用它建文件夹、命名源文件、写 `freopen`**。留空则加进比赛时再填（本场管理里也能改） |
| 题面 | `题目.md`（也认 `题面.md`/`statement.md`/`problem.md`/`README.md`） | Markdown，站点按 Markdown 渲染（支持 `$…$` 公式） |
| 测试点 | `data/` 下 `<数字>.in` + 同名 `.out` | 按数字**升序**重排为站点的 `1.in/1.out`、`2.in/2.out`…（前导零无关） |
| 标程 | `标程.cpp`（也认 `std.cpp`/`solution.cpp`/`ac.cpp`/`correct.cpp`） | 导入后站点会**自动编译并评测标程**，可用于反向验证数据与标程是否一致 |
| 难度 | `_索引.md` 的「难度」列 | 按洛谷 7 级标签映射为站点难度 1~7，原始标签保留为标签 `难度:<原文>` |
| 考点 | `_索引.md` 的「考点」列 | 按规范用全角竖线 `｜` 分隔（也兼容 `\|`、`、`、`,`、`/`），每个考点作为一个标签 |
| 时限/内存 | 接口参数（默认 1000ms / 256MB） | 也可用 `--time` / `--memory` 覆盖 |

> **两个名字别混**：**题目编号**（`T00012`，老师侧、系统分配、不能改）只是老师找题用的；
> 学生看到的是**英文名**（`candy`，学生侧，在导入/建题时给个默认值，加进比赛时可以按场次改）。
> 判断规则见《[设计说明](../docs/设计说明.md)》第四节。

### 自动忽略的文件

`*.exe`、`*-洛谷上传.zip`、`大样例/`、`data/样例*`、`__pycache__/`、`跑数据.py`、`暴力.cpp`、`生成器.py`
—— 这些是出题过程的附属物，不参与导入（与你现有的洛谷打包规范一致）。

### `_索引.md` 的格式（可选但推荐）

```markdown
| 编号 | 分类号 | 题名 | 难度 | 考点 | 测试点 | 大样例 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 001 | G01 | 加边后最小生成树 | 提高+/省选− | 最小生成树｜树上路径最大边｜增量维护 | 20 + 样例2 | 1 组 | ✅ 已通过 |
```

导入器只读取 **分类号 / 题名 / 难度 / 考点** 四列。

## 二、导入结果

每道题在站点上生成一个题目：

| 站点字段 | 来源 |
|---|---|
| pid | 分类号（冲突时：默认跳过，`--overwrite` 则先删除旧题再导入） |
| 标题 | 题名 |
| 题面 | `题目.md` |
| 标签 | 参数 `--tag` 指定的标签 + 考点 + `难度:<原文>` |
| 难度 | 难度标签映射值（1~7） |
| 时限/内存 | 接口参数 |
| 测试点 | `data/<数字>.in|.out` 顺序重排后的全部数据（**样例不参与评测**） |
| 标准程序 | `标程.cpp`（导入后自动评测，可在题目页「提交记录」里看到结果） |

另外**考试服务这一侧**还会记两样东西（不在评测站上，见 `data/problem_codes.json`）：

| 考试服务的字段 | 含义 |
|---|---|
| `code`（**题目编号**） | `T` + 5 位数字，导入时由系统分配、跟着题走（报告里是 `number`）。老师只用它定位查找 |
| `name`（**默认英文名**） | `--code G01=candy` 给的那个（报告里是 `name`）；留空就加进比赛时再填。学生看到的就是它 |

## 三、命令行接口

**在部署根目录（服务器上是 `/root/csp-exam`）用模块方式跑**：

```bash
cd /root/csp-exam
python3 -m csp_exam.core.importer <zip 或 目录> [选项]
```

> 别直接 `python3 csp_exam/core/importer.py` —— 它是包内模块（用相对导入），直接跑会报
> `ImportError: attempted relative import with no known parent package`。

| 选项 | 说明 |
|---|---|
| `--tag 名称` | 额外打上的标签，可重复；例如 `--tag 寒假作业 --tag CSP-J` |
| `--time 毫秒` | 时限，默认 1000 |
| `--memory MB` | 内存，默认 256 |
| `--only G01,D01` | 只导入指定题目标识（逗号分隔） |
| `--code [分类号=]英文名` | 给这道题定一个**默认英文名**（可重复）。`--code G01=candy` 按分类号指定；整包只有一道题时可以直接 `--code candy`。**题目编号由系统分配**（`T00001` 那种），不在这里指定；留空则加进比赛时再填 |
| `--overwrite` | 站点已存在同标识题目时先删除再导入（默认跳过） |
| `--dry-run` | 只解析并生成题目包、打印报告，**不导入站点**（用于先检查结构）。注意：**这一步仍会把新题目编号登记进 `data/problem_codes.json`**（见下面"注意事项"第 7 条） |
| `--workdir 目录` | 题目包输出目录（默认临时目录，导入后自动清理） |
| `--json 报告.json` | 把结构化报告写到文件 |

**退出码**：全部成功 `0`；有题目校验失败 `1`。

示例（都在 `/root/csp-exam` 下跑）：

```bash
# 先干跑，确认识别结果对不对（顺便给 G01 一个默认英文名 candy）
python3 -m csp_exam.core.importer 题单.zip --dry-run --code G01=candy

# 正式导入，并打上"寒假作业"标签
python3 -m csp_exam.core.importer 题单.zip --tag 寒假作业 --time 2000 --memory 512

# 只导入两道题，覆盖同名题目，并留档报告
python3 -m csp_exam.core.importer 题单.zip --only G01,D01 --overwrite --json /root/report.json
```

干跑的完整输出长这样（每题一行「编号 + 测试点数 + 包目录」，末尾汇总）：

```
识别到 1 道题
  [试运行] G01 加边后最小生成树：编号 T00012，20 个测试点 -> /tmp/problemset-xxxx/G01

共 1 道题：已生成题目包 1、校验失败 0，耗时 0.0s（试运行，未导入站点）
题目编号（老师侧）： G01→T00012
默认英文名（学生侧）： G01→candy
```

代码调用：

```python
from csp_exam.core.importer import import_problemset      # 注意是包内路径

# codes = {分类号: 默认英文名}；留空的题加进比赛时再填英文名
report = import_problemset("题单.zip", tags=["寒假作业"], codes={"G01": "candy"},
                           time_ms=1000, memory_mb=256)
print(report["ok"], report["imported"], report["failed"])
for p in report["problems"]:
    print(p["pid"], p["number"], p["name"])        # T00012 / candy
```

（老写法 `from import_problemset import import_problemset` 只在**先 `import csp_exam`**
注册过兼容模块之后才有效，别在脚本里用。）

## 四、HTTP 接口（教师端）

服务地址：`http://<你的服务器IP>:8080`（管理密钥见服务器 `/root/csp-exam/data/admin_key.txt`）。

### 1) 提交导入任务

```
POST /api/problemset/import?key=<管理密钥>
Content-Type: multipart/form-data
```

| 表单字段 | 必需 | 说明 |
|---|---|---|
| `file` | 是 | 题单 zip 文件（字段名也接受 `zipfile`） |
| `tag` | 否 | 额外标签，可重复 |
| `time` | 否 | 时限（毫秒） |
| `memory` | 否 | 内存（MB） |
| `only` | 否 | 只导入指定标识，逗号分隔 |
| `code` | 否 | 默认**英文名**，写法与命令行 `--code` 完全一致：`G01=candy` 逐题指定，整包只有一道题时可以直接写 `candy`。多题要一次给多个，字段里用**逗号分隔**（`code=G01=candy,DP01=t1`）；留空的题加进比赛时再填 |
| `overwrite` | 否 | `1` 表示覆盖同名题目 |
| `dry_run` | 否 | `1` 表示只解析不导入 |

> 题目编号（`T00001`）不在这里指定，导入时由系统分配。
> 只想先看识别结果就用 `dry_run=1`（注意它同样会登记新题目编号，见下面"注意事项"第 7 条）。

响应（立即返回，导入在后台进行）：

```json
{
  "ok": true,
  "job": "ps-1727262000-ab12cd",
  "message": "已接收题单（0.0 MB），正在后台导入",
  "report_url": "/api/problemset/report?key=...&job=ps-1727262000-ab12cd"
}
```

### 2) 查询导入进度与报告

```
GET /api/problemset/report?key=<管理密钥>&job=<任务号>
```

导入中：

```json
{ "ok": true, "state": "running", "progress": "已导入 5/17：G01 加边后最小生成树" }
```

完成后（`state` 为 `done` / `failed`）——下面这份是**干跑**的真实报告（`--dry-run`/`dry_run=1`，
只生成题目包不导入站点，`status` 是 `package-only`）：

```json
{
  "ok": true,
  "state": "done",
  "report": {
    "total": 1,
    "imported": [],
    "prepared": ["G01"],
    "skipped": [],
    "failed": [],
    "elapsed_s": 0.0,
    "problems": [
      { "pid": "G01", "title": "加边后最小生成树", "case_count": 20,
        "difficulty": 5, "difficulty_label": "提高+/省选−",
        "topics": ["最小生成树", "树上路径最大边", "增量维护"],
        "has_statement": true, "has_std": true,
        "number": "T00012", "name": "candy",
        "status": "package-only", "message": "仅生成题目包（dry-run，未导入站点）" }
    ]
  }
}
```

正式导入时 `status` 是 `imported`（`prepared` 为空、`imported` 有值），每题同样带
`number`（题目编号）与 `name`（默认英文名）；`number` 与旧字段 `code` 同值。

### 3) 错误码

| HTTP | 场景 |
|---|---|
| 400 | 没有上传文件 / 不是 zip / 表单不合法 / **文件超过上限（512MB）** |
| 403 | 管理密钥不正确 |
| 404 | 任务号不存在 |

教师端**没有上传表单页**：管理端导航里的「导入题单文档」只打开本文，
要上传就调上面这个接口（`curl`/脚本）或用命令行导入。

## 五、注意事项

1. **样例不参与评测**：`data/样例*.in/out` 与 `大样例/` 一律忽略（与你现有洛谷打包规范一致）；导入的测试点只有 `data/<数字>.in|.out`。
2. **幂等**：同一份题单重复导入，站点已有的题目会被跳过并在报告里列出；确需覆盖用 `--overwrite`（会删除旧题目及其提交记录，慎用）。
3. **标程即质检**：导入后站点会自动编译并评测标程。若标程不是 AC，说明该题的**数据或标程有问题**，可在题目页「提交记录」里看到具体判定（这是导入环节自带的免费质检）。
4. **题目包落盘位置**：宿主机 `/root/hydro/data/backend/import/<pid>/`（容器内 `/root/.hydro/import/<pid>/`）。注意这两个路径的对应关系，命令行里要用**容器内路径**。
5. **大文件**：数据文件按流式复制，不会整包读进内存；单次上传上限 512MB。
6. **编码**：题面与标程按 UTF-8 读取，遇到 GBK 会自动回退（Windows 下生成的文件常见）。
7. **`--dry-run` 也会登记题目编号**：编号分配走 `problems.assign_number()`，它总是写
   `data/problem_codes.json`（`--dry-run` 只挡住"导入评测站"这一步）。所以干跑之后想撤销，
   要把这次新登记的编号从 `data/problem_codes.json` 里删掉；不删也无害 —— 下次导入同一道题
   会沿用同一个编号。
8. **编号与英文名跟着题走**：同一道题重复导入（或 `--overwrite`）**不会换编号**；
   已经给过的默认英文名也不会被后来的导入冲掉（不传 `--code` 就保留原值）。
