# 题单导入接口规范

本文对应当前 `csp_exam.core.importer` 和 `/api/problemset/*` 实现，核对日期为 2026-10-11。此处是教师向题库导入题目的接口，与学生交卷接口不同，不改变考生提交的目录要求。

## 1. 输入方式和题包结构

- HTTP 接口：一次上传一个 ZIP，不接收本机目录路径或逐文件文件夹表单。
- 命令行 / Python 调用：接收 ZIP 路径或本机目录路径。
- 管理端“新建题目”的文件夹 / ZIP 上传使用另一个接口 `/admin/problem`，不应与本接口混用。

建议每题使用“分类号-题名”目录；分类号格式为 1～3 个大写字母加两位数字，例如 `G01`、`DP01`。外层目录名称不限，也可以只导入单题目录。

```text
题目库/
  G01-加法/
    题目.md
    标程.cpp
    problem.json             # 可选：评测限额、默认英文名等
    data/
      01.in
      01.out
      extreme.in
      extreme.ans
    大样例/                  # 可选：供学生下载，不参与评测
      样例.in
      样例.out
  G02-另一题/
    题目.md
    标程.cpp
    data/...
```

每题必须有题面、标准程序及至少一组完整的输入 / 答案文件。题面候选名按优先级为 `题目.md`、`题面.md`、`statement.md`、`problem.md`、`README.md`；标程候选名为 `标程.cpp`、`std.cpp`、`solution.cpp`、`ac.cpp`、`correct.cpp`。请按这些名称的大小写命名，文本建议使用 UTF-8。

评测数据可直接放在题目目录下，或放在 `data`、`testdata`、`tests`、`test` 的下一层；更深的目录不会识别为评测数据。同一目录内，`.in` 与同文件名主体的 `.out` 或 `.ans` 配对，主体不限于数字，主体的大小写必须一致。扩展名大小写均可；同一输入同时有 `.out` 和 `.ans` 会报重复答案。缺输入、缺答案或重复数据会使该题失败。

名称为 `样例`、`sample`、`example`、`ex`，后面可跟数字或“下划线 / 短横加数字”的数据不计入测试点，例如 `data/样例1.in`、`data/sample_1.out`。其他名称不会仅因包含“sample”而自动排除。大样例建议放在独立的 `大样例/` 目录中。

可选 `problem.json` 示例：

```json
{"name":"sum","time_ms":1000,"memory_mb":256,"case_count":2}
```

`time_ms`、`memory_mb` 必须是正整数，优先于本次导入的全局 `time`、`memory`；`case_count` 如填写，必须等于识别到的完整评测数据组数。`name` 为默认英文名，显式 `code` 参数优先于它。可选 `id`、`title` 字符串覆盖批量导入时的内部标识与标题；`only` 仍按目录推导的标识筛选，`code` 映射可使用目录标识或覆盖后的标识。JSON 仅支持上述六个字段，其他字段会报错。

分类号是题库内部 `pid`；教师定位用的编号由系统分配，形如 `T00001`。默认英文名用于配置比赛时预填，也可留空；学生使用的英文名最终以该场比赛设置为准。英文名限制为 1～32 个小写字母、数字或下划线。

导入保存题面、评测数据、标准程序、样例及评测限额，不会原样归档全部命题工程。生成器、暴力程序等附件不是自动执行项；特殊判题器、自定义测试点权重或子任务计分配置不会自动导入。

## 2. 大小上限和校验边界

- HTTP multipart 请求体默认上限 **64 MiB**，包括表单开销；由服务端环境变量 `CSP_MAX_PS_UPLOAD_MB` 配置，客户端不能自行提高。
- 题单 ZIP 中全部成员的未压缩文件总量上限 **512 MiB**，压缩包目录项与文件项合计不得超过 **20000** 个。这个限制也适用于命令行读取 ZIP。
- 正式写入时，单题全部上传文件的总量还受 `CSP_MAX_PS_UPLOAD_MB` 限制，默认 **64 MiB**，最多 **20000** 个文件；因此压缩后很小的单题也可能在写入阶段失败。
- ZIP 的越界路径、归一化后的重复路径、符号链接和加密文件会被拒绝。

1 MiB = 1048576 字节。命令行读取普通目录不受 HTTP 请求大小限制，但写入单题仍受上述单题限制。

`dry_run` 是结构预检查：读取题面 / 标程、配对数据、检查 JSON 的基本格式、内部标识与默认英文名，不分配题号、不写题库。它不编译或运行标程，不核对标准答案、约束、样例正确性或部分分，也不会完整复现正式写入的全部校验；不能把预检查通过当作题目验收通过。

同目录标识的已有题默认跳过。`overwrite=1` 会覆盖该题；涉及在途评测时拒绝换数据，已受影响的成绩撤回并要求重测。批量导入按题执行，部分题目失败不会回滚已经导入成功的其他题目。

## 3. HTTP 请求

教师登录后发送 `POST /api/problemset/import`，格式为 `multipart/form-data`，携带管理会话 Cookie。外部工具也可用 URL 查询参数 `?key=管理密钥`；密钥不是 multipart 字段，也不是 Bearer 请求头。跨来源 POST 还必须携带有效的 URL 管理密钥。

| 字段 | 含义和默认值 |
| --- | --- |
| `file` | 必需文件字段，一个 ZIP；兼容旧字段名 `zipfile`，其他文件字段或多文件上传返回 400 |
| `code` | 可选默认英文名：`G01=sum,G02=game`；选中仅一道题时可直接填 `sum`；不用于指定系统题号 |
| `time` | 全局时限，正整数，毫秒；默认 `1000`，单题 JSON 可覆盖 |
| `memory` | 全局内存限制，正整数，MiB；默认 `256`，单题 JSON 可覆盖 |
| `only` | 仅选择这些目录推导出的内部标识，逗号分隔，如 `G01,G02`，匹配不区分大小写；筛选不到任何题时任务失败 |
| `tag` | 一个额外标签；不按逗号拆成多个标签 |
| `overwrite` | 值为 `1`、`true` 或 `on` 时覆盖；省略或其他值为否，区分大小写 |
| `dry_run` | 值为 `1`、`true` 或 `on` 时只预检查；省略或其他值为否，区分大小写 |

请求成功接收时，HTTP 200 返回 JSON，例如：

```json
{"ok":true,"job":"ps-时间戳-随机串","message":"已接收题单……","report_url":"/api/problemset/report?job=ps-时间戳-随机串"}
```

此时还没有确认导入成功。轮询 `report_url`，即 `GET /api/problemset/report?job=任务ID`。查询同样要求教师鉴权；用密钥的外部工具需要自行追加 `&key=管理密钥`，返回的 `report_url` 不含密钥。

查询响应最外层的 `ok:true` 只表示任务存在并且查询成功。`state` 取值为：

- `running`：处理中，`progress` 为文字进度。
- `done`：流程完成且 `report.ok=true`；可能是全部导入、全部跳过或预检查通过，应继续查看分类列表。
- `failed`：题目有失败、未识别到任何题目或后台异常；仍可能已经导入部分题目。

正常解析后，响应包含 `report`：`dry_run`、`total`、`imported`、`prepared`、`skipped`、`failed`、`problems`、`codes`、`names`、`elapsed_s`、`ok`，必要时还有 `error`。前四个分类列表保存内部标识。`problems` 中逐题给出 `pid`、`title`、`case_count`、`status` 和 `message`；**仅正式成功导入的条目保证有 `number` 与 `name`**，`code` 是 `number` 的兼容字段，绝非学生英文名。预检查通过的状态为 `validated`，列入 `prepared`。后台异常可能只返回任务级 `error`，没有完整 `report`。

| HTTP 状态 | 含义 |
| --- | --- |
| `200` | 接收任务成功，或任务查询成功；不是“全部题目导入成功” |
| `400` | 请求体超限、表单 / 文件字段错误、非 ZIP 开头、无文件或全局限额参数无效 |
| `403` | 教师鉴权失败，或 POST 来源检查失败 |
| `404` | 查询的任务不存在、已被清理或服务重启后丢失 |
| `429` | 已有两个导入任务运行，须稍后重试 |
| `500` | 导入组件不可用，或无法保存文件 / 启动任务 |

带 ZIP 标识但损坏的压缩包、ZIP 展开超限和逐题内容错误通常在后台发现，表现为 HTTP 200 查询到 `state=failed`，不能只靠上传响应的 HTTP 状态判断。

任务临时文件放在配置的数据目录 `ps-jobs/` 中，任务正常结束后清理。任务查询状态仅存在于当前进程内存，后续新任务会清理较旧的已完成状态；服务重启后无法继续查询旧任务。已成功写入的题目是持久数据，不随任务状态清理；服务在导入中途停止时不能保证整包完成，须重新检查题库和报告。异常终止可能留下临时目录。

## 4. 命令行示例

在项目根目录运行：

```bash
python3 -m csp_exam.core.importer 题单.zip --dry-run
python3 -m csp_exam.core.importer ./题目库 --only G01,G02 --dry-run
python3 -m csp_exam.core.importer 题单.zip --code G01=sum --code G02=game --time 1000 --memory 256 --json 导入报告.json
```

命令行标签参数 `--tag` 可重复。报告写入 `--json` 指定的文件，目标父目录应已存在；退出码 0 表示报告通过，退出码 1 表示报告失败。压缩包无法打开等异常也会使进程以非零状态退出。

网页 `/docs/problemset` 和 `/docs/problemset.md` 都是渲染后的 HTML 文档；后者的 `.md` 后缀不表示返回原始 Markdown。

## 5. 系统导出的可迁移题包

管理端「导出 ZIP」产生 `csp-problem/1` 清单题包，本版本的上述 API 可直接导入。清单逐文件校验完整性，保留测试点文件名、样例分类、标签和附件；明确导出的空题面或未保存标程亦可迁移。普通命题工程仍按第 1 节要求提供题面和标程。目标机器题目编号重新分配，覆盖时保留目标编号；完整用法见 [题目导出与迁移](../docs/题目导出与迁移.md)。
