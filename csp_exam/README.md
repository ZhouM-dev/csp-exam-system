# CSP 模拟赛考试服务

给中小学信息学集训用的模拟考试工具：**老师维护可复用的名单分组 → 每场考试随机分配考号 →
学生用本场链接 + 考号进入 → 看题面、交考号文件夹 → 自动判分 → 老师出成绩表**。

学生**不需要注册、不需要密码**，只要打开老师给的考试链接、输入自己的考号。

| 入口 | 谁用 | 能做什么 |
|---|---|---|
| `http://<你的服务器IP>:8080/` | **学生**（凭考号） | 参赛 / 交文件夹 / 看题面 / 考生须知 / 查成绩 |
| `http://<你的服务器IP>:8080/admin?key=<管理密钥>` | **管理员** | 全部管理页面（密钥在服务器 `/root/csp-exam/data/admin_key.txt`） |
| `http://<你的服务器IP>/`（评测站） | 只有管理员 | 题库与判分（比赛全在考试服务这边） |

> **考号是按场次随机分配的**：同一个学生在"周三模拟赛"里可能是 `GD-S10029`，在"周五模拟赛"里
> 可能是 `GD-J07915`。每场考试的考号互不相关，所以**每场都要用那一场的考试链接**进入
> （链接形如 `http://<你的服务器IP>:8080/enter?c=c1`，考号表上会印出来）。
> 好处：考号与姓名/名单顺序毫无关系，学生猜不到彼此的号；同名同姓、跨班重名也不会串。

> **本站现在是"只办比赛"的精简模式**（补丁在服务器 `/root/csp-ui/`）：
> 评测站**不开放注册**，题库只对管理员开放，管理员登录后导航只留「比赛 / 题库 / 评测记录」等必要项。
> 调整方式：改 `/root/csp-ui/csp-site.js` 里的 `HIDE_SECTIONS`（对访客隐藏的首页板块）与
> `HIDE_FOR_ADMIN`（对管理员隐藏的导航项），再跑 `bash /root/csp-ui/install.sh /root/csp-ui`。
> Hydro 是第三方程序，模块无法真正删除，这里用的是**服务端关权限 + 界面隐藏**，随时可恢复。

## 一、三种赛制

新建比赛时三选一。**三种赛制的提交方式完全一样**：学生交一个以考号命名的文件夹（上传文件）。
差异只剩两件事：

| 赛制 | 程序怎么写 | 怎么计分 | 适用 |
|---|---|---|---|
| **OI** | **标准输入输出**（`cin`/`cout`、`scanf`/`printf`，不需要 freopen） | 每题按**最后一次**提交 | 国内 OI / NOIP 风格 |
| **IOI** | **标准输入输出** | 每题取多次提交的**最高分** | IOI / 国际赛风格 |
| **CSP** | 必须 **freopen** 读写 `<英文名>.in` / `<英文名>.out` | 每题按**最后一次**提交 | CSP-J/S 复赛模拟 |

**赛中三种赛制都看不到分**（没有"反馈模式"这类开关）：判分照常跑，但学生端在老师点
「公布成绩」之前看不到任何判定与分数 —— 比赛页只显示「已提交 / 未提交」，交卷回执只查
文件结构，查成绩页直接说"成绩还没有公布"。老师点「发布成绩」后学生立刻能在「查成绩」页
看到分数（可随时收回），**IOI 也一样**（它以前是交完就实时给分）。
CSP 的文件读写由服务在提交前自动"包装"实现（见文末技术说明）。

## 二、题目编号与英文名（两个概念，别混）

| 概念 | 谁用 | 长什么样 | 在哪设置 | 作用 |
|---|---|---|---|---|
| **题目编号** | **老师** | `T00001`（`T` + 5 位数字） | 建题/导入时**系统分配**，**不能改** | 定位查找（「T00001 那道题」） |
| **英文名** | **学生** | `candy`、`m02`（小写字母/数字/下划线） | **建题时给个默认值 + 本场配题时可改** | 学生建文件夹、命名源文件、写 `freopen("candy.in")` |

- **老师界面上两列都显示**：本场管理的题目表、题目列表页都是「题目编号 + 英文名」。
- **学生界面上只有英文名**：比赛页题目表、题面页、交卷回执、考生须知里都看不到 `T00001`。
- 英文名只允许**小写字母、数字、下划线**（它要当文件夹名和文件名）；**同一场里不能重名**。
- 某道题在本场**没填英文名**时，系统按本场顺序自动给 `p1`、`p2`…（占位），
  老师在本场管理的「英文名」列改一次即可；改了之后学生交的文件夹名要跟着换。
- 同一道题加进不同场次，**题目编号不变**（跟着题走），英文名可以按场次不同。

## 三、老师怎么用

浏览器打开 `http://<你的服务器IP>:8080/admin?key=<管理密钥>`（密钥在服务器
`/root/csp-exam/data/admin_key.txt`）。导航：比赛列表 · 名单分组 · 题目列表 · 新建题目 ·
导入题单文档 · 学生端入口；进了某一场还会多出「本场管理 / 成绩总表 / 考号表」。

> 从评测站导航「比赛」进入可免密钥（用密钥进过一次后服务会记住）。

### 1. 新建比赛
填比赛名称、选赛制（OI / IOI / CSP）、选**级别**（J 入门级 3.5 小时 / S 提高级 4 小时，
级别决定考号里的字母与默认时长），点「新建」。可以建任意多场，互不影响
（成绩、名单、上传文件都分开）。建完自动进「本场管理」。

### 2. 名单与考号（每组可反复用，考号每场随机）

**先建分组**（管理端「名单分组」）：给一批学生起个名字（如"初三1班"），把姓名一行一个粘进去。
**分组可以反复用于不同考试**，不用每次重新粘名单。

然后在本场管理的「2. 名单与考号」里：

- **① 从分组导入**：选分组；**② 或者临时粘贴名单**（每行一个姓名，也可以从 Excel 整列粘）。
- **追加 or 重建**：*追加*（默认）已有学生保持原考号、新人拿新号；*重建*清空本场名单、全部重发。
- 考号用「本场设置」里的**考号前缀**（默认 `GD`）+ 级别字母 + 5 位随机数，如 `GD-S10029`。
- **名单和考号就在同一节里**（导入控件下面就是「本场名单」表：考号 / 姓名 / 评测站账号 / 提交），
  不用再往下翻。
- 「**重新随机分配考号**」按钮：把本场考号全部重排（只在**还没人提交**时可用 —— 否则成绩会对错人）。
- 「**考号表**」：打印出来发给学生，上面印着本场考试链接 + 考号↔姓名对照 + 发给学生时的提醒清单。

**考号是纯随机数**（`00001`~`99999` 里随机取、场内不重号），不是 `1..人数` 的排列：
号码与姓名、名单顺序、机位都无关，学生猜不到别人的号。已经导进名单的人再导入一次**不会换号**。

> **每场都要把本场链接发给学生**：`http://<服务器>:8080/enter?c=<比赛id>`。
> 学生从链接进 → 输入考号 → 直接进本场。不带考场编号时，只有当这个考号只出现在一场里才自动进入。

### 3. 本场管理：一页一个「保存」按钮

「本场管理」这一页的**本场设置 / 名单与考号 / 题目**三个区域在**同一个表单**里，改完点页面底部
**唯一的「保存」**，一次全提交，顶部会给出结果（如 `保存成功 —— 本场设置（时长 240 分钟）；
已保存 3 道题：第 1 题 candy（T00004）…`）。
页面上的「公布成绩 / 关闭提交 / 重新随机分配考号 / 提前建好账号」是**立即生效的动作**，
不走「保存」这条路：前两个在保存表单外面，后两个在名单表下面、用 `formaction` 直接提交到各自
的接口（`<form>` 不能嵌套，所以没给它们单独套表单）。
**本场设置里没有「反馈模式」这一项**（赛中零反馈是唯一行为，见第一节）；「成绩总表」也不在本页，
从导航或比赛列表每行的「成绩」按钮进。

**配题区两块，从上到下是「题库待选」→「本场题目」**：先在待选里点「加入」，
加进来的题就出现在下面的本场题目表里。

「**题库待选**」表格按**标题**搜索（`A+B`、`糖果分配`…），点「加入」加进本场；
读不到题库时可以展开「手动填写」直接写 `G01,G02`（也可以写 `G01:candy` 顺便给英文名；
**在这里动过就以这里为准**）。题库里没有想要的题？→「新建题目」。

「**本场题目**」用表格配（一行一道题）：

| 列 | 说明 |
|---|---|
| 顺序 | 第几题（加进来的顺序就是第 1、2、3… 题） |
| 题目编号 | `T00004` 这种，系统分配，只读 |
| 英文名（可编辑） | 学生要用的名字；加题时自动填题库里的默认值，可以直接改 |
| 题目 | 标题（题库里来的） |
| 读写的文件 | 跟着英文名实时变成 `candy.in / candy.out` |
| 满分 | 每题一行，默认 100 |
| 操作 | ↑ 上移 / ↓ 下移 / 移除 |

### 4. 题库里没有想要的题？直接建一道

管理端「**新建题目**」（或本场管理配题区的链接）。这一页**只有一个表单**：
**选完出题文件夹就在浏览器里认一遍**（本地读文件、**不上传**），标题/题面/标程自动填进表单，
页面上给一行识别结果（识别到哪道题、题面/标程有没有、几组评测数据、几个大样例文件、
几组题目样例）；核对、改完再点「**建题并导入评测站**」——**这时才把整个文件夹传上去**，
服务端建题时会**再认一遍**（以服务端认出来的为准）。

**推荐直接选整个出题文件夹**，按出题工程结构识别：

```
题目库/                          ← 容器目录（叫什么名字都行）
└── G01-加边后最小生成树/
    ├── 题目.md                  ← 题面（自动认）
    ├── 标程.cpp                 ← 标程（自动认，也可以叫 std.cpp/solution.cpp）
    ├── data/01.in 01.out …      ← 评测数据（数字命名、成对，自动收集）
    ├── 大样例/大样例.in 大样例.out  ← 大样例（单独存档，学生可下载）
    ├── 样例1.in 样例1.out        ← 题目样例（**不参与评测**，也给学生下载）
    └── 暴力.cpp / 生成器.py / 洛谷上传.zip   ← 自动忽略
```

- 也可以手选成对的 `.in`/`.out`（或 `.ans`），或打包成一个 zip（按名字自然排序配对）。
  **zip 在浏览器里看不了**（浏览器不解压），页面会提示直接点「建题」，由服务端解开并识别。
- **题目编号由系统分配**（`T00001` 这种），不用填；**「英文名（默认）」可留空** ——
  填了就是加进比赛时的默认值（本场还能改），留空则加进比赛时按顺序给 `p1`、`p2`…。
- 题面可以直接在页面上改、点「预览」看学生视角；标程是**可编辑的代码框**（识别到就填进去，
  没识别到也可以直接粘）。
- 建题时可以**单独传大样例**（表单里的「⑤ 大样例」；不参与评测、不影响分数，学生能在考试页下载）。
  没有"给已有题目补大样例"的入口 —— 大样例跟题一起定下来；要换就先**彻底删除**这道题再重建
  （见下面「删题目」：假删除不会腾出标识，重建还得先彻底删）。
- **建完不自测**：要确认数据/时限没问题，去「**题目列表**」点这道题那行的「**自己测试**」——
  把代码（默认填这道题的标程）粘进去跑一遍**全部测试点**，页面给逐点结果与最慢点用时；
  建题时记下了时限的题还会给出**占时限的比例**，最慢的点超过时限 50% 会预警。
  这是防止"题出错了自己不知道"的关键一步。
- **题面随时能改**（不用删了重建）：「题目列表」每行有「**改题面**」——
  打开就是这道题现在的题面，改完点「保存题面」，**学生那边立刻生效**（同一个页面还有「预览」，
  按学生视角渲染，改字的过程中会跟着更新）。改的只是题面：测试数据、时限、标程都不动。
  > 题面的"真身"在**评测站**（题目文档里那一份）；考试服务这边的 `data/statements/<pid>.md`
  > 只是**6 小时缓存**。所以保存时**两处一起写** —— 只刷缓存的话，6 小时后缓存过期，
  > 题面会自己变回旧的（老师会以为白改了）。
- **可以建重复的题（不用先删旧的）**：站点上已经有同标识的题目时，新的一份会**自动换个
  内部标识**（`T9101` 建过了就落成 `T9101b`，再往后 `c`、`d`…），旧的那道**原样不动** ——
  两份都在「题目列表」里，各拿各的**题目编号**，互不影响。提示里会说一句
  「站点上已经有 X 了，这份新题改用了内部标识 Y」，但那个标识只在日志和评测站里出现，
  老师界面只看得到题目编号。
  > 后缀只能是**字母**：评测站的标识只认「字母开头的字母数字」（`G01-2`、`G01_2` 这类它
  > **不报错、直接换成它自己的 `#N` 编号**，题就"消失"了 —— 踩过，所以让位标识一律用字母结尾）。
  > 覆盖同一道题（换题面/换数据）现在没有入口：想换就先删旧的再建。
- **上传有进度**：点「建题并导入评测站」之后页面上会出现进度条 —— 先报**上传百分比**
  （还有已传/总大小、速度），传完切成「服务端正在建题…」的流动条纹，提示别关页面
  （这一段是服务端在解包/配对测试点/导入评测站，一道题十几秒，服务端没有细粒度进度，不瞎编数字）。
- **选完文件夹之后，浏览器会一直"占着"这些文件**（这是浏览器的行为，不是服务端锁的）：
  在 Windows 上就表现为「文件正在被使用，改不了 / 删不掉」—— 你想回去改自己的标程会被它拦住。
  所以：① 点「建题」之后**文件一传完就自动松手**，服务端建题那十几秒你已经可以回去改文件了；
  ② 想在上传之前就改，点「①选出题文件夹」下面那个「**清空已选文件**」，
  改完重新选一次出题文件夹即可（文件不做暂存，重选才能再建）。
- 建题失败时页面会回显**服务端认出来的结构**和填过的字段；**文件不做暂存**，
  所以**重试要重新选一次出题文件夹**（页面提示里也写了）。

**删题目**在「**题目列表**」每行右边的「删除」按钮（红色）。这个「删除」是**假删除**：
它只把这道题从「全部题目」里**收起来**，题面、大样例、编号、**历史提交记录**全都留着 ——
所以删掉之后**题面照样能看、学生的提交记录也照常**。瞬间完成（不少老师反馈真删要等好几秒，
那是因为它要进容器删评测站的题目，现在只有「彻底删除」才那样）。

删掉之后**系统就不再认这道题了**：题库待选、配题候选、题目列表的主表格里都没有它，
它也**不再挡建题**（同一个标识再建一次会建出一份新的，见上面「可以建重复的题」）。
只是评测站上那份还留着 —— 这是"留证据"，不是"没删干净"。

删掉的题收在列表下面的「**已删除的题目**」里（点标题展开），那儿有两个按钮：

- **恢复**：放回「全部题目」（瞬间，因为什么都没删）。
- **彻底删除**：这一步才是真删 —— 评测站上的题目、题目编号、测试点/时限/内存记录、
  题面缓存、大样例存档一起清掉，**删了就找不回来了**（要等几秒）。
  > 它会**复查**：删完再查一次评测站，查不到才算成功。万一没删掉（评测站没起来、命令超时），
  > 页面会**如实说没删掉**并给出下一步，而不是报个"已彻底删除"让你回头在题库里又看见它。

> **还在比赛里用着的题删不掉**：那一场的题目表指着它，删了那场就判不出分。点删除会告诉你
> 「还在比赛里用着，不能删：CSP 模拟赛 第 1 题、…」——先从那些比赛里把它移除，再回来删。
> 假删除的题也**不会出现在配题候选里**（要用先在「已删除的题目」里恢复）。

一次导入多道题（出题工程里有很多题）也可以：文件夹里有几道就导入几道。
题单批量导入（CLI / HTTP 接口）见《[题目单导入接口.md](题目单导入接口.md)》。

### 5. 把考号发给学生
把**本场考试链接**（考号表上印着）+ 学生自己的考号一起发下去。

### 6. 考完公布成绩

在**比赛列表里该场比赛那一行**点「**发布成绩**」（发布后按钮变成「收回成绩」，随时可收回）。
发布后学生能在「查成绩」页看到自己的分数。**三种赛制都要公布后才可见** —— IOI 也不例外。
  > 公布之后，学生点进「查成绩」（登录状态直接显示自己的，不用再输考号）还能展开看
  > **逐测试点的情况**（每个点的结果/用时/内存/失败说明——是超时、内存还是答案错一眼看得出来）
  > 和**自己交的那份代码**（带行号）。这两样**只给本人**：分数是公开的，别人的代码不是。
（它不再实时给分），这个开关对每一场都一视同仁。

- 「**成绩总表**」按总分排名，含**每题得分、判分结果**（满分 / 部分正确 / 答案错误 / 未交）；
  点分数或考号进「提交详情」。
- **代码一键复制**：两端的代码块右上角都有个「复制代码」（学生端：交卷回执/文件预览、
  查成绩里的「你交的代码」；老师端：提交详情的「原始代码」「编译报错」、测试点的输入/输出/标准答案）。
  行号是**单独一列**，复制出来是纯代码，不会有 `  1  ` 这种前缀。
- 「**提交详情**」依次是：① **学生上传的目录结构**（目录树，标出文件大小、每个文件是哪一题
  判分用的、多余文件、个人信息文件交没交；**每个文件名都能点开看内容**）② 逐题判分
  （x/满分、提交次数、用时/内存、freopen 检查提示）+ **测试点明细三层**（状态条 / 得分构成 /
  逐点表）③ **学生提交的原始代码**（可展开）。
- 「提交详情」页顶上有个「**快速换人**」下拉：一页看一个学生，老师常常要连着看好几个 ——
  直接在下拉里选下一个就行，不用回「成绩总表」再点进来。下拉的顺序**就是成绩总表的顺序**
  （总分从高到低），每项写着「第 N 名 · 姓名（考号）· 总分」（没交的标着「未交」），
  旁边还有「第 N / M 个」告诉你看到哪儿了。
- 逐点明细里**每行的状态可以点**：弹窗一屏给这一点的判定/用时/内存/得分、一句话结论、
  **该点的输入数据与标准答案**（从题目数据文件读）。**学生输出**评测机不保存，页面上会明说。
- 不发布时，学生赛中只能看到「已提交 / 未提交」——**没有**每题的判定、逐点状态与分数。

> **关于部分分**：三种赛制都是**按测试点给分**的（每点分值 = 满分 ÷ 点数），
> 一道题通过一半测试点就是实打实的部分分。显示层把满分写成「答案正确」、中间分写成
> **「部分正确（17/100）」**、0 分才写「答案错误」；**学生端在老师公布成绩前只看得到
> 「已提交 / 未提交」**（连"部分正确"这种状态都不给），公布后才带分数。

## 四、学生怎么用

三种赛制**同一套操作**：打开本场链接 → 输考号 → 看题面 → 交**考号文件夹** → 看交卷回执。

1. 打开老师给的**本场考试链接**，输入自己的考号（`GD-S10029` 这种：短横是半角 `-`，字母大写）。
2. 比赛页有**倒计时**、赛制/级别徽章、题目表（题号 / **题目英文名** / 题目 / 你要读写的文件 /
   大样例 / 满分），点题目标题看题面；考场规则看「考生须知」（`/help`）——那里是**考区通告
   的原文**，后面附一段「本场信息」：你自己的考号、目录树、要交的个人信息文件名。
   学生页顶部那行导航是：`考号（姓名） · 我的比赛 · 返回比赛 · 查成绩 · 考生须知 · 退出` ——
   **「查成绩」在每一页都挂着**（老师公布前点进去会说"成绩还没有公布，请等老师通知"）。
3. 按题目表里的**英文名**建文件夹（**不是**题号、也不是页面上的 `T00004` 那种编号）：

```
GD-S10029/          ← 文件夹名必须是你的考号
├── candy/          ← 第 1 题的英文名（题目表里写着）
│   └── candy.cpp
├── road/
│   └── road.cpp
├── meal/
│   └── meal.cpp
└── 张三.txt         ← 个人信息文件（文件名＝自己的名字）
```

4. **CSP 赛制**的代码要用 freopen 读写**英文名**对应的文件（OI/IOI 用标准输入输出、不写 freopen）：

```cpp
#include <bits/stdc++.h>
using namespace std;
int main() {
    freopen("candy.in", "r", stdin);    // ← 题目英文名 + .in
    freopen("candy.out", "w", stdout);
    // ... 你的解法 ...
    return 0;
}
```

5. 比赛页「**提交我的文件夹**」：选**整个考号文件夹**（或打包成 zip）→ 提交。
   交完是「**交卷回执**」页：一份**文件结构检查清单**（考号文件夹名、每题文件名、
   个人信息文件、freopen 文件名、大小写），**不涉及算法对错**，但真实考场没人替你查，离场前核一遍。
6. 可以**反复提交**（每次整个文件夹覆盖上一次）：OI/CSP 按**最后一次**计分，IOI 取**最高分**。
   成绩等老师公布（三种赛制都一样），在「查成绩」页按考号查。

### 常见的 0 分（和真实 CSP 一样，别踩）

- 文件夹用了题号或别的名字（比如把第 1 题写成 `1/`），不是题目表里的**英文名** → 这题匹配不到文件，0 分
- 忘写 `freopen` → 读不到数据（回执里会提示"未检测到 freopen 调用"）
- freopen 文件名写错（`Candy.in` 大小写不符、或写成别的题的名字）→ 0 分（回执会提示应该打开哪个文件）
- 文件夹名不是自己的考号 / 少交某题 / 交的文件夹套了两层
- **命名一律严格区分大小写**（没有开关，与真实考场一致），`candy` 与 `Candy` 不互相匹配

## 五、在服务器上维护

```bash
# 服务状态 / 日志 / 重启
sudo systemctl status csp-exam
tail -n 40 /root/csp-exam/logs/exam.log
sudo systemctl restart csp-exam

# 数据都在这里（备份就备份这个目录；`-C /root/csp-exam data` 打进包的，解开也要带 -C）
sudo tar czf /root/csp-exam-data-backup-$(date +%Y%m%d-%H%M%S).tgz -C /root/csp-exam data
```

`data/` 里各文件是什么：

```
admin_key.txt           # 管理密钥
groups.json             # 名单分组（一批学生，可反复用于不同考试）
contests.json           # 比赛清单（含 level / duration_min）
problem_codes.json      # 题库每道题的【题目编号】与【默认英文名】登记
problem_info.json       # 建题时记下的测试点数 / 时限 / 内存 / 标程
problem_catalog.json    # 题库缓存（配题搜索用）
students.json           # 老版全局考号池，只在迁移旧数据时读
statements/<pid>.md     # 题面缓存（6 小时过期）
samples/<pid>/          # 大样例与题目样例（学生可下载）
contests/<比赛id>/
    exam.json           # 本场题目：每题 {no, pid, title, code=题目编号, name=英文名, full}
    roster.json         # 本场名单：考号 → 姓名 / 评测站账号（考号是本场随机分配的）
    results.json        # 本场成绩（含逐点明细 testcases）
    cases/<考号>/…       # 逐点内容超限时的转存
    uploads/<考号>/…     # 学生提交的原始文件（保持上传时的目录结构）
```

**改完代码/文档要跑的验收**（都在服务器上，`cd /root/csp-exam` 后执行）：

```bash
python3 csp_exam/tools/run_selftests.py     # 包内自测：6 套 163 项，约 1 秒，不需要 docker
bash tests/_smoke_pages.sh                  # 全路由冒烟：52 项，约 2 秒
bash tests/_regress_all.sh --quick          # 上面两项（约 4 秒）
bash tests/_regress_all.sh                  # 全量：再加 7 套端到端（约 10 分钟）
bash tests/_regress_all.sh roster tree      # 只跑相关的那几套（绕开最慢的 rules，约 9 秒）
```

**删/重置**（脚本是绝对路径，cd 到哪都能跑）：

```bash
bash /root/csp-exam/reset_exam.sh            # 不带参数：列出所有比赛 + 交互式问你删哪一场
bash /root/csp-exam/reset_exam.sh c2         # 直接删 c2（名单、题目配置、成绩、提交代码一起删）
bash /root/csp-exam/reset_exam.sh --all      # 全部清空 + 清空考号池（会停一下服务）
```

**升级老数据**（改过比赛字段/考号/题目编号的版本之后）：见《[运维手册](../docs/运维手册.md)》第四节，
先把服务停掉、备份 `data/`，再 `python3 csp_exam/tools/migrate_v2.py --dry-run` 预演、
`python3 csp_exam/tools/migrate_v2.py` 真跑。脚本**幂等**，重复跑不会重复改。

### 重启服务器之后（重要）

重启后有两件事会自动处理，不用管；但知道原因有好处：

- **判分机要重新注册判题会话**。它有时会在后端还没完全就绪时去注册、然后就不再重试，
  表现是**所有提交都变成"系统错误"**（界面上完全看不出原因）。为此装了开机守卫
  `hydro-judge-guard.service`：等后端就绪后自动重启一次判分机。手动执行同样有效：
  `cd /root/hydro && sudo docker compose restart oj-judge`。
  系统里如果出现"系统错误"，提交详情页会直接提示这句话，不用再猜。
- **`/tmp` 会被清空**，所以验收脚本放在 `/root/csp-exam/tests/`（不会被清）。

## 六、技术说明（给维护者）

**为什么要在提交前"包装"学生代码？**

实测这套 Hydro 版本（hydrooj 5.0.7 + @hydrooj/hydrojudge）**不支持题目级文件输入输出**：
题目配置里的 `redirect` 评测机没实现；`filename` 会被后端解析成 `subType` 丢掉。
所以 **CSP 赛制**在提交前给学生的 C/C++ 代码拼一段隐蔽包装（`core/wrapper.py`）：

1. 启动时把评测机喂进来的 stdin 落成 `<英文名>.in`，并把 stdin 读空；
2. 结束时若学生把 stdout 重定向到了 `<英文名>.out`，把该文件内容写回原始 stdout。

效果与真实 CSP 一致：写了 `freopen("<英文名>.in")` 的能读到数据，忘写或写错文件名的拿 0 分。
包装是纯 C 的，C 和 C++ 都能编译；学生提交的原始代码原样保存在
`data/contests/<比赛id>/uploads/<考号>/` 下。OI / IOI **不做任何包装**（标准输入输出）。

**判分不长在考试服务里**：考试服务只负责"收文件、对题目、提交给评测站、把判定写成成绩"，
判题由评测站（HydroOJ）的 go-judge 沙箱做。两者之间的接口只有三类：建账号（`hydrooj cli`）、
提交代码（HTTP 登录后提交）、读判定（查评测记录）。

**考号与身份**：考号**每场随机分配**，所以"某个考号属于谁"只在**本场名册**里有意义
（`roster.json`）。学生在评测站提交时用的是 `<比赛id>-<考号>` 这个账号；学生会话（cookie）里存的是
**比赛 id + 考号**，因此拿 A 场的会话访问 B 场会被挡回登录页 —— 必须如此，否则同号的另一个人会被冒用。
评测站账号是**按需创建**的（学生第一次提交时建），因为建一个账号要启动一整套 Hydro 进程，
一次给全班开号会把小机器压垮；想提前预热就在本场管理点「提前建好账号」（后台串行、限速）。

**判分与计分**：逐题走「CSP 套垫片（仅 CSP）→ 提交 → 等记录 → 写成绩」；
按赛制取 `RULES[rule]` 的 `freopen` / `best_of` 决定"要不要包装""覆盖还是取最高分"。
每次提交都落盘（提交次数、最近一次结果 `attempt_*` 与计分成绩分开记录），所以 IOI 交更差的代码
不会覆盖分数，但提交次数如实显示。**总分**一律按"每题得分之和"实时算（`store.entry_total`），
不信任存下来的 `total` 字段。

**提交不做目录结构校验**：`wrapper.pick_sources()` 尽量把文件对上题目（`<英文名>/<英文名>.cpp`
→ `<英文名>/其它源码` → 任意目录下的 `<英文名>.cpp` → 以英文名开头的唯一文件 → 只有一题又只交一个
文件时兜底用它），对不上的题就是"没交这道题"（0 分），不再整份退回。回执页把这个过程讲给学生。

**安全**：学生代码在评测站沙箱里运行（实测读不到宿主机文件、无法对外联网）。
考试服务只接受考号登录，学生看不到别人的提交；管理端靠管理密钥（或管理 cookie）保护。
考号相当于口令：知道别人考号 + 本场链接就能看到/覆盖他的提交（真实考试里考号也是公开的）。
