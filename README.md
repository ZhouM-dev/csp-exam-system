# CSP 模拟考试系统

给中小学信息学集训用的一套**模拟考试系统**：老师维护可复用的名单分组 → 每场考试**随机分配考号** →
学生交一个**以考号命名的文件夹** → 自动判分 → 老师公布成绩。

判分本身交给 [Hydro](https://hydro.ac/) 评测站，这个项目是**考试服务**那一半：管考场、名单、考号、
收卷、成绩与老师/学生两端的界面。

> 原型（纯静态、数据写死）在 [`原型/overview.html`](原型/overview.html)，
> 用浏览器直接打开就能点着看，不用起服务。

---

## 它解决什么

真实 CSP-J/S 第二轮是**发文件夹收卷**：学生交一个以考号命名的目录，里面按题目**英文名**分子目录，
代码要 `freopen` 读写对应的 `.in`/`.out`。市面上的 OJ 都是"网页上粘代码"，对不上这套流程。
这里按考场那套来做：

- **考号是每场随机发的**（`GD-S10029` 这样：前缀 + 级别字母 + 5 位纯随机数），和学生姓名、
  名单顺序、机位都无关，学生猜不到别人的号；同一场不重号，各场各发。
- **学生不注册、不登录**：老师发本场链接 + 学生自己的考号，输考号即进场。
- **收的是文件夹**：上传整个考号目录，系统按题目英文名把代码分到各题；命名大小写写错、
  少交个人信息文件都会在交卷回执里点出来。
- **赛中零反馈**：判分照常跑（老师要看成绩），但老师在管理端点「公布成绩」之前，学生端
  看不到任何判定与分数 —— 连"部分正确"都不给。三种赛制一视同仁。

## 三种赛制

| 赛制 | 代码怎么写 | 怎么计分 |
|---|---|---|
| **CSP** | 必须 `freopen` 读写 `<题目英文名>.in` / `.out` | 每题按**最后一次**提交 |
| **OI** | 标准输入输出（`cin`/`cout`，不用 freopen） | 每题按**最后一次**提交 |
| **IOI** | 标准输入输出 | 每题取多次提交的**最高分** |

三者的**提交方式完全一样**（交考号文件夹），成绩也都是"老师公布后才可见"。

## 老师怎么用

1. **名单分组**：把一批学生存成一个分组，可反复用于不同考试。
2. **新建比赛**：选赛制 / 级别（J 入门级、S 提高级）/ 时长，得到本场专用入口链接。
3. **导入名单**：从分组导入或直接粘贴，系统为每个学生**随机分配考号**并建好评测站账号。
4. **配题**：搜题库、点「加入」，加进来的顺序就是第 1、2、3… 题；每题可以按本场改**英文名**。
5. **发考号**：打「考号表」发给学生（上面印着本场链接 + 考号↔姓名对照 + 注意事项）。
6. **考完**：关闭提交 → 公布成绩 → 学生就能在「查成绩」页看到自己的分数。

建题目可以直接**选中整个出题文件夹**：题面、标程、`data/` 下的成对 `.in/.out`、`大样例/`
都会被自动识别并填进表单（识别在**浏览器本地**做，点「建题」时才上传）。

## 学生怎么用

打开老师给的本场链接 → 输考号 → 看题面 → 按题目英文名组织文件夹：

```
GD-S10029/          ← 文件夹名必须是你自己的考号
├── candy/          ← 第 1 题的英文名（题目表里写着）
│   └── candy.cpp
├── road/
│   └── road.cpp
└── 张三.txt         ← 个人信息文件（文件名＝自己的名字，广东考区要求）
```

交上去会拿到一份**交卷回执**：哪一题用了哪个文件、有没有缺题、命名有没有问题、
个人信息文件交了没 —— 但**不给任何判分信息**，成绩等老师公布。

## 技术构成

```
csp_exam/
├── core/           业务层：数据存储、判分调度、代码包装、题单导入、Markdown 渲染
├── web/            页面层：学生端 / 管理端页面、路由、会话
├── tools/          运维脚本（迁移、生成测试题、跑自测、部署）
├── tests/          包内自测（纯逻辑，不需要评测站）
└── docs/           设计说明 / 架构 / 运维手册
tests/              端到端验收脚本（跑在服务器上，真提交真判分）
原型/               静态 HTML 原型（设计定稿用）
```

依赖方向是**单向**的：`web/` → `core/` → `config.py`，`core/` 不 import `web/`。

- **纯标准库**，不需要 pip 装任何东西（Python 3.10+）。
- 题面 Markdown 由自带的 `core/markdown.py` 渲染（支持标题/表格/代码块/引用/列表），
  公式用本地 KaTeX。
- 与评测站的交互走 `docker compose exec` + `mongosh` / `hydrooj cli`。

## 跑起来

前置：一台 Linux 服务器，装了 Docker + Docker Compose，Hydro 评测站已经跑起来
（`oj-mongo` / `oj-backend` / `oj-judge` 容器），Python 3.10+。

```bash
# 1) 把代码放到服务器
sudo mkdir -p /root/csp-exam && cd /root/csp-exam
#    把本仓库的 csp_exam/ docs/ tests/ run.py 等放进来

# 2) 按你的环境改 config.py（Hydro 目录、端口、数据目录）

# 3) 起服务
python3 -m csp_exam        # 或 python3 run.py

# 4) 打开管理端（密钥在 data/admin_key.txt，首次启动自动生成）
#    http://<你的服务器IP>:8080/admin
```

学生入口：`http://<你的服务器IP>:8080/enter?c=<比赛id>`（每场一个专用链接）。

## 验收

```bash
python3 csp_exam/tools/run_selftests.py   # 包内自测：6 套 142 项，约 1 秒
bash tests/_smoke_pages.sh                # 全路由冒烟：36 项
bash tests/_regress_all.sh --quick        # 上面两项（约 4 秒）
bash tests/_regress_all.sh                # 全量：再加 7 套端到端（约 10 分钟）
```

端到端那几套会**真提交真判分**，`_e2e_rules.sh` 一套就要 6–7 分钟，所以平时改点小东西
跑 `--quick` 就够；全量留给批量改动之后。

> 测试脚本会临时改比赛的「公布状态 / 提交开关」，收尾**按运行前的原值还原**
> （不是写死成默认值）—— 老师可能已经公布过成绩，跑一次测试不该把它收回去。

## 说明

- 仓库里的示例数据（学生姓名、考号、密码）都是**占位符**，真实数据在 `data/` 下且不进仓库。
- 这套系统是为"一个班/一个考场的模拟赛"设计的，不是通用 OJ：它刻意不做注册、不做题库共享、
  不做实时榜单，因为真实 CSP 考场就是这样的。
