# 当前评测实现

本版本使用原版 **@hydrooj/hydrojudge 4.0.6**（AGPL-3.0-or-later）处理编译、运行、检查器、测试点判定与评分；使用 **criyle/go-judge v1.12.0** 执行沙箱。没有本地自编检查器或自动降级判题流程。Python 的 `judgelocal` 名称保留以兼容调用方，其职责已经是本地题库校验与接口调用。历史审计记录描述的是旧版本。

适配服务只有 HTTP 鉴权、题库路径校验、配置转换、原始字节复制和结果转发。上游 `JudgeTask.handle()`、`judge/default`、`checkers/default` 与 `flow` 都未修改。每个测试点设置为独立子任务，保持平台已有的按点计分。比赛按最后交卷计分或 IOI 保留最高分属于平台比赛规则。

## 版本与工具链

- HydroJudge：4.0.6；上游源码提交 `11fc1f59c9dba8f790f363d222d4012267d36be0`。依赖由 `deployment/hydro-bridge/package-lock.json` 锁定，安装使用 `npm ci`。
- go-judge：v1.12.0；本次二进制 SHA256 `2ecef4151b13da0fe38d919a75c4fe2621d94e69802325f52558985d6829b232`。
- 独立 CSP 沙箱为 Ubuntu 20.04 / G++ 9.3.0，编译参数 `-O2 -std=c++14 -static`；没有借用 LiteOJ 的 G++ 12.2 沙箱。
- 运行 CPU 时间、内存按题目限制；配置上游 `strict_memory: true`，使栈上限跟随题目内存，避免默认 8 MiB 栈误伤。严格内存限额下，分配失败导致退出可以由上游判为 RE；实际触碰超限资源则由沙箱及上游处理。时间倍率默认 1.0、未标定。云主机与官方评测硬件并不相同。本镜像不是完整官方 NOI Linux 镜像。
- 编译限额：30 秒 CPU / 1024 MiB；单题运行内存最大 1024 MiB。更大配置报系统错误，不自动降低题目限制。对于特殊模板或极大编译开销，需要在正式考试前验证。

## CSP 口径

`filename` 配置要求 `<英文名>.in/.out`；不注入源码、不以标准输出替代缺失的 `.out`。目录仍为 `考号/英文名/英文名.cpp`。目录上传、ZIP 上传与 TXT 附属文件的归档逻辑不改变。

采用 Hydro 原版 default 检查器：忽略 CRLF、行末空格/制表符和末尾空行；保留行首和行中差异。这与旧 Python 检查器对行末制表符的行为有变化，正式重测必须使用当前规则。测试点时间由 Hydro 提供，整题时间为测试点 CPU 时间之和；内存为峰值 KiB。

上游在 CSP 文件模式中对缺失答案文件返回 RE。若程序尚未创建 `.out` 就超时或超过内存，上游可能仍显示缺失输出文件的 RE；得分仍为零，平台不另写逻辑改判其状态。正常先打开答案文件的程序会保留 TLE 等资源判定。此行为在验收中单独检查并记录。

检查器错误信息会保留，平台不另外取回或解码输出去判断正误。Hydro 清理临时输出文件，因此管理端逐点详情显示输入、标准答案及 Hydro 差异信息，完整选手输出目前不留存。非 UTF-8 的归档源码与数据保持原始字节。

## 单机共存

CSP 网站 127.0.0.1:8081；Hydro 适配服务 127.0.0.1:8082；独立 go-judge 127.0.0.1:5060。Hydro 接口另需随机私密 Bearer token，不通过 Caddy 开放。go-judge 本次未启用可选鉴权，仅绑定本机。Hydro 与 go-judge 不可获得考号、密钥和成绩目录；只有独立题库和临时评测文件可见。

CSP 并发为 1。持久 SQLite 队列承接集中提交，原始源码先归档；进程重启恢复未完成任务，沙箱临时故障退避重试，系统错误不替换已确认成绩。网站同时读取上传最多 2 份，学生上传 32 MiB、题包默认 64 MiB。磁盘剩余不足 512 MiB 时拒绝新的上传并明确说明。

隔离按 go-judge 上游实现使用命名空间、用户命名空间映射到独立宿主 UID/GID 20000 段（执行身份为沙箱内 1536，对应宿主 20001 及以上）、NoNewPrivs 和 cgroup v2。此发布二进制默认没有启用可选 seccomp；上游文档不推荐随意配置体系结构相关的系统调用白名单。平台核验并记录真实状态，可通过 CSP_REQUIRE_SECCOMP=1 要求其生效，未满足则停止评测。当前没有宣称 seccomp 已启用。

沙箱容器限制 1 CPU / 1536 MiB，Hydro 容器 0.5 CPU / 256 MiB，网站 0.5 CPU / 512 MiB；评测开始前要求系统可用内存不少于 1536 MiB。资源上限和低 CPU 权重可减少对 LiteOJ 的影响，但不等于硬件性能与正式 CSP 相同，也不等于 100 人能同时得到判定。集中交卷可能需要排队。
