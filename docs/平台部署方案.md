# CSP 比赛平台改造与部署方案

本次代码基于 `HydraBor/csp-exam-system` 的 dev：`2fb981ac22c52cf18db1128f72d34cc99c7da88a`。
它比 main 的 `d9c801f` 多一个后继提交。工作分支为 `codex/contest-schedule-zip`。
本文件保留部署前设计和规则；实际上线操作、端口与资源配置以服务器上线记录和运维手册为准。其他文档中的旧生产机器、旧目录、旧备份地址是历史记录。

## 已实现的考试行为

- 管理 key 和考号登录方式保留。新建比赛必须填写开始、结束时间，均按北京时间解释，持久化为 Unix 秒；服务器操作系统的时区不影响比赛窗口。
- 开始之前学生可见比赛标题、级别、时长、开考时间及倒计时，到时自动进入考试；服务器拒绝题面、样例、交卷、提交文件等入口。未设置时间的旧草稿也关闭这些入口，管理员须补齐时间。
- 时间窗口为 `[开始, 结束)`：开始时刻可提交，结束时刻立即拒绝。以服务器收到完整上传、校验后提交归档的时刻为准，上传过程中跨过结束时间也拒绝，不留下新交卷和队列占位。
- 结束之后比赛页显示“比赛已结束”，隐藏题目和上传入口。成绩在考试结束且评测全部完成后由教师公布；教师公布后可另行查成绩及自己的代码。
- 浏览器根据服务器状态自动切换页面，倒计时以服务器时间锚定，不要求学生电脑时间正确。断网、关闭 JavaScript 或保留旧页面不能绕过后端限制。已经发送到学生设备上的内容无法从设备、截图或浏览器历史中追溯删除。
- 已经开始的比赛不能通过管理页面修改开始时间；可以调整结束时间。修改赛程会撤回已公布成绩。时长输入用于填写结束时间，实际结束时刻以保存的结束时间为准。
- 旧手动提交开关已从管理页面移除，旧 POST `open` 参数明确拒绝。

## 考生提交目录

保留原来展示的考场结构，当前依据 [NOI 官网广东考区 2025 第二轮考生注意事项](https://www.noi.cn/gs/xw/gd/2025-10-25/850192.shtml?province=df)。每题英文名取本场题面规定值，以下以模拟赛 001 为例：

```text
GD-J12345/
  张三.txt
  number/number.cpp
  desk/desk.cpp
  label/label.cpp
  transit/transit.cpp
```

上传整个考号目录，ZIP 内部也须保留考号这一层。CSP 入口只选择 `本考号/题目英文名/题目英文名.cpp`，大小写严格；省略考号、使用其他考号、多套一层、放错子目录或源码名均不自动匹配。目录不合格的题记录为未找到源码；原始交卷保存，回执提示修正，不自动搬动或改名。

姓名 `.txt/.TXT` 必须直接位于本考号目录下，错放到题目子目录不算通过个人信息文件检查。该文本是广东考区规定的资料文件，不参与题目评分；不能将此地方要求描述为全国所有考区统一要求。源程序仍按题面指定的文件名在当前目录读写输入输出。

网页校验的是上传包内的相对目录，无法确认考生电脑上原文件夹所在盘符；本机答案保存位置按考点指引执行。使用其他考区或新年度规则前须再核对相应官方通知。

此次修复保留目录设计，另外收紧原项目“省略考号外层也识别代码”“姓名文件任意层级也识别”的兼容行为。普通 OI/IOI 的通用源码匹配不采用此 CSP 限制。

## ZIP 导入规则

教师与学生上传、题单 CLI 使用同一 ZIP 文件名与边界校验。支持 UTF-8 中文名、旧 Windows GBK 中文名及 Unicode Path 扩展。保留姓名 `.txt/.TXT`；它是个人信息文件，不是 C++ 源码。
拒绝路径越界、符号链接、加密包、同路径覆盖及超限解压。损坏包明确失败。

标准教师包：

```text
题单.zip
  README.md                 # 可以有题单说明，不会吞掉多道题
  G01-往返报号/
    题目.md
    标程.cpp
    problem.json
    data/01.in
    data/01.ans              # .out、.ans 均可，扩展名大小写兼容
    data/02.in
    data/02.out
    大样例/样例.in
    大样例/样例.out
  G02-样品登记/...
```

也支持 ZIP 根目录直接放一道题。评测数据必须完整配对：任何缺输入、缺答案、同一输入对应多个答案，都使本题导入失败，不会用剩下的测试点拼成“导入成功”。多题包分别报告每题成功或失败，已成功的题保留。

可选 `problem.json` 示例：

```json
{"id":"J001T1","title":"往返报号","name":"number","time_ms":1000,"memory_mb":256,"case_count":20}
```

逐题时空限制、英文名和测试点数量会核验并保存，不会被批量上传表单的默认限制覆盖。没有此文件时沿用上传表单设置。
当前平台按独立测试点均分满分，余数分配给前面的点。它尚不支持任意逐点分值、整组计分、SPJ；不认识的评分字段会拒绝导入，不会静默丢弃。后续题包必须与此计分方式相容，或先实现并验证相应模型。

## liteoj.cn 只读检查（2026-10-10）

通过用户授权的 SSH 完成系统、监听端口、容器状态、编译器版本检查；没有安装、停止、重启或修改任何线上服务，也没有读取用户数据库或应用密钥。

| 资源限额 | 现有两个容器未设置容器级 CPU/内存上限 |

## 推荐的共存结构

1. LiteOJ 保持原来的目录、数据卷、3000/5050 端口和服务定义。
2. CSP 使用独立系统用户 `csp-exam`、`/opt/csp-exam` 源码、`/var/lib/csp-exam` 数据、`/var/log/csp-exam` 日志以及回环端口 8081。独立管理 key，不复用 LiteOJ 账号或数据库。
3. 在现有 Caddy 中增加 CSP 子域名站点，反代到 8081。保留现有站点，验证整份配置后平滑 reload，不重启 LiteOJ。
4. CSP 使用单独的 go-judge 入口（拟用回环 5060，安装前再核对空闲），单评测队列。现有 G++ 12.2 沙箱不能满足 CSP 项目当前要求的 G++ 9.3.0 / C++14 / O2 / static，也不应为了 CSP 改坏 LiteOJ 的工具链。

这台 2 核、3.4 GiB 机器适合先验证两个 Web 服务共存。CSP 编译单任务限额为 2 GiB，两边评测各自排队并不能限制“同时有两个任务运行”；同时评测可能干扰时间测量或触发宿主内存压力。
正式比赛优先让 CSP 评测运行在另一台受控评测机，Web 可以仍在本机。远程无鉴权 go-judge 通过专用 SSH 隧道呈现为本地回环端口，不能直接对公网开放。
若坚持单机双评测，需要先实现跨平台总并发限制或明确比赛期间的资源安排，并做峰值与超限测试。仅启动第二个容器不能证明不会影响 LiteOJ。

未来统一评测机应共享执行基础设施、资源调度和监控，并为两种平台保留工具链配置、队列身份与独立文件仓库。不要直接把两个客户端指向当前同一个 5050 入口；这样既没有统一排队，也没有解决工具链差异。

## 安装与验收顺序

`deployment/` 提供 systemd 单进程应用服务、环境变量示例与 Caddy **新增站点片段**，对应配置已在当前服务器安装，公开入口为 https://csp.liteoj.cn；本目录是可复用的配置示例，私密实际配置不进入仓库。
服务模板默认保护源码和其他用户目录，进程只允许写自己的数据、日志；Web 配额供初始测试，正式导入与学生并发要验证后调整，不能把模板当容量结论。

1. 分配 CSP 子域名并确认 DNS；保存现有 Caddy 配置副本以及 LiteOJ 备份，记录当前首页状态和容器状态。
2. 本地构建源码发布包：`python3 csp_exam/tools/build_release.py /输出路径/csp-exam.tgz`。构建前自动运行自测，包中只包含源码、文档、配置示例和 SHA-256 清单，不含学生数据、key、日志和 `.env`。
3. 创建 CSP 专用系统用户和目录。解包到 `/opt/csp-exam/releases/<版本>/`，`/opt/csp-exam/current` 指向该版本。数据、日志在源码目录之外。
4. 把环境示例安装为 `/etc/csp-exam.env`，替换实际子域名；数据目录属 CSP 用户，密钥与数据文件只允许该用户和运维管理员读取。只启动 `csp-exam.service`，先验证回环 `/health`。
5. 准备并验证独立 CSP 沙箱：实际 G++ 9.3、cgroup v2、seccomp/NoNewPrivs。执行 `sandbox_regression.py`、`http_judge_regression.py` 与带 live 参数的管理回归，验证 AC、WA、CE、RE、TLE、MLE、文件 I/O、零反馈、重测和重启恢复。只对 CSP 数据副本运行，不能连接 LiteOJ 的沙箱做压力实验。
6. Caddy 追加新站点并验证完整配置，再 reload。HTTPS 下启用 Secure cookie，配置 PUBLIC_ORIGIN；不要将 8081、5060 放到公网。可核对 [Caddy 请求体限制文档](https://caddyserver.com/docs/caddyfile/directives/request_body)。
7. 用实际套题和模拟考号进行全流程验收，包含提前登录、自动开赛、ZIP 交卷、截止边界、队列重启恢复、400 分成绩、成绩公布，以及 LiteOJ 前后健康状态。随后才交给学生。

服务仅支持一个写数据的 Python 进程；启动锁会阻止重复启动同一数据目录。不要开启多 worker 或多副本共同写这些 JSON。当前使用单 worker 的持久 SQLite 队列，已取消旧的 64 个待评测任务上限；源码先归档，重启恢复未完成任务。扩容仍须保留计分和提交快照规则，并核验资源与磁盘容量。

## 备份、恢复与升级

密钥、题目数据、题面、样例、名单、成绩和所有提交快照都在数据目录，完整备份必须包含整个目录。源码包不能替代业务备份。

暂停 CSP 接收新交卷并确认队列空闲，在没有进行中的比赛时停止 **csp-exam**，执行：

```sh
python3 /opt/csp-exam/current/csp_exam/tools/backup_data.py /var/lib/csp-exam /var/backups/csp-exam/<唯一时间>.tgz
```

备份工具与服务共用进程锁，服务仍运行时拒绝复制，防止跨多个 JSON 文件得到不一致快照。备份文件权限为 600，不覆盖已有备份。保留返回的 SHA-256，异机保存一份；备份包含个人资料和管理 key，不能放在公开 Web 目录。

恢复时停止 CSP，在独立暂存目录解开可信备份并核对结构和 SHA-256；将当前数据目录改名保留，再切换恢复目录、核对 CSP 用户权限后启动。先用隔离副本做一次恢复演练。恢复副本不得连接生产评测端或接收真实学生提交。

升级时先完成备份，部署新的独立源码目录，切换 current 链接，仅重启 CSP。健康检查、独立测试交卷或 LiteOJ 健康验证失败时，切回旧源码链接。涉及数据格式迁移时需同步回滚数据，不只回滚源码。旧的 SSH deploy.sh 已改成只构建本地包，防止把历史路径误用到当前服务器。
