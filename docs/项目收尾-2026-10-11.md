# 项目收尾验收（2026-10-11）

公开服务为 [CSP 模考平台](https://csp.liteoj.cn)，由 Caddy 提供 HTTPS。网站、HydroJudge、go-judge 的 HTTP 回环地址只用于本机通信，不是考生访问地址。历史开发和首次上线记录保留原日期，当前行为以本记录、使用说明和运维手册为准。

## 接口和功能

逐项检查服务路由、角色权限、赛程、比赛设置、名单、题库修改、题单导入、ZIP 和目录交卷、归档、持久队列、重测、成绩公布、排行榜、个人源码、退出和候考倒计时。实际回归使用独立临时数据，真实引擎测试使用临时 Hydro 容器及 CSP 专用沙箱。

本次修复包括：

- 题单 API 按 multipart 字段识别文件，拒绝多文件和无效限额；上传写配置的数据目录，兼容只读源码部署；并发任务先原子占位，同标识并发导入只建一次。
- 单题错误逐题记录，保留同包之前已成功的结果；JSON 标识和标题遵循文档；dry-run 校验默认英文名，但不编译或执行程序。文档明确总请求、展开量、单题限额和异步部分成功语义。
- 非 ASCII 错误密钥返回拒绝，而不是比较函数异常；比赛列表按本场会话过滤，个人源码旧路径也限制在本人提交目录。
- 所有限额修改入口共用正在评测的保护和旧成绩失效处理，拒绝修改时不残留标题或英文名的部分保存。
- 保存结果如实报告名单、选题和设置的失败；拒绝重复/不存在题目及非正分值；重复的 32 字符英文名自动补后缀后仍合法。
- 考号前缀在写设置前校验为 1—16 个英文字母；比赛进行中及仍有排队/评测提交时拒绝删除。
- 比较成绩快照时检查题目、题号、满分和提交英文名等评分契约；只改题名不会误使旧成绩失效，历史快照文字保留。

赛中公开排行榜和 API 拒绝返回成绩，即使同浏览器有管理员 cookie，学生路径也不升级为内部视图。公开成绩要求比赛结束且教师公布；个人成绩与源码还要求本场考生身份。候考时间来自服务端 `/api/contest-state`，客户端使用单调时钟计算倒计时，到点及比赛状态改变自动导航；未使用未经验证的第三方校时接口。

## 常规第三、四题

常规第三题改为《彩灯布置》，第四题改为《巡检路线》，并更换故事。相对强化版分别去掉各类连续长度限制、最短路线方案数，是模型简化，并非仅缩小数据。原强化《展签排布》《中转通道》保持独立题库，常规英文名仍为 `label`、`transit`，不改变 CSP 的考号/英文名/英文名.cpp 结构。

本次重新从题面推导，第三题以不含数量上界公式的搜索对拍 2,900 组；第四题以逐条显式建边的双状态 BFS 对拍 26,156 组，零分歧，同批 ASan/UBSan 无错误。两题 40 个正式输入及公开附加性质逐点核对，六个样例一致；部分分用枚举、构造、排序、记忆化和唯一入口映射等独立可行路线实跑。

全卷另核对 80 点数据、11 个样例、计分和导出标程，学生卷 8 页、教师卷 3 页逐页渲染目检通过。2.1 对常规 2.0 仅改题名和故事，程序及正式数据哈希不变；题目资料、私有教师包和详细证明保留在本项目的成品目录，不放入公开平台源码。目标机器全卷及强化标程复核见 `target-exam.json`。

## 运维边界

升级须先确认没有正在进行的比赛、队列空闲，停止 CSP 网站后备份整个业务正本，再切换独立发布目录并只重启 CSP。本次题面同步只更新两题题面、题名和在用试卷显示标题；名单、考号、赛程、提交快照、历史成绩、强化题和数据不覆盖。上线检查需核对业务文件哈希及 LiteOJ 容器 ID/启动时间。

当前评测并发 1、倍率 1.0；没有可信官方参考机测量，不能仅按 CPU 型号宣称已校准。100 份单点交卷接收/恢复的历史测试不是 100 人四题整卷的容量结论。题位难度是按大纲和真题形成的设计判断，尚无学生试考统计。
