# SQLite 存储与题库迁移

当前业务正本为 `CSP_EXAM_DATA_DIR/csp-exam.sqlite3`。SQLite 采用 WAL、完整同步、外键、参数化查询和事务；单机无需增加数据库进程。网站仍通过数据目录进程锁保证仅一个实例写入。选择依据为 [SQLite 官方适用场景](https://www.sqlite.org/whentouse.html) 与 [WAL 文档](https://www.sqlite.org/wal.html)。未来多机写入时，应迁移至独立题库服务和客户端/服务器数据库。

比赛、题目编号及默认英文名、题目限额与标程、分组、考号名单、成绩与历史记录、样例清单、评测倍率均入库。集合元素按主键单独存行；复杂的历史快照、逐测试点结果保留 JSON 字段。逻辑名称 `exam.json` 等仅是存储适配层的键，运行时不再读写同名业务文件。题面存在 `statements` 表中，每次修改递增版本。排行榜使用数据库记录版本失效缓存。

数据库表为 `documents`（集合形状和版本）、`records`（集合元素和顺序）、`statements`（题面）。`problem_library` 视图暴露 `id/title/description/time_limit/memory_limit/submission_name/problem_number/deleted`，便于后续题库服务调用。现阶段属于独立 CSP 数据库，并未接入或更改 LiteOJ 数据库。

测试点继续位于 `problems/<pid>/testdata/`，样例文件位于 `samples/<pid>/`，学生原始交卷和源码快照位于 `contests/<cid>/`。文件输入输出及考号/英文名/英文名.cpp 的提交规则保持。管理密钥和部署环境配置仍为受保护的凭据文件。

题库详情页修改默认英文名后，编号登记、题库元信息和尚未结束且沿用旧默认值的比赛在同一 SQLite 事务内同步。同场存在重名时拒绝整次元信息修改；单独设置的场次英文名和已结束比赛保留。清空只移除题库默认值。已有提交及排队任务保留原文件契约，新交卷重新读取本场英文名，上传识别和 HydroJudge 的 `filename` 使用同一份快照。源码中的 `freopen` 必须与新名一致，平台不改写学生程序。

## 旧数据升级

先停止 **CSP 网站**，保持其他 OJ 运行。离线迁移工具备份整个数据目录，再用单个事务导入已知 JSON 与 Markdown；严格解析并逐项比较原记录、原顺序、原题面，检查 SQLite 完整性。坏 JSON 会阻止迁移。通过后旧格式可移入私有归档，不作为运行时回退来源。

```bash
sudo systemctl stop csp-exam.service
sudo python3 /opt/csp-exam/current/csp_exam/tools/migrate_storage.py \
  /var/lib/csp-exam --backup /var/backups/csp-exam/唯一名称.tgz \
  --archive /var/backups/csp-exam/唯一旧格式目录
sudo chown csp-exam:csp-exam /var/lib/csp-exam/csp-exam.sqlite3
sudo chmod 600 /var/lib/csp-exam/csp-exam.sqlite3
sudo systemctl start csp-exam.service
```

新安装直接建立数据库。启动遇到旧格式会在首次访问初始化，但生产升级应使用上述离线工具，留下核验与备份。首次迁移后回滚到旧版源码必须同时恢复对应旧格式备份；先保存升级后的最新交卷。不得仅切换代码后继续写旧 JSON。

## 备份和迁移包

`backup_data.py` 拒绝服务运行期间备份，检查数据库完整性并将 WAL 检查点写回后打包，涵盖业务数据库、提交队列和全部数据文件。数据库和源码的备份都需保密。

```bash
sudo systemctl stop csp-exam.service
sudo env CSP_EXAM_DATA_DIR=/var/lib/csp-exam \
  python3 /opt/csp-exam/current/csp_exam/tools/export_library.py /私有目录/题库.zip
sudo systemctl start csp-exam.service
```

导出包含 CSP 可重新导入的 `problem.json/题目.md/标程.cpp/data/samples`，逐文件 SHA-256 清单，以及每题 `liteoj-seed.json`。后者对照 LiteOJ 仓库 `backend/db.js`、`backend/problem-files.js`、`seed/problems/P1001/problem.json` 的字段，使用稳定题目标识、毫秒时限、MiB 内存和明确的数据路径。CSP 文件提交英文名放在额外 `csp` 字段中。LiteOJ 的种子文件是离线数据交换格式，需要接入其导入适配器，不能宣称已有整包一键导入功能。

后续共用题库宜由一个服务负责题面、限额、数据版本和更新，两个 OJ 通过接口读取；考试题目仍保存当时的提交契约与成绩快照。统一前须确定标识冲突、公开权限、评分/子任务和检查器语义。目前导出只支持已实现的普通标准判题与独立测试点。

管理端现支持在线单题 ZIP 下载，保留样例分类和测试点名称，使用方法与跨机器版本要求见 [题目导出与迁移](题目导出与迁移.md)。离线导出和在线导出共用 `csp-problem/1` 单题清单，外层题库清单为 `csp-library/2`；旧格式仍可导入，但无法恢复它未保存的样例分类。
