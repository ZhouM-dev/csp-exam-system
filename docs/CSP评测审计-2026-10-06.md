## 官方基准与实际边界

以已公布的 [CSP-J/S 2025 资料](https://www.noi.cn/zxzy/lnzl/jszl/2025-12-15/854079.shtml)、CCF 编写的 [2025 J 题面镜像](https://zqiceberg-picgo.oss-cn-beijing.aliyuncs.com/img/day1%281%29%281%29.pdf)、[NOI Linux 2.0 官方说明](https://www.noi.cn/gynoi/jsgz/2021-07-16/732450.shtml)和[广东考区通知](https://www.noi.cn/gs/xw/gd/2025-10-25/850192.shtml?province=df)为依据；不将 2025 硬件当成尚未公布的 2026 第二轮硬件。

| 项目 | 基准与本次处理 |
|---|---|
| 编译环境 | 官方 NOI Linux 2.0 的 G++ 9.3.0；从官方 ISO 提取编译器、头文件和库，只读挂载到沙箱 |
| C++ 参数 | `-O2 -std=c++14 -static`，源码原样编译，执行文件使用题目英文名 |
| 输入输出 | CSP 严格使用题目要求的 `.in/.out`，空标准输入；OI/IOI 使用标准输入输出 |
| 目录与源码 | CSP 采用 `题名/题名.cpp`，可放在本考号目录下，大小写严格；源文件最多 100 KiB |
| 比较 | 原始字节比较，仅过滤行末 ASCII 空格和文末换行；支持 CRLF；不吞制表符或不同非法 UTF-8 字节 |
| 时限 | 保留每题原始时限，使用 CPU 时间；另行配置近似性能倍率 |
| 内存和栈 | 均使用题目内存限制，单位 MiB，不随时间倍率变化 |
| 未知题目限额 | 不再用 1 秒 / 256 MiB 猜测，停止评测并要求补齐 |

## 确认问题与修复

| 编号 | 原问题 / 复现证据 | 修复 |
|---|---|---|
| A01 | 上传跳过 `../` 文件，但判分仍采用原始文件列表；读取了目录外受控 `.cpp` canary | 上传路径统一校验，挑选前处理；读取和下载检查 resolve 后仍在提交目录内，拒绝符号链接逃逸 |
| A02 | 压缩包没有展开大小约束，约 8 KiB 文件展开为 8 MiB 被接收 | 展开前检查总大小、文件数、重复、加密、符号链接；多个 ZIP 共享总预算；增加归档和磁盘配额 |
| A03 | 最后整卷缺题时保留旧满分，空 picked 可一直“判题中” | CSP/OI 的最后交卷缺题记零，空交卷也完成状态；IOI 仍保留历史最高分 |
| A04 | 旧任务读到新上传文件，旧完成结果可能覆盖新提交 | 每次交卷 UUID 与不可变快照；逐题写入和完成状态都核对当前 UUID |
| A05 | 两次同时写不同题丢失其中一题 | 读、改、写整个结果事务持有同一锁；重试同一提交不重复累计次数 |
| A06 | semaphore 只保护写成绩，没有限制实际评测并发 | 完整读数据、编译、执行受单任务闸门保护；有界队列，go-judge 单并发并固定 CPU 0 |
| A07 | 缺标准答案被保存为空文件，空输出可能得分 | 建题拒绝缺答案；评测时发现答案缺失记系统错误，不产生正式新成绩 |
| A08 | 沙箱不可用会将原成绩覆盖为零 | 原成绩暂存，标记待重测；最多自动重试三次；存在待处理提交时拒绝公布成绩 |
| A09 | 大于 100 KiB 源文件、明确过期的交卷仍可接受 | 源文件上限，截止时间在接收前及保存事务内复核；移除会过期消失的建赛时间猜测 |
| A10 | `rstrip()` 吞制表符和 Unicode 空白；解码替换使不同非法字节相等 | 比较原始字节，并只过滤规定的字符 |
| A11 | 逐点记录在 100 点截断后重算分数，200 点 / 1000 分示例错误放大 | 所有测试点参与计分，展示内容限制不再裁掉测试点 |
| A12 | 执行异常时缓存二进制未释放 | 源码、输入、输出和编译产物都由 finally 释放，移除无归属的 keep_binary 选项 |

同时修复默认动态链接、8 MiB 栈、教师自测 auto 与学生 CSP file 不一致、标准输出兜底、请求体未统一限额及重复 multipart 文件静默覆盖。教师自测明确选择 CSP 文件 I/O 或 OI 标准 I/O，默认 CSP。

常见改变编译选项的 pragma、编译属性和内联汇编按 CSP 源码规则拒绝；检测忽略注释和字符串。此检查不是完整 C++ 静态分析，宏或混淆规避仍需要教师复核。沙箱在每分钟首次评测时核验编译器、cgroup v2、seccomp 和 NoNewPrivs，异常时停止评测。

## 性能倍率与校准

公式：`本机有效时限 = ceil(官方时限 × 本机基准 CPU 耗时 / 参考机基准 CPU 耗时)`。较慢机器倍率大于 1，较快机器小于 1；实际耗时除以倍率只作为参考换算，原始值仍保存。一次评测内倍率固定，修改后历史分数不会自动变化。

管理端「评测设置」可设置手动倍率。配置在 `data/judge_profile.json`，默认 1.0、未标定。没有符合官方配置的机器对照时不自动写入假定官方倍率。

```bash
# 在已配置 G++ 9.3.0 的参考机上跑固定受控基准。
python3 -m csp_exam.tools.calibrate_judge --native --label '参考机配置与频率设置' --output reference.json
# 评测服务器通过沙箱运行完全相同的整数、排序、内存基准，各热身一次，再采样五次。
python3 -m csp_exam.tools.calibrate_judge --reference reference.json --output local.json
# 无异常后显式应用。样本波动或各负载比例差异大时拒绝自动应用。
python3 -m csp_exam.tools.calibrate_judge --reference reference.json --output local.json --apply
```

一个统一倍率无法消除缓存、内存带宽、指令集、云主机共享负载等差异；临近时限的提交无法保证与官方相同判定。

## 排行榜与旧成绩

入口 `/scoreboard?c=<比赛>`；教师预览 `/admin/scoreboard?c=<比赛>`；接口 `/api/scoreboard?c=<比赛>`。表格展示每题分数、总分和并列名次，每 15 秒更新；采用 CSP 分数，不加 ICPC 罚时。未公布时公开接口没有名单和成绩；教师预览要求管理员认证。待评测提交不参与正式排名。

旧成绩没有默默批量改写。管理端「评测设置」提供 CSP/OI 最后交卷整场重测：先备份 results/exam，归档原文件，再收回公开状态、排队重测。完成后教师复核并重新公布。IOI 需要全部历史提交才能完整重算最高分，暂不提供整场重测。

旧题 `P1000`（A+B）没有时限和内存元数据，涉及 c9/c14/c15；需要按原题配置在「评测设置」补齐。不能把它当作有明确官方限额的 CSP 题。

- 逻辑自测：9 套通过；原 185 项断言通过，另有 21 项评测漏洞 unittest 回归。
- 实际官方工具链沙箱：18 项，包括 AC/WA/CE/TLE、文件与标准 I/O 区别、16 MiB 栈、32 MiB 内存限制、非法字节比较、二进制 I/O、倍率记录、静态 ELF。

- 不向真实名册写入验收学生，不改变真实成绩；重测备份保存在该比赛 `rejudge/<UUID>/`。

服务为 `csp-exam.service`（8080）和 `go-judge.service`（127.0.0.1:5050），均开机启动。配置前的 go-judge 备份为 `/etc/go-judge/*.pre-csp20261006`；应用部署前代码和全部 data 单独归档，具体目录见部署验收记录。恢复旧评测配置将重新引入环境差异，不应只回滚沙箱而保留新代码。
