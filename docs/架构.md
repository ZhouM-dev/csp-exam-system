# 架构与职责

唯一业务正本在 `data/`。Python HTTP 服务处理权限和输入校验，核心模块负责状态变化，go-judge 负责隔离编译与执行。前端页面读取同一份核心投影。

| 模块 | 职责 |
|---|---|
| `core/store.py` | JSON 原子写入、业务锁、比赛/分组/名单/成绩；总分、排名、成绩公开及过期成绩撤回 |
| `core/problems.py` | 建题、编号、元信息、测试数据配对、题目/大样例管理 |
| `core/importer.py` | zip/目录解析与题单报告；调用同一建题流程，dry-run 不写题库 |
| `core/localoj.py` | 本地题库查询、题面读写、测试点读取与教师自测入口 |
| `core/submissions.py`、`core/wrapper.py` | 原始提交与归档路径、源码匹配、CSP 源码检查与文件输入输出提示 |
| `core/grading.py` | 排队、交卷/重测快照、按题计分、IOI 最高分保留与异常状态 |
| `core/judgelocal.py`、`core/gojudge.py` | 本地数据快照、编译/运行限额、沙箱请求及环境核验 |
| `core/judge_profile.py`、`core/judge_result.py` | 评测倍率配置与结果状态解释 |
| `core/scoreboard.py` | 在统一排名上生成教师/公开投影与文件版本缓存 |
| `web/server.py` | HTTP 方法分发、会话校验、请求上限与解析 |
| `web/student_pages.py`、`web/admin_pages.py` | 学生/教师页面与按钮处理 |
| `web/scoreboard.py`、`web/judge_settings.py` | 排行榜交互、管理登录和评测设置 |

数据流为“交卷 → 校验/保存原始文件 → 冻结评测参数 → 排队 → go-judge → 逐题结果与源码归档 → 统一成绩投影 → 教师公布”。重测沿同一执行路径，先保留旧成绩，资料不足进入需处理状态。

`store._LOCK` 是进程内重入锁，保护跨文件业务操作及公布检查。JSON 使用临时文件替换写入。测试数据先写暂存目录，再在锁内更换；读取测试点使用同一锁，避免读到半份数据。当前服务单进程运行，不支持多个应用实例同时写同一 JSON 数据目录。

比赛定义和名册存于 `data/contests/<id>/`，题库数据存于 `data/problems/<pid>/testdata/`；题面、样例与编号/元信息分别有明确存储位置。题库与比赛引用分离：比赛中的英文名不会因题库默认英文名修改而自动重命名。

Hydro 客户端、账号服务、源码注入包装、平铺导入兼容层与静态原型已经移除。历史数据的字段兼容与真实恢复证据保留，防止旧记录失去归属。
