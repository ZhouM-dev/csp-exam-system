# 架构说明

> 这份文档讲**代码是怎么分层的、为什么这么分、加东西该往哪加**。
> 功能与流程见《[设计说明](设计说明.md)》，运维见《[运维手册](运维手册.md)》。
> 口径对应 2026-09-26 上线的改造。

---

## 一、分层与依赖方向

```
                    ┌──────────────────────────────────────┐
                    │  web/   HTTP 与页面                   │
                    │  · server.py    Handler、路由、入口、静态资源
                    │  · student_pages.py  学生端页面（mixin）
                    │  · admin_pages.py    管理端页面与接口（mixin）
                    │  · ui.py        CSS 与共用 HTML 片段（含 contest.js 内联）
                    │  · multipart.py 表单/文件名解析
                    │  · urls.py      管理端链接拼装
                    │  · static/contest.js  倒计时/悬浮窗（内联）
                    │  · static/katex/      题面公式（走 /static/katex/ 路由）
                    └───────────────┬──────────────────────┘
                                    │ 只能向下依赖
                    ┌───────────────▼──────────────────────┐
                    │  core/  业务与数据（不碰 HTTP）       │
                    │  · store.py      数据层（含 RULES / LEVEL_MINUTES 两张表）
                    │  · grading.py    判分调度、按点算分、成绩落库
                    │  · wrapper.py    freopen 垫片 + 源文件匹配 + 个人信息文件
                    │  · hydro_client.py 评测站对接（账号/提交/判定/逐点明细/题面）
                    │  · problems.py   建题目（识别出题工程、分配题目编号 / 默认英文名）
                    │  · importer.py   题单批量导入
                    │  · markdown.py   题面渲染
                    │  · security.py   cookie 签名
                    │  · util.py       日志与格式化
                    └───────────────┬──────────────────────┘
                                    │
                    ┌───────────────▼──────────────────────┐
                    │  config.py   唯一配置来源             │
                    │  tests/      纯逻辑自测（不跑网络）   │
                    │  tools/      部署 / 自测入口 / 出题 / **data 迁移**
                    └──────────────────────────────────────┘
```

**规则**（改代码时照着做）：

1. **依赖只能向下**：`web → core → config`。core 里 **不许 import web**，也不许出现 HTML。
   这条没有变（本轮改造也没有破例）：`core/grading.py`、`core/wrapper.py`、`core/problems.py`
   都只回数据/结论，文案与颜色在 `web/ui.py` 与两个 `*_pages.py` 里拼。
2. **业务规则只放 core**：例如"IOI 取最高分""CSP 要不要套 freopen 垫片""考号怎么随机""每点多少分"
   —— 都在 core。页面层只做"取数据 → 套模板"。本轮新增的三处规则也都遵守了这条：
   按点算分在 `grading._point_scores`、提交文件的匹配与大小写严格口径在
   `wrapper.pick_sources`（`strict=True`）、
   **题目编号（`problems.assign_number`）与英文名（`problems.name_of_pid`）在 core**
   —— 页面只负责把这两列显示出来（`store.number_of` / `store.code_of` 读）。
3. **要加一个新页面**：在 `web/student_pages.py` 或 `web/admin_pages.py` 里加一个方法，
   到 `web/server.py` 的 `_route_get/_route_post` 里加一行分发。共用片段放 `web/ui.py`。
4. **要加一条业务规则**：先想清楚它属于 store（数据/规则）、grading（判分/成绩）、
   wrapper（提交前处理）还是 hydro_client（和评测站交互），再落到对应文件；
   不要在页面里写 if-else 拼业务逻辑。
5. **配置只写在 `config.py`**：端口、路径、上限、密码文件位置。别的地方不要再出现字面路径。
6. **每个文件一个职责**，行数控制在几百行内（例外是 `admin_pages.py` 3168 行、`ui.py` 742 行：
   它们是"管理端所有页面""所有共用样式"的集合，按页面继续拆也在预期内）。

## 二、为什么这么分（重构前的样子）

重构前所有代码是**平铺在部署根目录**的 14 个 `.py`，其中 `exam_server.py` 一个文件 2966 行，
同时管着 HTTP、两个端的所有页面、判分调度、成绩计算、建题目流程、大样例服务、题单导入接口。
带来的实际问题：

| 问题 | 现在怎么解决 |
|---|---|
| 改一行判分逻辑要在 3000 行里找 | `core/grading.py` 只有 568 行，讲判分、按点算分与成绩落库 |
| 页面 HTML 和业务规则混在一起 | 页面在 `web/*_pages.py`，规则在 `core` |
| 部署靠逐个 `scp`，漏过文件（真的漏过） | `csp_exam/tools/deploy.sh` 一条命令同步整包 |
| 没有入口约定，服务直接跑 `exam_server.py` | `python3 -m csp_exam` / `run.py`，systemd 指 run.py |
| 配置散在 5 个文件里 | 全部集中到 `config.py`（支持环境变量覆盖） |
| 自测和源码混放 | 自测在 `csp_exam/tests/`，一键 `python3 csp_exam/tools/run_selftests.py` |
| 页面方法之间互相看不见（拆包的经典坑） | 用 **mixin**：`Handler(StudentPages, AdminPages, BaseHTTPRequestHandler)`，`self.xxx` 照旧能用 |

## 三、一次请求的路径（以"学生提交考号文件夹"为例）

```
浏览器 POST /upload?c=c1
   └─ web/server.py            Handler.do_POST → _route_post()          ← 只做分发
        └─ web/student_pages.py _do_upload()
             ├─ web/server.py        _parse_multipart()                 ← 按原始字节解析表单
             │                        （中文文件名不能过 email 模块，会变成 U+FFFD）
             ├─ core/wrapper.py      pick_sources()                     ← 学生文件 → 每题代码
             │                        + find_person_file()             ← 个人信息文件交没交
             ├─ core/store.py        写到 data/contests/c1/uploads/<考号>/…
             │                       并在 results.json 记 picked / missing_sources
             ├─ 起线程 core/grading.py  safe_judge_csp()                ← 判分线程的兜底入口
             │     ├─ core/store.py        rule_of() → freopen / best_of
             │     ├─ core/wrapper.py      wrap()                      ← 只有 CSP 套 freopen 垫片
             │     ├─ core/hydro_client.py ensure_account() / submit() / wait_records()
             │     └─ core/grading.py      _apply_result()             ← 按点算分、落 testcases
             └─ web/student_pages.py  _receipt_page()                  ← 文件结构检查清单
   页面渲染：web/*_pages.py 拼装 → web/ui.py 的 page()/CSS
             （page() 把 static/contest.js 内联进 <head>，倒计时与悬浮窗靠它）
```

## 四、目录速查

| 路径 | 作用 | 部署到服务器 |
|---|---|---|
| `src/csp_exam/` | 服务代码（包，含 `web/static/contest.js` 与 `web/static/katex/`） | `/root/csp-exam/csp_exam/` |
| `src/run.py` | 入口（systemd 用） | `/root/csp-exam/run.py` |
| `src/csp_exam/tests/` | 纯逻辑自测（6 套 167 项） | 同左 |
| `src/csp_exam/tools/` | `deploy.sh`（部署）、`run_selftests.py`、`make_problem_set.py`（出题）、`migrate_v2.py`（data 迁移） | 同左 |
| `build/` | **开发机上的**验收脚本（端到端，跑在服务器上）+ 本机检查 + 题目包源码 + 历史归档 | 只把 `_e2e_*.sh` / `_smoke_pages.sh` / `_regress_all.sh` 传到 `/root/csp-exam/tests/` |

## 五、前端资源的两种走法（本轮新增的一种）

| 资源 | 走法 | 为什么 |
|---|---|---|
| `web/static/katex/`（公式渲染，1.3MB 含字体） | **HTTP 静态路由** `/static/katex/…`（白名单后缀、防目录穿越、30 天缓存） | 体积大、只有题面页用；走缓存更省流量 |
| `web/static/contest.js`（倒计时 + 悬浮窗，约 7KB） | **由 `ui.page()` 读出来内联进 `<head>`**，不发请求 | 每个页面都要用；`server.py` 的 `/static/` 只路由了 katex，内联不依赖静态路由、少一次请求。内联前会把 `</script` 转义掉（否则 HTML 解析器会提前结束脚本） |

`ui.timer_bar()` 只负责把**服务端算好的截止时刻**写进 `data-deadline`，前端只走秒：
**绝不"从打开页面开始倒计"**（刷新就会重算，真考场会算错）。

## 六、兼容层：为什么还有 `csp_exam/compat.py`

历史上那些模块是平铺的，一些运维脚本仍在写 `import store` / `import exam_server`。
`csp_exam.compat` 把这些名字登记进 `sys.modules`（**同一个模块对象**，不是副本），
所以老脚本一行不改也能跑；新代码请用 `from csp_exam.core import store`。

（曾经试过更"自动"的方案——在部署根放 `sitecustomize.py`。但 Ubuntu 自带
`/usr/lib/python3.10/sitecustomize.py`（apport 用），会把我们的影子掉，
**隐式生效的魔法不可靠**，所以改成显式 import。）

## 七、验证方式（改完必跑）

```bash
# 服务器：包内自测（纯逻辑，不动数据、不需要 docker）——6 套 167 项断言
cd /root/csp-exam && python3 csp_exam/tools/run_selftests.py

# 服务器：全路由冒烟——两个端每个页面都请求一遍，37 项
bash /root/csp-exam/tests/_smoke_pages.sh

# 服务器：全量验收 = 冒烟 + 自测 + 7 套端到端（约 10 分钟）
bash /root/csp-exam/tests/_regress_all.sh
bash /root/csp-exam/tests/_regress_all.sh --quick      # 只跑冒烟 + 自测
bash /root/csp-exam/tests/_regress_all.sh roster tree  # 只跑相关的那几套（绕开最慢的 rules）
```

开发机上还有三道几秒级的静态检查（`build/_syntax310.py` 按服务器的 3.10 语法卡一遍、
`_check_names.py` 找"用了没定义"的全局名、`_verify_struct.py` 检查 Handler 上的页面方法与
两条路由分发是否齐全），合成一条：`runtime\python\python.exe build\_check_all.py`。

`_check_names.py` 与 `_verify_struct.py` 是**拆包的产物**：拆包最容易犯的错就是
"某个方法/常量留在原文件里没跟着走"，这两个脚本几秒钟就能找出来。

**端到端那 7 套是"系统该怎么表现"的可执行说明**（改之前先读相关那套，能少走弯路）：

| 脚本 | 管什么 |
|---|---|
| `_e2e_rules.sh` | 三种赛制全流程：统一交文件夹、freopen 只对 CSP、`best_of` 只对 IOI、公布前零反馈、题面（全绿，114 项） |
| `_e2e_new.sh` | 新功能：部分分显示、提交详情的测试点明细、配题搜索下拉 |
| `_e2e_roster.sh` | 名单分组、每场纯随机发号（断言"格式对/场内不重号/不是 1..N"）、考号表、登录与考场隔离 |
| `_e2e_tree.sh` | 提交详情里的目录结构（文件名可点、个人信息文件标注、没匹配到的题） |
| `_e2e_mkproblem.sh` | 建题目：选文件夹 → **浏览器里就地识别** → 点「建题」才上传 → 加进比赛判分（**建题不再自动拿标程自测**：坏标程靠「题目列表」的「自己测试」发现，`/admin/scan` 只剩题面渲染） |
| `_e2e_folder.sh` | 上传整个出题文件夹 + 大样例单独存档 + 学生下载 |
| `_e2e_httpimport.sh` | HTTP 题单导入接口的 `code` 字段（题目默认英文名）真的透传到底（Python 实现，收尾还原编号登记表） |
