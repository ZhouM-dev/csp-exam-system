# 架构与职责

业务正本由单进程 Python HTTP 服务管理；交卷排入持久 SQLite 队列。原版 HydroJudge 完成编译、运行调度、检查器与测试点评分，独立 go-judge 完成沙箱执行。当前版本见 [成熟评测服务](成熟评测服务.md)。

| 模块 | 职责 |
|---|---|
| `core/store.py` | JSON 原子写入、业务锁、比赛/名单/成绩和统一排名 |
| `core/problems.py`、`core/importer.py` | 题目资料导入、数据配对、元信息与编号 |
| `core/submissions.py`、`core/archive.py` | 原始提交、目录/ZIP 验证、源码和 TXT 字节归档 |
| `core/grading.py`、`core/task_queue.py` | 持久排队、参数/源码快照、重启恢复与故障重试、比赛计分 |
| `core/judgelocal.py`、`core/hydro_client.py` | 本地题库校验、限额与格式映射、调用 Hydro，名称保留以兼容旧接口 |
| `core/gojudge.py` | 编译环境及沙箱隔离核验、性能诊断；不作为自编判题器 |
| `deployment/hydro-bridge/bridge.cjs` | 本机鉴权、路径校验、原始字节复制、调用上游 `JudgeTask.handle()` |
| 原版 HydroJudge | 编译、运行、答案检查、测试点状态和评分 |
| 原版 go-judge | 命名空间、用户身份、cgroup 资源限制和隔离执行 |
| `web/`、Tabler 资产 | 会话、时间控制、学生与教师界面 |

数据流为“交卷 → 校验并保存原始字节 → 冻结评测参数/源码 → 持久队列 → HydroJudge → go-judge → Hydro 原版检查器 → 保存成绩 → 统一排名 → 教师公布”。不回退到旧的 Python 判题逻辑。每个测试点配置为 Hydro 的独立子任务；CSP/OI 最后交卷、IOI 最高分属于比赛层规则。

业务 JSON 正本和 SQLite 队列都有自身原子写入与锁。只允许一个应用实例写入同一业务目录。改题面之外的题目、数据、限额变化会撤回过期成绩并提示重测；源码快照与旧成绩保留。

网站、Hydro、沙箱分别绑定 8081、8082、5060 的本机回环地址。Caddy 只代理网站并提供公开许可源码；Hydro 和沙箱没有公网入口。Hydro 只能读题库并写临时评测目录，不能读学生名单、密钥与成绩。部署环境与实际隔离限制以运维文档为准。
