# 运维手册

生产部署根目录 `/root/csp-exam`，应用服务 `csp-exam.service` 监听 8080；沙箱服务 `go-judge.service` 仅监听本机 5050。普通 SSH 用户是 admin，可通过 sudo 管理服务。另一项目 person-station 的服务与目录独立，不在本项目清理范围。

```bash
ssh admin@120.24.168.222
sudo systemctl status csp-exam go-judge
sudo journalctl -u csp-exam -n 80 --no-pager
sudo journalctl -u go-judge -n 80 --no-pager
curl -fsS http://127.0.0.1:8080/health
```

代码以开发工作区为源，只同步 `run.py`、`csp_exam/`、文档和验收工具，禁止覆盖 `data/`、`logs/`。启动入口为 `python3 run.py`，端口由 `CSP_EXAM_PORT` 控制。应用保持单进程，JSON 存储不支持多实例同时写入。

```bash
# 开发机先验收，再部署到已有服务器；采用现有免密 SSH 配置：
bash tests/_regress_all.sh --quick
bash csp_exam/tools/deploy.sh admin@120.24.168.222
# 在实际服务器验收（写入部分全用临时数据，生产冒烟为只读）：
cd /root/csp-exam
sudo bash tests/_regress_all.sh --live
sudo bash tests/_smoke_pages.sh
```

go-judge 使用 `/opt/csp-noi-linux/root` 中的 NOI Linux 2.0 工具链（GCC/G++ 9.3.0、C++14/O2/static），编译和运行都在沙箱内完成。不要删除该根文件系统、挂载配置或沙箱工作目录。实际镜像、服务设置、CPU 型号与核验来源见 [CSP 评测审计](CSP评测审计-2026-10-06.md)。应用对环境和题目限额校验失败时应停止评测，不能补猜限额。

评测并发为 1，限制同一小型云主机上的资源争抢。`/admin/judge` 管理时间倍率，当前 `data/judge_profile.json` 为 1.0，校准基准保存在 `data/judge_benchmark_20261006.json`。没有官方同款硬件的实测结果时，不宣称性能完全一致。倍率修改用于之后的任务；旧成绩需要教师手动重测。

比赛正本在 `data/contests/<id>/`。`exam.json` 是本场题目与公开开关，`roster.json` 是本场名册，`results.json` 是结果；`uploads/` 保留原始交卷与不可变源码快照，`rejudge/` 保留重测前结果。题库、题面、样例、编号、元信息在 `data/problems/`、`data/statements/`、`data/samples/`、`problem_codes.json`、`problem_info.json`。原始上传、成绩及重测归档均是业务资料，不能作为临时文件清除。

批量历史重测使用 `csp_exam/tools/rejudge_history.py`，先阅读其 `--help` 及 [历史重测记录](历史重测-2026-10-07.md)。服务启动会恢复普通在途任务，缺失资料的记录保持需处理状态。教师改题目/限额后必须重测并重新公布。

唯一恢复档案集中在 `/root/csp-history-backup-20261007-012536/`：原始完整备份 `complete.tgz`、本轮源码备份、数据 SHA256 清单和历史恢复证据。旧备份中的独有数据以内容哈希去重保存于 `legacy-data-evidence/`。该目录还承担两份缺失资料记录的恢复依据，不能随旧备份一起清理。部署脚本在其中保留最近一次源码回滚包。

代码回滚应先停应用服务，恢复源码包，再启动并执行只读冒烟；不要把源码回滚和业务数据回滚混在一起。恢复旧数据前核对当前数据保护清单和学生最新交卷。

过期生产夹具、静态原型、Hydro 客户端/账号操作、旧迁移脚本和重复备份已清理。Hydro 容器保持停止且不自动重启，Docker 本身不作为本应用依赖。导入上传暂存目录会在任务结束时清除，日志和生产归档保留。
