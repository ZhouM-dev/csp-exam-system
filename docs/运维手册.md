> 面向"要维护这套系统的人"。设计原理见《[设计说明](设计说明.md)》，
> 日常使用（怎么建比赛、怎么发考号、怎么配题）看《[csp_exam/README.md](../csp_exam/README.md)》。

## 一、在哪里、怎么进

| 项目 | 值 |
|---|---|
| 服务器 | 腾讯云/阿里云 Ubuntu 22.04，公网 `<你的服务器IP>`，2 vCPU / 3.5GB / 无 swap |
| SSH | `ssh -i %USERPROFILE%\.ssh\<你的密钥名> admin@<你的服务器IP>`（普通用户 `admin`；**需要 root 时在命令前加 `sudo`**。`root@` 直登不通，只有 `admin` 的密钥） |
| 学生端 | `http://<你的服务器IP>:8080/`（每场考试的专用入口：`/enter?c=<比赛id>`） |
| 评测站 | `http://<你的服务器IP>/` |
| 管理端 | `http://<你的服务器IP>:8080/admin?key=<管理密钥>`，或从评测站导航「比赛」进 |
| 管理密钥 | `/root/csp-exam/data/admin_key.txt` |
| 评测站管理员 | 账号 `admin`，密码 `/root/hydro-admin-password.txt` |
| 评测站判分机账号 | `judge`，密码 `/root/hydro-judge-password.txt`（**改密码必须用 uid**：`hydrooj cli user setPassword 2 <pw>`） |

## 二、服务与启停

| 组件 | 位置 | 管理方式 |
|---|---|---|
| 考试服务 | `/root/csp-exam`（systemd `csp-exam`，enabled） | `sudo systemctl status/restart/stop csp-exam` |
| 日志 | `/root/csp-exam/logs/exam.log`（另有 `service.log`） | `tail -n 40 /root/csp-exam/logs/exam.log` |
| 评测站 | `/root/hydro`（docker compose 三容器 `oj-backend/oj-judge/oj-mongo`） | `cd /root/hydro && sudo docker compose ps/restart/logs` |
| 开机守卫 | `hydro-judge-guard.service`（oneshot，enabled） | 重启后自动等后端就绪、重启判分机；日志 `/var/log/hydro-judge-guard.log` |
| 评测站界面补丁 | `/root/csp-ui`（内联进模板，改完跑 `bash install.sh /root/csp-ui`） | 见 `/root/csp-ui/install.sh` 头部说明 |

容器都是 `restart: always`，服务器重启后会自动起来；考试服务与守卫是 enabled 的服务，也会自启。

## 三、备份与恢复

备份这些路径（都是纯文件，直接 tar 即可）：

```bash
# 考试服务的全部数据（名单、成绩、提交的代码、大样例、题面缓存）——最要紧的就是它
sudo tar czf /root/csp-exam-data-backup-$(date +%Y%m%d-%H%M%S).tgz -C /root/csp-exam data
# 代码 + 部署的文档：注意代码现在全在 csp_exam/ 里，根目录只剩 run.py
sudo tar czf /root/csp-exam-src-backup-$(date +%Y%m%d-%H%M%S).tgz \
    /root/csp-exam/csp_exam /root/csp-exam/run.py \
    /root/csp-exam/tests /root/csp-exam/docs /root/csp-exam/项目索引.md /root/csp-ui
# 评测站里的题目与记录（如需要）
sudo tar czf /root/hydro-backup-$(date +%Y%m%d-%H%M%S).tgz /root/hydro/data
```

- **考试数据**（名单、成绩、提交的代码、大样例）全在 `/root/csp-exam/data`，恢复=解回去重启服务。
- `data/` 里的内容是 `-C /root/csp-exam data` 打进去的，所以**解开也必须 `-C /root/csp-exam`**
  （见第五节回滚）。
- 代码备份**不要**再写 `/root/csp-exam/*.py`：代码已分层到 `csp_exam/` 下，那个通配符现在
  只能匹配到 `run.py` 一个文件，会把整包源码漏掉。
- 评测站的题目/账号在 mongo 里（`/root/hydro/data/mongo`），恢复要停容器再解包。

服务器上已有的部署备份长这样（部署脚本自己留的）：`/root/csp-exam-data-backup-<时间戳>.tgz`、
`/root/csp-exam-src-backup-<时间戳>.tgz`。

## 四、数据迁移（`migrate_v2.py`：怎么跑、怎么回滚）

老数据（改造之前建的比赛/名单/题目）升级到新结构时用 `csp_exam/tools/migrate_v2.py`。

**它改什么**（脚本头部也有同样的清单，三步）：

1. **比赛字段**：`contests.json` 每场补 `level` / `duration_min`（缺省 `S` / 该级别的默认时长）。
   **不再补 `feedback_mode`** —— 「反馈模式」这套概念已从代码里删掉，老数据里残留的
   `feedback_mode` 字段一律忽略（新代码不读它），不用清、也不用迁移。
2. **考号格式**：老的「`GD-` + 4 位数字」→ 新的「`GD-` + `J`/`S` + 5 位纯随机数」
   —— 同步改 `roster.json` 的 key、`results.json` 的 key、`uploads/<考号>/` 目录名
3. **题目编号升级 + 英文名搬运**（改造后新加的一步，2026-09-27 上线时跑过）：
   把"一个字段兼两职"的老数据拆成**题目编号**（老师侧，`T00001` 形式）与**英文名**（学生侧，
   `candy` 这种）两个字段 —— 具体做两件事：

   | 改哪儿 | 怎么改 |
   |---|---|
   | `data/problem_codes.json`（题库登记表） | 每条记录的 `code` 改写成 `T` + 5 位序号（`T1` → `T00001`、`candy` → `T0000N`）。排序规则：原来已是 `T<数字>` 的按序号排前面，其余按题库标识排后面 —— 老编号之间的相对顺序不乱，且**不重号** |
   | 每场比赛的 `exam.json` | 每道题：`name` = 原来的英文名（取老字段 `code`/`slug`；都取不到就留空），`code` = 新的题目编号，老字段 `slug` **删掉** |
   | 题库登记表（顺带） | 把本场在用的英文名回填成这道题的**默认英文名**（`name`），下次把它加进别的场次时输入框会自动填上 |

   - **学生的文件夹名不会变**：英文名原样搬到 `name`，`store.code_of()` 读的还是同一个值；
     老数据里压根没有英文名的题留空，学生侧退回"按位置"的 `p{题号}`（`p1`、`p2`…，
     迁移前后学生看到的一致）。
   - **编号跟着题走**：迁移按**题库标识（pid）**分配编号，所以同一道题在 c1/c2/c3 里拿到的是
     **同一个** `T00004`；编号分配后不会因为再跑一次迁移而改变。
   - 迁移还会给"只出现在比赛里、题库登记表里没有"的题补一条登记（补编号），
     这样老师侧每道题都有号可查。

**它明确不做的事**：老 `results.json` 里的 `testcases`（逐点明细）**不补** —— 只有改造后
新判分的提交才有；老记录的提交详情页会说明"这一题没有逐点数据"。`results.json` 的键
（`T{题号}` = 本场第几题）也不动。

**幂等**：重复执行不会重复改（已经迁过的会被跳过）。实跑过两次：第二次输出「共 0 处改动，0 个错误」。

**它不改什么**：评测站账号名（`roster.json` 里的 `uname`）**保持原样**，老账号还是老名字
（老单场时代就是 4 位号，后来是 `<场次>-` + 老考号）。历史提交与成绩都还挂在原账号上，
迁移后新发的考号只影响"学生用哪个号登录"，不影响已有记录。

### 跑迁移（四步，顺序别换）

```bash
# 1) 停服务：迁移要改 data/，别让老师和学生在跑
sudo systemctl stop csp-exam
sudo systemctl is-active csp-exam        # 应输出 inactive

# 2) 先备份
sudo tar czf /root/csp-exam-data-backup-$(date +%Y%m%d-%H%M%S).tgz -C /root/csp-exam data
sudo ls -lh /root/csp-exam-data-backup-*.tgz | tail -1

# 3) 预演：只看要改什么，**不写盘**
cd /root/csp-exam && python3 csp_exam/tools/migrate_v2.py --dry-run
#    输出末尾是「共 N 处改动，M 个错误」「这是预演，没有写盘」，退出码 0 = 没有错误
#    三个小节：① 比赛字段 ② 考号格式 ③ 题目编号 / 英文名
#    已经是最新的会写「已是最新，无需改」/「已全是新格式，无需改」/「已是最新，无需改」

# 4) 真跑（再跑一次是安全的：幂等）
cd /root/csp-exam && python3 csp_exam/tools/migrate_v2.py
echo "退出码 $?"        # 0 = 没有错误
```

> ✅ **预演真的不写盘**（2026-09-27 实测）：`--dry-run` 走的是"只算不写"的分支 ——
> 需要编号时用 `_next_number()` 在内存里算，不动 `problem_codes.json`，跑完还额外把登记表
> 原样还回去（脚本里那段 `codes_snapshot` 兜底）。所以**预演前的那次备份仍然要做**（防手滑），
> 但不再是"因为预演会写数据"了。
>
> ⚠️ 只有一个例外：**题单导入的 `--dry-run` 会登记编号**（那是 `core/importer.py` 的行为，
> 不是本脚本）—— 见《[题目单导入接口](../csp_exam/题目单导入接口.md)》注意事项第 7 条。

### 迁移完先自检

```bash
sudo systemctl start csp-exam
sudo systemctl is-active csp-exam            # active
bash /root/csp-exam/tests/_smoke_pages.sh    # 52 项全过
```

再打开管理端「本场管理」逐项核对：考号是不是 `<前缀>-<J/S><5 位>`、名单人数对不对、
**题目编号（`T0000x`）与英文名两列**是不是对得上（英文名就是学生该用的那个名字）、
成绩总表里分数还在、提交详情能打开。

### 回滚（把 `data/` 换回备份）

迁移只动 `data/`、**不动代码**，所以回滚 = 换回 `data/` 目录：

```bash
# 1) 停服务
sudo systemctl stop csp-exam

# 2) 把现在的 data/ 挪开（别直接删，留着查）
sudo mv /root/csp-exam/data /root/csp-exam/data.bad-$(date +%Y%m%d-%H%M%S)

# 3) 从备份解开（必须 -C /root/csp-exam：备份里是 data/ 相对部署根）
sudo tar xzf /root/csp-exam-data-backup-<第 2 步那个时间戳>.tgz -C /root/csp-exam
sudo ls /root/csp-exam/data | head

# 4) 起服务并冒烟
sudo systemctl start csp-exam
sudo systemctl is-active csp-exam
bash /root/csp-exam/tests/_smoke_pages.sh
```

回滚**不用管评测站**：迁移只改考试服务自己的 `data/`，评测站上的题目、账号、评测记录
一直是原样（`problem_codes.json` 里多登记的编号也无害——下次迁移会沿用同一个编号）。

确认没问题之后再删掉 `data.bad-<时间戳>`。

## 五、常见故障

### 1. 所有提交都变成「系统错误」
**原因**：判分机没注册上判题会话（服务器重启后常见）。
**处理**：`cd /root/hydro && sudo docker compose restart oj-judge`，几秒后让学生重交。
开机守卫会在重启时自动做这件事；若还不行，看 `sudo docker compose logs --tail=50 oj-judge`
（出现 `ECONNREFUSED ...:8888` 就是它）。
提交详情页也会把这句话直接显示给管理员。

### 2. 学生说"看不到题面"题面的**真身就是本机的 `data/statements/<pid>.md`**（迁移到自建判题之后就没有"从别处取回来缓存"
这回事了，也没有 6 小时过期）。
先在管理端「**题目列表**」点这道题的「**查看题面**」—— 打开的是**题目详情页**：
左边是 Markdown 原文（能直接改），右边就是学生看到的样子。
右边是空的 ⇒ 这道题还没有题面，在左边写好、点「保存修改」，学生端立刻就是新的。

> ⚠️ **别删 `data/statements/`**（老版运维手册里有一句"改完题面想立刻生效就 `rm -rf data/statements`"，
> 那是"题面存在评测站、本地只是缓存"那个年代的写法）。现在这份文件就是题面本身，
> 删掉等于把这几十道题的题面全丢了 —— 改题面请走题目详情页的「保存修改」。

### 3. 学生说"考号不对/进不去"
- 考号是**按场次随机分配**的：要先确认他用的是**本场链接**（`/enter?c=<比赛id>`）+ 本场考号。
- 用「考号表」核对（`/admin/print?c=<比赛id>`），里面是权威的考号↔姓名对照。
- 老师说"名单里没有他"：在比赛页「从分组导入」把人补进去（追加模式不会影响已发号的其他人）。
- 学生报"进不去"时先看考号格式：`GD-S48213` 中间的短横是 `-`（不是 `_`），字母必须大写；
  考号是**级别 + 5 位纯随机数**，不是从 1 排下来的，不要按小号去猜。

### 4. 学生第一次提交失败、第二次却正常
已修：账号是按需创建的，刚建好时评测站用户缓存可能还没生效，`hydro_client.submit`
会自动等 3 秒重试一次。若仍出现，检查评测站是否在跑。

### 5. 学生说"看不到分"（这是设计如此）
学生端**一律「公布前零反馈」**（没有反馈模式开关）：比赛页只给「已提交 / 未提交」，
交卷回执只查文件结构、不给任何判分信息，查成绩页在老师公布前直接说"成绩还没有公布，请等老师通知"。
判分是照常跑的（老师要看成绩、要讲评），老师在管理端点「公布成绩」后学生立刻能在「查成绩」页
看到分数（随时可以「收回成绩」）。**三种赛制一视同仁 —— IOI 也不再实时给分**，同样要等公布。

### 6. 学生说"我过了这题却 0 分 / 分数比预期低"
按顺序查：
1. **文件夹名 / 文件名 / freopen 的文件名**：三者都要用**题目表里的英文名**（如 `candy`），
   不是题号、也不是页面上的 `T00004` 那种题目编号。命名**一律严格区分大小写**（没有
   "全真 / 训练"之分），`candy.cpp` 与 `Candy.cpp` 不算匹配。
2. **CSP 场次忘写 freopen**：这类代码读不到数据（垫片会把 stdin 读空），与真实复赛一致地拿 0 分。
   提交详情里 `hint` 会写"未检测到 freopen 调用"。
3. **OI/IOI 场次写了 freopen**：这两个赛制用标准输入输出，写了 freopen 反而读不到数据。
4. 打开「提交详情」看**测试点明细三层**和学生的目录树，一眼能看出是哪一步错了。

> 比赛页题目表、交卷回执、考生须知里给学生的都是**英文名**（`candy`），
> 老师侧的本场管理/题目列表才是「题目编号 + 英文名」两列。学生报错时先问清他看到的名字，
> 再在本场管理里核对这两列。

### 7. 提交详情里"测试点明细"点开是空的
这是**评测站的限制，不是页面坏了**：Hydro 的评测记录里 `testCases[i]` 只有
`{id, subtaskId, status, score, time, memory, message}`，**不存测试点的内容**。
本系统的做法是：**输入与标准答案**从题目的数据文件读（题目文档 `data[].etag` 是 base64 的
容器内路径，映射到宿主机 `/root/hydro/data/file/…`）；**学生输出评测机比完就丢，补不回来**，
页面上会明写"评测机没有保存这一点的内容"（不再显示成"学生没有输出"）。
所以看到"输入/标准答案有、学生输出没有"是正常现象。

### 8. 服务器变慢/卡死
历史教训（2026-09-25）：在小机器上**突发启动了几十个 Hydro CLI 进程**（给全班建账号），
加上 snapd 刷新，2 核机器直接失去响应（内核没报 OOM，重启后数据完好）。
现在的防护：建账号按需创建 + 全局串行限速（≥1.5s 间隔）；验收脚本也不再放 `/tmp`（重启会清）。
**建议**：给这台机器加 1–2GB swap（现在零 swap，内存一紧就是硬扛）：
`sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile`
再把 `/swapfile none swap sw 0 0` 写进 `/etc/fstab`。

### 9. 磁盘不够
- 评测站的数据：`/root/hydro/data`（题目测试数据 + mongo）。已清理过导入缓存，可重复清理
  `/root/hydro/data/backend/import/*`（题目数据已进站点，这里只是原始包）。
- 学生提交的文件：`/root/csp-exam/data/contests/<比赛id>/uploads/`，删旧比赛时可一并清。
- **逐点内容转存**：`/root/csp-exam/data/contests/<比赛id>/cases/<考号>/<英文名>-<点号>.txt`
  —— 测试点的输入/输出/答案超过 4KB 时会把完整内容转存到这里（单块最多 256KB）。
  一道几十个点的大数据题会攒出不少文件，删比赛时会跟着比赛目录一起清掉。
- `/var/lib/docker` 占大头（约 8GB），`docker system prune` 可回收未使用的镜像/层。

### 10. 本轮改造踩过、已经修掉的坑（别再犯）

| 现象 | 原因与修复 |
|---|---|
| **老师「公布成绩」之后，学生在学生端看不到任何成绩** | 两个原因叠在一起：① **比赛页在「提交已关闭」时直接 return**，只显示一句"本场比赛已关闭提交"，连下面那块"总分 N 分"都不渲染 —— 而老师考完的自然顺序恰恰就是「关闭提交 → 公布成绩」，于是公布了的成绩被这一句挡掉。改成：关闭提交只多一条提示，**该显示的成绩照常显示**。② **「查成绩」页存在但没有任何入口链接**（导航里没有），学生根本点不进去。现在学生页导航统一挂上「查成绩」（未公布时点进去就是一句"成绩还没有公布，请等老师通知"，也不算白点）；比赛页给出总分时还带一个「看逐题得分 →」直达链接。改这段时又踩了一个小的：`_flash()` 的正文是 `html.escape` 过的，**链接不能塞进 flash 里**（页面上会原样显示 `<a href=...>` 这串字面量），要单独拼一条 —— 所以这类"带链接的提示"改完一定要在浏览器里看一眼实际渲染 |
| **跑一次验收，老师公布的成绩被悄悄收回、提交开关被重新打开** | `tests/_e2e_rules.sh` 收尾时**遍历所有比赛**把 `released` 硬写成 `False`（`_e2e_new.sh` 则硬写 `release c1 0`），两个脚本的 `release()` 辅助函数还顺手带 `open=1`。老师考完点过「关闭提交 + 公布成绩」，谁再跑一次全量验收就把这两项都改回去了。现在两个脚本**开机先快照、收尾按原值还原**（含中途被 Ctrl-C 的 trap），只碰自己改过的那几场。教训：**测试收尾要还原"原值"，不是还原成"默认值"** —— 生产数据里的开关状态是老师的选择，不是测试的默认值 |
| **改了「关闭提交」的语义容易踩偏**：它**只该挡住"交"，不该挡住"看"** | 关闭提交之后，学生仍然要能正常打开比赛页、看题目表、点开题面、下大样例（`/hall` `/problem` `/sample` `/help` `/score` 全部照常 200），只是**交不上去**。服务端的 `/upload` 本来就拒收（`_do_upload` 里判断 `open`），但页面上还摆着"选文件夹 + 提交我的代码"会让人白点一次 —— 现在关闭时提交区只显示一句提示、不渲染表单。回归断言在 `_e2e_new.sh`：关闭后**题面照常打开**、**比赛页不再有上传表单**、**仍然看得到总分** |
| **题面样例没有换行**：代码块里的样例被挤成一行，`3 3 / 1 2 1` 显示成 `3 31 2 1` | `core/markdown.py` 的 `md_to_html()` 结尾用 `"".join(out)` 拼接，而代码块是**逐行 append** 到 `out` 的，空串拼接把换行吃掉了。改成 `"\n".join(out)` 即恢复 |
| **OI/IOI 学生拿不到分**：标准 `cin/cout` 的 A+B，100 分的数据只拿到 17 分 | `judge_csp()` 无条件套了 CSP 的 freopen 垫片 —— 垫片会把评测机喂的 stdin 读空写成 `<英文名>.in`，标准输入输出的程序只能读到 EOF。改成**按 `RULES[rule]["freopen"]` 决定要不要包装**。教训：统一入口时，被合并掉的旧差异要显式补回去 |
| **IOI 的"取最高分"失效**：先交对（100 分）再交错，计分从 100 变成 0 | `judge_csp()` 里三处 `_apply_result(..., best_of=False)` 写死，`RULES["IOI"]["best_of"]=True` 没被读到。改成传 `rule["best_of"]`，并且每个调用点都要显式传（漏一个就是 TypeError，判分线程静默死掉、提交永远卡在"判题中"） |
| **逐点详情取不到输入/答案**：三块全空 | Hydro 的评测记录不存测试点内容。改成"输入与标准答案从题目数据文件读，学生输出补不回来并明写"，见上面第 7 条 |
| **`data/` 被写出孤儿目录**：删了比赛，判分线程还在写 | 判分是异步的，老师可能在判分过程中把比赛删了；照旧写回成绩会把 `data/contests/<cid>/` 重新创建出来。现在 `_apply_result` 先查 `store.get_contest(cid)`，比赛不在了就丢弃结果 |
| **密码以 `-` 开头导致建账号静默失败** | `hydrooj cli` 会把 `-xxxx` 当成命令行开关。现在密码用 `secrets.token_hex(6)`（纯十六进制），且 CLI 用 uid 而不是用户名 |
| **题目列表点「查看题面」永远打不开**（只看到「管理密钥不正确」） | 页面里 `scan_url` 是用 `admin_url(key, path="/admin/scan")` 拼的，那个值**本身已经带 `?key=`**；JS 后面又按统一写法拼了一次 `window.CSP_KEY_QUERY`（也是 `?key=`），于是请求变成 `/admin/scan?key=X?key=X`，服务端把 key 解析成 `X?key=X` → 一律 403。改成传**不带 key 的裸路径**，密钥只由那一次拼接提供。注意**登录 cookie 还有效时看不出来**（`_check_admin` 会退回 cookie 校验），服务一重启 cookie 失效就必现 —— 所以这类"点开才发"的请求要单独测，页面 200 完全不代表它能用（冒烟里已加 `tests/_check_viewstmt.py`：照页面里的拼法把地址算出来再打一次） |
| **「查看题面」「自己测试」两个按钮点了毫无反应**（连悬浮窗都不弹） | `modal()` 渲染副标题时**没给 id**，而两处 JS 的第一句就是 `document.getElementById('pv-sub').textContent = …`（`test-sub` 同理）→ 抛 TypeError → **整个点击处理函数从第一行就死掉**。页面 200、按钮和悬浮窗元素都在，肉眼完全看不出。修法：`modal()` 给副标题 span 固定生成 `id="<mid 去掉 -modal>-sub"`（`pv-modal`→`pv-sub`、`test-modal`→`test-sub`），sub 为空也照样输出。教训：**JS 引用的 id 必须和渲染出来的 id 对齐**，冒烟里加了"页面脚本引用到的 id 是否都真的存在"这一条（同一份 `_check_viewstmt.py`） |
| **`/docs/problemset` 整页是黑底等宽的 Markdown 原文** | `_serve_doc()` 把 .md 整个塞进 `<pre>` 里倒出来，没走渲染 —— 老师看到的是 `#`、`**` 和一整屏表格竖线。改成和题面页同一份逻辑：`<div class="card stmt">{md_to_html(text)}</div>`（`.stmt` 那套 CSS 直接生效，标题/表格/代码块/引用都有样式）。冒烟里那条"文档页 200 就算过"换成真断言：**渲染出来必有 `<h2>` 和 `<table>`**（原文里一个都没有） |
| **新建题目页整页 500：`NameError: name '路径' is not defined`** | 这一页的 HTML 是 **f-string** 拼的，往里面加 JS 时注释里写了 `/* 把 FileList 整理成 {路径: File} */` —— f-string 会把注释里的 `{路径: File}` 当成**表达式**去求值（`File` 被当格式说明），渲染页面时抛 `NameError`，整页 500。**`ast.parse` 查不出来**（语法上完全合法，3.10 语法检查那一关照样过），**只有真请求一次这个页面才发现**。改法：写的时候**所有字面花括号都要 `{{ }}`**（注释里的也一样）。教训：**改完这类 f-string 拼的页面务必真的打开一次**（冒烟脚本本来就请求 `/admin/problem`，别只看"语法过了、别的页 200"就收工） |
| **建题「成功」了，题库里却怎么也搜不到那道题** | 评测站对 **pid 有自己的规矩**（`hydrooj` 的 `model/problem.ts` → `isValidPid`）：只认 `^(?:[a-z0-9]{1,10}-)?[a-z][0-9a-z]*$`，**带短横的前半截还得是注册过的命名空间**。不合规时它**不报错**，而是自己起一个 `#<docId>` 当标识 —— 导入命令的输出里照样有 `Imported problem #63`，调用方以为成功，站点上就多出一道**没有标识的僵尸题**（老师在自己界面里永远搜不到，「题库」里那行还显示 `#63` 或者干脆是空的）。踩过两次：一次是让位标识写成 `G01-2`（数字跟在短横后面它不收），一次是 `_2`/`.` 这类字符。现在两头都堵上：① 生成让位标识**只用字母结尾**（`G01` → `G01b`，见 `core/problems.free_pid`）；② `core/importer.hydro_import()` **导完必须复查**「站点上真的出现了这个 pid 吗」，查不到就报失败、并把评测站自动建的那道清掉（只清"这次导入前后新多出来的、以 `#` 开头的"）。教训：**外部命令"说成功"不等于"结果对了"**，能让它复查就别信它的返回码 |
| **冒烟脚本明明有 `[FAIL]`，汇总却写「0 项失败」** | 不是脚本的锅，是**看输出的人的坑**：汇总行 `结果：$PASS 项通过，$FAIL 项失败` 里的全角冒号 `：` 经过 ssh + 终端编码转换后会把**紧跟其后的那个数字吞掉** —— `：1 项失败` 在屏幕上显示成 `锛? 项失败`，看着就像"0 项失败"。那天 `tests/_check_viewstmt.py` 其实一直在崩（见下一条），我却以为全绿。现在冒烟结尾除了中文那行还打一行**纯 ASCII** 的 `SMOKE_RESULT pass=N fail=N`（认这一行，别认中文那行），并且**有失败就 `exit 1`**（以前永远退出 0，谁都拦不住） |
| **改成 XHR 上传之后，建题失败的提示不见了**（页面干干净净，像成功了一样） | 服务端「建题失败」走的是 `_retry()`：`self._admin_problem(...)` **直接把这一页带着红框提示和回填字段重新渲染出来**（HTTP 200），不是 302 跳转。上传 JS 原来一律 `location.href = xhr.responseURL` —— 没跳转时那个值就是 POST 的地址本身，等于拿服务端渲染好的失败页去换了一次**干净的重载**，提示、认出来的结构、填过的字段全丢。现在按「有没有跳转」分两路：跳转过就 `location.href = 跳转后的地址`（提示在 `?m=` 里）；没跳转就 `document.open(); document.write(xhr.responseText); document.close()` 把服务端那份 HTML 装进来。**另一个小坑**：判断跳转要比**绝对地址** `form.action`，写 `form.getAttribute('action')`（相对地址字符串）永远不等于 `responseURL`，第一次改就是这么白改的 |
| **子检查脚本崩了，冒烟只少算几项、不报错** | `tests/_check_viewstmt.py` 用懒惰正则 `re.search(r"window\.CSP_CAND = (\{.*?\});")` 取页面里的题目数据。页面里嵌的不只是标题/编号，**还有标程源码**（「自己测试」用它预填代码框），源码里一句 `int cnt[26] = {0};` 就带着 `};` —— 正则在那儿截断，`json.loads` 抛 `JSONDecodeError`，脚本**一个字都没打印就退出**。冒烟那头只知道"这一项没输出"，项数悄悄少了 3 项（36→33），**看汇总还以为是全绿**。修法：① `_check_viewstmt.py` 改成**按花括号配对**取那段 JSON（`js_obj()`，字符串和转义都要跳过），并把"能解析"本身也做成一条断言；② 冒烟对子脚本的"没有输出"算失败并**计数**。教训：**"输出变少"和"输出变红"一样要查** |
| **学生点「重新输入考号」没反应，一直卡在「不在名单里」那一页** | 死循环是这么来的：老师**重排考号**之后，学生手上的会话 cookie 还指着旧考号 → `/hall` 判定"不在名单里"，给出 403 提示页 → 那一页的按钮指向 `/enter?c=…` → 而 `/enter` 一看到会话还在就 `redirect` 回 `/hall` → **自己跳自己**，点多少次都是同一页（学生描述就是"点了没反应、卡死"）。修法：按钮带上 `again=1`，`/enter` 见到它就**先把这个场次的会话清掉**再显示考号输入页（和"拿别场会话走这个考场链接"是同一个套路）；那一页的文案也说清了原因（多半是老师重排过考号）并多给一个「考生须知」入口。回归断言在 `_smoke_pages.sh`（4 条）：拿签名合法但不在名单里的旧考号进比赛页 → 403 且按钮带 `again=1` → 点它得 200 登录页 → 会话确实被清掉（再去比赛页是 302 去登录页）。**同一类还有一个**：会话指着的场次被老师删掉时（比如删测试场），`/hall` 原来也往自己跳（浏览器直接 ERR_TOO_MANY_REDIRECTS），现在清掉会话并给一句「这场考试已经不在了」。教训：**会话指着的东西可能已经不存在了**（考号被重排、场次被删），凡是"有会话就跳过去"的分支都要先问一句"那边还在吗" |
| **上传出题文件夹之后，电脑上那些文件「一直被占用、改不了」**（老师反馈） | 锁不在服务端，是**浏览器攥着那份"选中"不放**：`<input type=file>`（尤其 `webkitdirectory` 选中的整个文件夹）在页面上选中之后，浏览器会一直持有这些文件，直到**选择被丢掉**（重新选、清空、关页面）——Windows 上就表现为「文件正在被使用，改不了 / 删不掉」。而我们的建题页恰恰会在这上面停很久：选完 →（本机识别）→ 点建题 → 上传 → **服务端建题那十几秒还停在同一个页面**，于是那十几秒里老师改不了自己的文件。修法两条：① `xhr.upload.onload`（字节传完那一刻，服务端还在干活）就 `releasePicks()` 把四个文件输入框全部清空 —— 老师马上能回去改文件；② 加一个「清空已选文件」按钮，上传前想改也能自己松手（松手只是丢掉"选择"，**不影响已经发出去的请求**：`new FormData(form)` 早就把文件抓下来了）。界面上把这件事写清楚（"浏览器会一直占着这些文件…"），别让老师以为是服务端锁的 |
| **改题面：只刷本地缓存会"自己变回去"** | 题面的**真身在评测站**（题目文档的 `content` 字段，可能是字符串、也可能是 `{zh: ...}` 多语言），考试服务这边的 `data/statements/<pid>.md` 只是**6 小时缓存**（`hydro_client.problem_statement()` 取到就写、过期就重取）。如果"改题面"只写缓存，老师改完当时看着是对的，**最多 6 小时后缓存一过期，题面自己变回旧的** —— 这种"过一会儿自己变回去"最难查。所以保存要**两处都写**：先 `set_problem_statement()`（写评测站 `content`；字符串就直接 `$set`、`{zh:...}` 就只改 `content.zh`，别把其它语言挤掉），成功后再覆盖缓存。另有两个小坑：① 文本**先 base64 再拼进 JS**（题面里引号/反斜杠/换行/中文都正常，直接拼要么转义出错、要么把 argv 撑爆）；② 读题面那条路会做"通用换行"归一（`\r\n`→`\n`）再 `.strip()`，所以写入前也把换行统一成 `\n`，"读出来原样存回去"才是真的没改动 |
| **冒烟里别写死比赛 id（老师会删测试场）** | 冒烟原来写死 `c2` 当"别的考场"，某天老师把 c2 这个测试场删了，那两条断言就开始红 —— 查半天发现是**测试数据变了、不是代码坏了**（顺带说明：上一轮给冒烟加的"有失败就退出非 0"正是靠这个把问题揪出来的，否则它会一直伪装成通过）。现在"别的考场"**动态挑一场**（`list_contests()` 里第一个不等于当前场的），一场都不剩就打印「跳过」而不是报失败。同一类还有：写文件的路径、题目标识，凡是"环境里现成的东西"都要先问一句"它还在吗" |

## 六、验收与自测（改完必跑）

脚本在服务器 `/root/csp-exam/tests/`（开发机同源在 `build/`）：

```bash
cd /root/csp-exam

# ① 包内自测：6 套 163 项断言，纯逻辑、不碰数据、不需要 docker（约 1 秒）
python3 csp_exam/tools/run_selftests.py

# ② 全路由冒烟：两个端每个页面都请求一遍，任何 500/异常都算失败（52 项，约 2 秒）
bash tests/_smoke_pages.sh

# ③ 最常用的自检入口：冒烟 + 自测（实测约 4 秒）
bash tests/_regress_all.sh --quick

# ④ 全量验收：再加 7 套端到端（实测约 10 分钟，其中 _e2e_rules.sh 一套就占 6–7 分钟）
bash tests/_regress_all.sh
# ⑤ 只跑相关的那几套：
#    可选 rules new roster tree mkproblem folder
#    绕开最慢的 rules：roster + tree 实测 9 秒
bash tests/_regress_all.sh roster tree
```

> **平时改点小东西，跑 ③（`--quick`）就够了，别动不动全量。**
> 端到端那几套会真提交、真判分（`_e2e_rules.sh` 一套就 6–7 分钟、要跑几十次评测），
> 一次性全跑对这台 2 vCPU 的小机器压力不小。全量验收留给"批量改动之后"或发版前。
> 只改了某一处就单跑相关的那一套（⑤）。

`_e2e_httpimport.sh` 是 Python 实现（同目录 `_e2e_httpimport.py`），专测 **HTTP 题单导入
接口的 `code` 字段**（题目默认英文名）：它自己造一份合规题单 POST 上去，断言英文名进了
报告和 `problem_codes.json`、编号与重复导入保持一致。**它会登记题目编号，收尾在
`finally` 里把 `problem_codes.json` 还原**，跑挂了也不会留下脏数据。
（夹具要用「题单」格式：`G01-x/题目.md` + `标程.cpp` + `data/1.in|1.out`。
别拿 `tools/make_problem_set.py` 当夹具——那生成的是 Hydro 原生题目包，喂给 importer
会被认成 2N 道题全军覆没。）

> 以前这里记着"`_e2e_rules.sh` 有 5 项已知失败"，那是**上一轮改造中途**的状态：
> 脚本夹具当时拿"带 freopen 的代码"去测 OI/IOI 的计分规则，而改造后只有 CSP 套垫片，
> 这类代码必然 0 分；另外脚本把英文名写死成 `candy`。**这两处脚本夹具后来都修好了**
> （夹具改成标准输入输出、名字从 `exam.json` 里读），所以现在全绿 —— 看到红的先按真问题查，
> 别再当成"已知失败"跳过。

## 七、清理与重置

```bash
# 删掉某一场比赛（名单、题目配置、成绩、提交代码一起删；管理端也有「删除」按钮）
bash /root/csp-exam/reset_exam.sh c2
# 全部清空 + 清空考号池（会停一下服务）
bash /root/csp-exam/reset_exam.sh --all
# 不带参数：列出所有比赛并交互式问你要删哪一场
bash /root/csp-exam/reset_exam.sh
```

- 这个脚本用的是绝对路径，`cd` 到哪都能跑；删单场**不会**重启服务。
- 只清某道题的大样例：`sudo rm -rf /root/csp-exam/data/samples/<题库标识>`
  （目录名是**题库标识**，如 `M02`；不是学生看到的英文名，也不是题目编号）
- 验收脚本会在 `/root/csp-exam/tests/tmp/` 留临时文件，可以随时清：
  `sudo rm -rf /root/csp-exam/tests/tmp/*`
- 服务器上的一次性排障脚本：`sudo rm -f /root/csp-exam/tests/_*.sh` —— **验收脚本别删**
  （`_smoke_pages.sh`、`_e2e_*.sh`、`_regress_all.sh` 是常规工具，剩下的 `_inventory.sh` /
  `_repair.sh` / `_restore_g01.sh` / `_run_all.sh` 之类才是历史遗留）。
- 清掉验收脚本留下的测试比赛（管理端会看到「大样例验收」「2026年9月26日测试」这类名字）：
  用管理端的「删除」按钮，或者 `bash /root/csp-exam/reset_exam.sh c5`。
- 误删/误覆盖了一道题时的恢复：从原题包 zip 里重新导入（开发机 `build/problemset-trim.zip`）。

## 八、改代码的标准流程（踩过的坑都在里面）

```bat
:: 1) 开发机：一条命令跑完本机检查（语法 3.10 / 未定义名字 / Handler 结构 / 验收脚本写法 / 自测），约 5 秒
runtime\python\python.exe build\_check_all.py
:: 2) 开发机：打包上传 + 服务器导入检查 + 重启 + 全路由冒烟 + 自测，约 40 秒
build\_ship.cmd
:: 3) 需要的话，再跑服务器上的全量验收（冒烟 + 自测 + 7 套端到端，约 10 分钟）
ssh -i %USERPROFILE%\.ssh\<你的密钥名> admin@<你的服务器IP> "bash /root/csp-exam/tests/_regress_all.sh"
```

`_ship.cmd` 会顺带同步 `docs/`、`tasks/`、根 `README.md`（服务器上叫「项目索引.md」）
和 `build/_e2e_*.sh`，所以文档与验收脚本不会和代码脱节。
它**在上传前先跑本机检查，不绿就不传**——这是为了不让"服务被打断"的事发生第二次。

要手工分步做（排查时用）：

```bash
# 传一个文件上去
scp -i %USERPROFILE%\.ssh\<你的密钥名> csp_exam\<文件> admin@<你的服务器IP>:/tmp/
ssh -i %USERPROFILE%\.ssh\<你的密钥名> admin@<你的服务器IP> "sudo mv /tmp/<文件> /root/csp-exam/csp_exam/<文件>"
# 先在服务器上"能不能 import"（比直接重启安全，报错也不会把服务打断）
ssh -i %USERPROFILE%\.ssh\<你的密钥名> admin@<你的服务器IP> \
    "cd /root/csp-exam && sudo python3 -c 'import csp_exam,csp_exam.compat'"
ssh -i %USERPROFILE%\.ssh\<你的密钥名> admin@<你的服务器IP> \
    "sudo systemctl restart csp-exam && sleep 2 && systemctl is-active csp-exam"
```

**为什么第 1 步必不可少**：曾经写过一句 3.12 合法、3.10 非法的 f-string，
`py_compile` 在本机过了，服务在服务器上反复重启起不来（systemd 显示 activating）。
`build/_syntax310.py`（`_check_all.py` 的第 1 项）用 `ast.parse(feature_version=(3,10))`
把整棵源码树都卡一遍。

### 换一份考生须知（换年份 / 换考区）

学生端「考生须知」（`/help`）整页渲染的就是 **`csp_exam/notice_guangdong.md`** 这份 Markdown，
页面代码里**没有一句规则文案**（`web/student_pages.py` 只负责套壳 + 附一段「本场信息」）。
所以换通告 = 换这一个文件：

1. 打开考区通告页，复制正文（标题、编号条款、第 5 条那张目录结构图）。
2. 按现有文件的写法贴回去：标题用 `#`；条款写成 `**1.** …`（**编号写成粗体的普通段落**，
   不要写成 Markdown 的 `1.` 有序列表 —— 遇到 7.x/8.x 这种子项列表会断成两段，
   浏览器从 1 重新编号，第 8 条会显示成"1."）；子项用 `- **7.1** …`；目录结构图放进
   ` ``` ` 代码块里（不然行首的 `├──` 会被当成正文）。
3. **先在本地渲染一遍**：`python tests/_check_help.py`（不连服务器、不写数据，30 多项断言，
   它逐条查"通告第 N 条在不在"—— 换了通告记得顺手改里面的断言）。
4. 部署 + 看一眼：`bash csp_exam/tools/deploy.sh`，浏览器打开 `/help?c=<比赛id>`。

两个注意点：

- 通告末尾那句版权声明（"未经NOI竞赛办公室书面授权，不得以任何形式非法侵权转载"）**照录**。
  这份文件**不进公开仓库**（`build_publish.py` 把它排除掉了）：仓库是公开的，把 CCF 的
  通告整篇贴进去属于转载，要发得先拿到授权。公开仓库里 `/help` 会自动退化成
  「以考点下发的纸质通告为准 + 官网链接」那条兜底，不会 500。
- 文件缺失（或改名）时页面不会报错，只是没正文 —— 排障时先看这个文件在不在。

## 十、导出某个分组学生的提交与成绩

每次考完想留档、或者想把学生的代码交给别人看时，一条命令：

```
sudo python3 /root/csp-exam/csp_exam/tools/export_group.py "<分组名>" --tgz
```

它在 `/root/csp-exam/tests/tmp/export-group/` 下摆好一棵目录树（**只读**，不动考试服务任何数据）：

```
总览-每人每场总分.csv        每个学生 × 每场考试的总分矩阵（含合计）
总览-每场情况.csv            每场人数 / 交卷人数 / 组内平均分 / 最高分
逐点明细-全部场次.csv        每个测试点的状态、用时、内存（不含输入输出原文，量太大）
<场次号-比赛名>/成绩.csv      该场全场成绩（含「是否本组」一列）
<场次号-比赛名>/提交代码/<姓名-考号>/…
                            学生交上来的文件夹**原样**（代码 + 个人信息文件 + 他们顺手带的 .exe/.in/.out）
```

学生按**姓名**匹配分组（分组里存的就是姓名；一个人在多组里，就会出现在每个组的导出里）。
CSV 一律带 UTF-8 BOM，Excel 双击不乱码。

拿回本机（在管理机上跑）：

```
ssh admin@<服务器> 'sudo cat /root/csp-exam/tests/tmp/export-group.tgz' > 导出.tgz
```

考试**还在进行中**时也能导，导到的是**当时那一刻**的快照；考完再导一次就是最终成绩。
