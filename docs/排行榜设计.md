# 排行榜设计与运维（2026-10-07）

目标：界面简洁、操作简单、查看成绩和提交高效。

## 官方案例与采用的部分

- [DOMjudge team manual](https://www.domjudge.org/docs/manual/9.0/team.html)：紧凑排名表，题目列使用颜色表达结果，补充信息放在悬停提示，提交详情独立展示。本项目采用淡色分数块和教师点击姓名/分数进入提交；保留 CSP 每题分数、总分和同分并列，不采用 ICPC 罚时。
- [DOMjudge scoring / scoreboard caching](https://www.domjudge.org/docs/manual/main/scoring.html)：成绩与名次作为可重建投影缓存，公开与内部榜分开。本项目分别缓存两种投影，成绩文件版本改变即失效。
- [CMS RankingWebServer 官方源码文档](https://github.com/cms-dev/cms/blob/main/docs/RankingWebServer.rst)：公众排行与评测核心分离。本项目保留轻量分层：`core/scoreboard.py` 只生成允许展示的数据，`web/scoreboard.py` 负责 HTML / JSON 和鉴权；无额外 DOMjudge、CMS、数据库或后台服务。

## 页面与操作

比赛名只显示一次。主表保留名次、学生、总分和各题分数；取消计分说明、重复满分和技术页脚。绿色为满分、浅橙为部分分、灰色为零分，未提交或待评测显示横线。满分放在表头悬停提示中。

搜索姓名；教师也能搜索考号。搜索不会重新计算名次。教师点击姓名查看整份提交，点击某题分数跳到实际题号锚点 `#T{no}` 并展开留存源码。匿名榜单不包含考号、源码路径、教师提交链接。已登录教师打开 `/scoreboard?c=比赛ID` 自动进入教师视图，也可点「公开视图」检查对外展示；教师未公布的预览显示「未公布」。

管理端列表与顶部导航统一使用「排行榜」入口；旧 `/admin/scores` 链接继续有效，呈现同一页面。提交详情的返回按钮回到这张榜单。匿名页面右上角「教师登录」使用现有管理密钥，密码表单 POST 成功后签发原有 HttpOnly / SameSite cookie，并返回原比赛；不更改密钥，不在新跳转 URL 中带密钥，返回地址限定本站管理页面和排行榜。

窄屏在表内横向滚动，名次与姓名固定。无 JavaScript 时首次成绩表仍可阅读，教师链接仍可点击。

## 刷新、性能与权限

- 首次服务端渲染，浏览器每 15 秒请求一次小型 JSON；页面隐藏时暂停，回到前台立即检查。
- ETag 基于当前角色允许看到的 JSON 内容生成。内容未变返回 304，不重画表格；请求超时 10 秒，最多一个在途请求。显示网络错误时仍保留已展示的数据。
- 核心 LRU 最多保存 32 个比赛/角色投影。检查比赛索引、exam、roster、results 的 inode、纳秒修改时间、ctime 和大小；同一文件版本不重复解析包含逐测试点详情的大型 results.json。返回副本防止调用方改写缓存。
- 撤回公开、成绩重测、改名册或题目时，下一次请求立即失效；不使用固定时长缓存。已打开的公开页面在下次成功轮询时隐藏成绩（正常前台轮询最长约 15 秒），不会继续返回旧成绩的 304。已经公开过的内容无法从读者保存的副本中收回。
- 条件请求先鉴权，再生成角色投影；教师 ETag 无法用于取得教师数据。保留本项目赛中零反馈、CSP/OI 最后提交及 IOI 最高分规则。
- HTML 按教师登录态自动选择视图；JSON 接口仍只有显式 `private=1` 且教师鉴权成功才能返回内部投影，避免有 cookie 时无意改变公开接口内容。
