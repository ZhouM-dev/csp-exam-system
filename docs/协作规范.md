# 开发与验收规范

修改前在 `tasks/` 记录任务目标、文件范围和数据保护约束；在 `tasks/lanes.md` 登记使用的范围。当前任务串行执行。用户明确要求并行协作时才安排不同执行者，同一文件由一个执行者维护。

改代码后运行 `bash tests/_regress_all.sh --quick`。涉及评测、提交、重测或管理动作时，在实际沙箱服务器再运行 `--live`。验收失败必须使脚本返回非零，不能靠过滤输出掩盖失败。

所有写入验收使用临时数据目录和独立 HTTP 端口。禁止用现有比赛和学生作为测试夹具。生产冒烟只读取页面；服务部署不得覆盖 `data/` 或 `logs/`。修改评测环境或算法后按影响范围重测，资料不足明确标记。

部署前核对在途任务并备份当前源码。部署后验证服务、当前测试套件、公开开关与数据保护清单。文档、验收命令和页面提示必须描述当前架构。保留必要回归测试，删除重复、失效或污染真实数据的旧测试。

收尾更新任务状态、释放车道并记录实际验证结果与仍需处理的事项。未经用户要求不创建 Git 提交。
