# 协作规范（多对话并行）

> 目的：**把"改一次要等很久"变成"几个对话同时改、各自几秒自检"**。
> 做法是把项目切成互不重叠的**车道**，每条车道有明确的文件白名单，任务写进 `tasks/` 里的任务文件。
> 任何一条指令都可以只描述"要什么"，执行细节按本规范走。

---

## 一、一条改动的标准流程

```
提出 → 建任务文件（定车道 + 文件白名单）→ 认领（一个对话干一条）
     → 改代码 → 本机五项检查（秒级）→ 部署 → 服务器验收 → 更新文档 → 归档任务
```

| 步骤 | 命令 / 动作 | 耗时量级 |
|---|---|---|
| 建任务 | 复制 `tasks/_模板.md` 为 `tasks/T-00NN-短名.md`，填车道与白名单，在 `tasks/lanes.md` 登记占用 | 1 分钟 |
| 改代码 | 只改白名单里的文件 | 视任务 |
| 本机检查 | `runtime\python\python.exe build\_check_all.py` | **约 5 秒** |
| 部署 | 双击 / 运行 `build\_ship.cmd`（上传 → 重启 → 冒烟） | 约 40 秒 |
| 服务器验收 | `ssh … "bash /root/csp-exam/tests/_regress_all.sh"`；只跑相关那几套更省时间：<br>`… \| bash tests/_regress_all.sh rules roster`（可选：`rules` `new` `roster` `tree` `mkproblem` `folder`）<br>`… --quick` 只跑冒烟 + 自测（约 40 秒） | 全量 3–8 分钟<br>挑套件 1–2 分钟<br>`--quick` 约 40 秒 |
| 收尾 | 更新 `docs/` 与包内 README，任务文件勾选"产出"并把状态改 `待验收` | 2 分钟 |

**只有"服务器验收"是几分钟级的**，而它是唯一必须跑全量的环节（因为跑在真机器上）。
开发过程中反复跑的是本机五项检查（秒级）。

两条命令在哪：

| 命令 | 位置 | 说明 |
|---|---|---|
| `build\_check_all.py` | 本机 | 语法(3.10) / 未定义名字 / Handler 结构 / 6 套自测（本机 123 项），**4 项全绿才返回 0** |
| `build\_ship.cmd` | 本机 | 先跑上面这套；绿了才打包上传 → 服务器导入检查 → 重启 → 冒烟(45 项) → 自测。<br>`_ship.cmd` 自己会同步 `docs/`、`tasks/`、`README.md`、`build/_e2e_*.sh`，所以**文档和验收脚本会跟着一起更新**；<br>它的屏幕输出故意是英文（cmd.exe 按 ANSI 代码页读 .cmd 文件，中文会变成乱码命令）。 |

## 二、车道划分（并行靠这个）

**铁律：同一时间，一个文件只属于一条车道。** 需要跨车道改文件时，写进任务文件里并说明原因，
由主对话（或任务负责人）串行安排，不要两个对话同时动同一个文件。

| 车道 | 负责范围 | 文件白名单 |
|---|---|---|
| **A 学生端** | 学生看到的页面、交互、上传/看题面/看成绩 | `csp_exam/web/student_pages.py`、`csp_exam/web/ui.py`、`csp_exam/web/static/**` |
| **B 管理端** | 管理端页面与接口（比赛/名单/题目/成绩/详情） | `csp_exam/web/admin_pages.py`、`csp_exam/web/urls.py` |
| **C 业务核心** | 判分、成绩、数据、考号、建题目、评测站对接 | `csp_exam/core/**`、`csp_exam/config.py` |
| **D 验证与工具** | 检查脚本、验收用例、部署脚本 | `build/**`、`csp_exam/tests/**`、`csp_exam/tools/**`、服务器 `tests/**` |
| **E 文档与站点外观** | 说明文档、评测站界面补丁 | `docs/**`、`csp_exam/README.md`、`csp-ui/**`、根 `README.md` |

### 共享热点（改动要特别小心）

| 文件 | 谁会动 | 约定 |
|---|---|---|
| `csp_exam/web/server.py` | A/B/C 都可能要加一行路由 | **新增路由时只在 `_route_get` / `_route_post` 各加 1–2 行**，不要顺手重构；同一时间只允许一条车道改它 |
| `csp_exam/config.py` | C 与 D 偶尔 | 只增常量，不改名、不删 |
| `docs/设计说明.md` | 每条车道都可能补一句 | 允许，但只加"自己那部分"的句子，冲突时以主对话合并为准 |

### 并行示例

```
对话 1：tasks/T-0003-学生端深色模式.md      （车道 A）
对话 2：tasks/T-0004-管理端导出成绩表.md     （车道 B）
对话 3：tasks/T-0005-G01 数据重做.md        （车道 C）
主对话：合并 + 部署 + 跑全量验收             （车道 D/E）
```

三个对话可以**同时改**，因为它们碰的文件不重叠；最后由一个对话统一部署与验收。

## 三、给"执行某一个任务"的对话的开场指令（直接复制）

```
执行 tasks/T-00NN-短名.md。
要求：
1. 只改任务文件里"文件白名单"列出的文件；需要动其他文件先停下来说明原因。
2. 改完在本机跑 runtime\python\python.exe build\_check_all.py，必须全绿。
3. 用 build\_ship.cmd 部署，并跑一次服务器冒烟（31 项）。
4. 按任务文件里的"产出"逐项打勾，把状态改成"待验收"，并把改动摘要写在任务文件末尾。
5. 不要动数据和别人的车道；不要 git 提交（本项目不依赖 git）。
```

## 四、任务文件格式

见 `tasks/_模板.md`。要点：

- **状态**：`待认领 / 进行中 / 待验收 / 已完成 / 已阻塞`
- **车道 + 文件白名单**：并行安全的前提
- **要做什么 / 不要做什么**：写清楚边界，避免"顺手扩张"
- **产出清单**：可逐项打勾的验收标准（含"本机检查通过""服务器验收通过""文档已更新"）

## 五、省时间的几条经验（都是踩出来的）

1. **本机先查，别急着上服务器**：`_syntax310.py`（3.10 语法）、`_check_names.py`（用了没定义的名字）、
   `_verify_struct.py`（Handler 方法/路由齐全）这三项合起来几秒钟，能挡掉绝大多数"部署后才发现"的错。
2. **改前先想清车道**：如果一次要动三四个文件且跨车道，说明这个任务该拆。
3. **文案/样式这类改动不必跑全量**：本机检查 + 冒烟（40 秒）足够；改了判分/数据/权限才必须跑全量。
4. **服务器验收脚本本身就是文档**：`tests/_e2e_*.sh` 里那几十条断言写明了"系统该怎么表现"，
   改之前先读一眼相关的那套，能少走弯路。**别每次都跑全量**：
   `_regress_all.sh rules`（只跑学生端/赛制那套）通常 1–2 分钟就够，
   动了判分、数据、权限才跑全量。
5. **真机浏览器验证**：UI 改动最后用浏览器点一遍（截图留档），比读 HTML 可靠。
