# 评测时间倍率测算（2026-10-11）

已经在 csp.liteoj.cn 的独立 CSP 沙箱完成基准测试，现有倍率保持 **1.0 / 未标定**。本次获得当前机器的性能基线，尚没有可信参考机器的对应测量，不能把它写成“官方倍率已校准”。

## 当前实测

环境：系统报告 Intel Xeon Platinum，2 个逻辑 CPU；CSP 沙箱容器最多 1 CPU / 1536 MiB。G++ 9.3.0、`-O2 -std=c++14 -static`，与当前 CSP 工具链一致。执行期间无 CSP 名单或待评测任务；LiteOJ 和 CSP 首页均正常响应。只使用既有独立沙箱，没有启动对 LiteOJ 的压力测试或改动其服务。

每类负载热身一次，再交错测量 7 轮，共 32 次基准执行，其中 28 次计入结果；全部输出校验一致。编译时间不计入。测量发生在空闲时段，不代表高峰或跨时段稳定性测试。

| 负载 | CPU 时间中位数 | CPU 最小～最大 | 样本跨度 | 运行墙钟中位数 |
|---|---:|---:|---:|---:|
| 2 亿次整数与位运算 | 458.834 ms | 457.396～459.580 ms | 0.48% | 460.115 ms |
| 400 万整数排序与校验 | 411.748 ms | 409.781～413.844 ms | 0.99% | 413.655 ms |
| 64 MiB 数组随机访问 | 669.238 ms | 665.357～697.821 ms | 4.85% | 672.394 ms |
| 文件写入、文本解析、格式化输出 | 313.448 ms | 312.655～316.495 ms | 1.23% | 315.024 ms |

样本跨度定义为 `(最大值 - 最小值) / 中位数`，不是置信区间或误差上界。文件负载在沙箱临时文件系统中执行，含固定输入的生成、读取和格式化输出，不是磁盘带宽测试。机器在本次样本内较稳定，但这些绝对耗时不能独立确定官方倍率。

原始数据：私有服务器 `/var/log/csp-exam/benchmark-20261011.json`；本地测算包中的 `current-server.json`。固定 C++ 源码 SHA256 为 `f921d721990495b42e953ced873bfa18b67f90f0deae504f5aec99ebde85237f`。

## 倍率如何计算

同一源码、编译器版本及编译参数在参考机器和目标沙箱各测多轮，先检查输出一致、样本足够长且稳定，再分别计算：

`某类负载倍率 = 当前评测机 CPU 中位时间 / 参考机 CPU 中位时间`

四类倍率接近时，以它们的中位数作为统一倍率估计。例如参考机耗时 600 ms、当前机耗时 900 ms，则该负载倍率是 1.5；题目 1000 ms 对应本机有效时限 1500 ms。这是说明公式的例子，不是本次已经算出的结果。

程序 CPU 时间和墙钟时间在 [go-judge 官方接口](https://docs.goj.ac/api) 中是不同字段。比较采用 CPU 时间，队列等待和网页响应耗时不用于计算倍率。墙钟数据用于观察调度或 I/O 等待，不把它乘进 CPU 时限。

当前工具将重复样本跨度超过 15%、四类倍率差异超过 25% 标成警告并阻止自动应用。这些是本项目筛查阈值，不是 CCF 规定。参考结果缺样本、含 NaN/无效时间、元信息不一致、校验不同或耗时过短，也拒绝应用。正式倍率需要针对实测参考机解释；硬件参数与公开单线程测试可以辅助粗估，不能替代同程序测量。

官方 [NOI Linux 2.0 发布资料](https://www.noi.cn/gynoi/jsgz/2021-07-16/732450.shtml) 可用于核对软件环境；安装同一个系统不能证明硬件速度一致。官方或可信参考机器的实测比对未取得前，保持 1.0；当前原创题还应根据标程、预期部分分程序与低效程序在实际数据上的耗时设置各题时限，不用全局倍率代替逐题数据验收。

## 工具与使用

新版工具只测固定受控 C++ 基准，不接受任意选手源码。编译内存从旧的 2048 MiB 改为 1024 MiB，增加文件 I/O、交错多轮采样及墙钟记录。参考机生成文件限定在临时目录，结束清理；源码按原始 UTF-8 字节写入，跨系统不改变哈希。相关目标回归 22 项中 21 项通过，1 项因 Windows 符号链接权限跳过。

服务端独立安装于 `/opt/csp-exam/diagnostics/20261011-calibration/calibrate_judge.py`。没有覆盖 r5 发布目录、重启网站、更改倍率或重测学生成绩；判题流程仍由原版 HydroJudge / go-judge 执行。

将本地“评测倍率测算包”复制到可信 Linux 参考机器，使用匹配的 G++ 9.3.0：

```bash
python3 calibrate_judge.py --native --label '参考机的真实来源和配置' \
  --repeats 7 --output reference.json
```

脚本自带固定源码；`benchmark.cpp` 用于审阅和核对，不接受将其替换为其他程序。记录要注明参考机的真实来源，不能仅改 label 就称其为官方机器。

参考数据经核实后放到当前服务器的私有路径，确保 csp-exam 账号可读；在未开考、无待评测任务的空闲期进行对比：

```bash
sudo bash -c 'set -a; . /etc/csp-exam.env; set +a; \
  PYTHONPATH=/opt/csp-exam/current runuser -u csp-exam -- \
  python3 /opt/csp-exam/diagnostics/20261011-calibration/calibrate_judge.py \
  --reference /var/lib/csp-exam/reference-benchmark.json --repeats 7 \
  --output /var/log/csp-exam/benchmark-comparison.json'
```

默认只出报告。参考与样本验证通过后，加 `--apply` 才写入倍率，并保留整份证据；有警告则拒绝应用。保存后的倍率影响之后启动的评测，已有交卷快照和成绩不会自动变成新倍率结果。考试过程中不要调整倍率；更改后需要按比赛规则安排重测。

## 网上 CPU 参数的补充核查

只读查询本机 `lscpu`、`/proc/cpuinfo` 与阿里云实例类型元数据，确认实例为 **ecs.e-c1m2.large**：2 vCPU，虚拟 CPU 名称为 `Intel(R) Xeon(R) Platinum`，family 6 / model 85 / stepping 4，本次报告约 2499.998 MHz。云端没有公开完整处理器 SKU，不能把它直接指定成某一款 Platinum。虚拟机报告的频率也不能当作每次运行的有效频率。

[阿里云官方 e 系列说明](https://www.alibabacloud.com/help/en/ecs/user-guide/shared-instance-families)明确它采用共享 CPU 调度，多个实例竞争物理 CPU，性能不作保证。本次短时稳定不等于全天或正式考试高峰稳定。

2025 年原卷首页注明全国统一评测硬件为 **Intel Core Ultra 9 285K @ 3.70 GHz，关闭睿频与能效核，96 GB 内存**。本地已收录的 J/S 原卷均有该条款；原卷镜像位于参考库，不把镜像保存冒充 CCF 直供下载。[CCF 发布页](https://www.noi.cn/zxzy/lnzl/jszl/2025-12-15/854079.shtml)提供该年题面与数据入口。2026 年第二轮尚未举行，这里不预先声称 2026 年沿用该配置。

只忽略架构与调度差异、假定相同工作每周期完成量，频率比为 `3.70 / 2.50 = 1.48`。这只是简化模型的结果，**不是可信正式倍率，也不是误差上下界**。目前缺少可据以估计这些差异的匹配测量，不能负责任地指定 1.5 或 2.0 并称为对标校准。

[Intel 官方规格](https://www.intel.cn/content/www/cn/zh/products/sku/241060/intel-core-ultra-9-processor-285k-36m-cache-up-to-5-70-ghz/specifications.html)列出性能核基础频率 3.7 GHz、最高睿频 5.7 GHz。网上通用跑分通常没有保证关闭睿频；例如 [PassMark 当前 285K 页面](https://www.cpubenchmark.net/cpu.php?cpu=Intel+Core+Ultra+9+285K&id=6296)的单线程分数 5085 是用户测试汇总，并未声明按 CSP 的关闭睿频配置测试，不能直接用于换算本场时限。更不能按整颗 CPU 的多核分数或核数比例换算单线程参赛程序。

处理结论：已获得官方历史硬件基线和实际云实例类型，正式倍率仍保持 **1.0 / 未标定**。原创题在目标沙箱的逐题验收继续有效；若要提高与官方时限的对应精度，仍需可信参考配置上的同程序 CPU 时间结果。服务器 `timedatectl` 同时确认 `NTPSynchronized=yes`，时钟同步与程序性能倍率是两个不同事项。
