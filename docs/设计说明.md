> 这份文档讲**为什么这么设计**、**数据长什么样**、**一次比赛从头到尾发生了什么**。
> 想直接上手操作看《[运维手册](运维手册.md)》和《[csp_exam/README.md](../csp_exam/README.md)》；
> 文档索引见《[项目索引](../项目索引.md)》。
>
> 本文口径对应 2026-09-26/27 上线的改造（改动全貌见仓库根的 `整改清单.md`），
> 其中**「题目编号 / 英文名」两个概念的拆分**见第四节。
> 2026-09-27 又删掉了整套「反馈模式」（赛制自带的 `feedback` + 本场 `feedback_mode`）：
> 学生端只剩一种行为 —— **老师公布成绩之前零反馈**，三种赛制一视同仁（见第三节）。

## 一、系统总览

两个人用的东西，两个服务：

```
                        ┌──────────────────────── 用户 ────────────────────────┐
                        │                                                      │
   学生（浏览器）                                   管理员（浏览器）
        │                                                │
        │  ① 打开本场考试链接 + 输考号                      │  ② 从评测站导航「比赛」进入
        ▼                                                ▼
┌───────────────────────────────┐              ┌──────────────────────────────────┐
│  考试服务  :8080              │              │  评测站（HydroOJ）  :80           │
│  /root/csp-exam（systemd）    │  ③ CLI/HTTP  │  /root/hydro（docker compose）    │
│  · 学生端：参赛/交文件夹/看题面 │ ───────────► │  · 题库（题目、测试数据、题面）    │
│  · 管理端：比赛/名单/题目/成绩 │ ◄─────────── │  · go-judge 沙箱评测              │
│  · 大样例存档与下载            │  ④ 读判定    │  · 评测记录（测试点明细）          │
└───────────────────────────────┘              └──────────────────────────────────┘
                                                   oj-backend / oj-judge / oj-mongo
```

- **考试服务**（本项目主要代码）：唯一面向学生的入口。管比赛、名单、考号、提交、成绩、大样例。
  它不自己判题，判题全部交给评测站。
- **评测站**（第三方 HydroOJ，已做界面精简）：题库与判分。管理员也可以直接在那边加题、看测试点明细。
- 两者之间的接口只有三类：**建账号**（`hydrooj cli`）、**提交代码**（HTTP 登录后提交）、
  **读判定**（mongosh 查记录）。见 `hydro_client.py`。

为什么不让 Hydro 直接当考试平台？因为它的比赛模型是"自己注册账号 + 自己报名"，
而这里的场景是**老师发考号、学生零门槛进考场**，还要"每场考试随机发号""交文件夹""大样例下载"——
这些 Hydro 没有，所以在外面套了这一层；判题这种硬骨头继续用 Hydro。

## 二、两个端

### 学生端（`http://<服务器>:8080/`）

共 **8 个页面**（另有 `/logout` 退出与 `/health` 存活检查两个功能入口）：

| 路由 | 页面 | 作用 |
|---|---|---|
| `GET /`、`GET /enter?c=<比赛id>` | 考试入口 | 显示本场考试名 + 级别/赛制徽章 + 考号输入框（提示考号形如 `GD-S10029`：短横是 `-`、字母大写） |
| `POST /enter` | — | 校验考号 → 写会话 cookie → 进本场考试 |
| `GET /contests` | 我的考试 | 这个考号出现在哪些考场（正常只有一场）；多一列「级别」 |
| `GET /hall?c=` | 比赛页 | **倒计时条** + 赛制/级别徽章 + 题目表（**题目英文名** / 满分 / 大样例 / 点开看题面）+ **提交我的文件夹**上传区；**老师公布成绩前只见「已提交 / 未提交」**。**「提交已关闭」只多一条提示，不影响成绩显示**（关闭提交与公布成绩是两件事，老师考完常常是先关提交再公布）；公布后这里给「你的总分 N 分」并带一个直达「查成绩」的链接 |
| `GET /problem?c=&p=` | 题面 | Markdown 从评测站读、带本地缓存；**公式用本地 KaTeX 渲染**。题面里**不写**"本题的读写文件与提交方式"（与真实题面一致，要求都写在考生须知里） |
| `GET /help?c=` | **考生须知**（新增） | 考场规则一页讲完：考号格式、目录结构、个人信息文件、命名红线、按点给分口径、Windows/NOI Linux 编译坑、考场纪律、**考试期间能看到什么**（赛中零反馈、成绩由老师公布） |
| `GET /score?c=&kaohao=` | 查成绩 | 按考号查；老师公布前一律回答「成绩还没有公布，请等老师通知」，公布后才给逐题得分与总分。**学生页导航里统一挂着这个入口**（以前页面存在却没任何地方链接到它，老师公布完学生根本点不进去） |
| `GET /sample?c=&p=` / `&f=` | 大样例 | 大样例列表 / 下载某个文件（附"别把 .in/.out 留在要交的文件夹里"的使用说明） |
| `GET /file?c=&f=` / `&dl=1` | 我的文件 | 看/下载**自己提交的文件**（代码带行号预览，二进制只给下载） |
| `GET /static/katex/<文件>` | — | 本地 KaTeX 资源（css/js/字体；白名单后缀、防目录穿越、30 天缓存） |
| `GET /logout`、`GET /health` | — | 退出 / 存活检查（运维用） |

**提交只有一条路**：比赛页的「提交我的文件夹」（`POST /upload?c=`，multipart，上限 32MB，
可以直接选文件夹，也可以交 zip）。三种赛制**完全一样**：都是交一个以考号命名的文件夹。
交完进「交卷回执」页，只做**文件结构检查**（考号文件夹、每题文件名、大小写、个人信息文件），
不涉及算法对错（**也不给任何判分信息，连"正在判分"都不提**）；这份清单真实考场不会有人替学生做，
所以留在页面上让他离场前自查。

学生登录**没有密码**：考号本身就是凭据。会话 cookie 里存的是 **比赛 id + 考号**
（`make_cookie(cid, kaohao)`，12 小时），不是光凭考号 —— 因为考号是按场次随机分配的，
同一串考号在别的考场属于别人，只认考号会串人。

**学生端一律「公布前零反馈」，没有开关**：判分照常跑（老师要看成绩、要讲评），但老师点
「公布成绩」（本场 `exam["released"]`）之前，学生端拿不到任何判定、分数与逐点状态 ——
比赛页只给「已提交 / 未提交」，交卷回执只查文件结构，查成绩页直接说"成绩还没有公布"。
**三种赛制一视同仁**（IOI 也不再实时给分），公布之后才在「查成绩」页看到分数，
老师随时可以「收回成绩」。以前那套"赛制自带 `feedback` + 本场 `feedback_mode`"两层开关
已按需求整段删掉：只剩一种行为，就不用两个概念去描述它。

### 管理端（`/admin?key=<管理密钥>`，密钥在服务器 `data/admin_key.txt`）

用密钥打开一次后浏览器记住 cookie（`?key=` 会自动下发，导航里的链接都不带密钥了），
也可以从评测站导航「比赛」直接进。共 **9 个页面**（`/admin` 一条路由按有没有 `c=` 分成前两个）：

| 路由 | 页面 | 作用 |
|---|---|---|
| `GET /admin` | 比赛列表 | 新建比赛（**名称 / 赛制 / 级别 / 时长**）+ 已有比赛（赛制、级别、名单数、已提交数、状态）；每行就有「发布成绩 / 收回成绩」「成绩」和「删除」 |
| `GET /admin?c=` | 本场管理 | **本场设置**（级别/时长/考号前缀）、广东考区固定要求提示、名单与考号（导入控件 + **本场名单表**：考号/姓名/评测站账号/提交，**同在第 2 节**）、配题区（**从上到下是「题库待选」→「本场题目」**；本场题目是**表格**：顺序/题目编号/英文名（可编辑）/题目/读写的文件/满分/上下移动）。**整页只有一个底部「保存」按钮**，一次提交全部改动；「重新随机分配考号」「提前建好账号」用 `formaction` 提交到各自接口（表单不能嵌套，页面上一共只有 1 个保存表单 + 2 个发布/开关表单，无嵌套）；页面上**没有「反馈模式」这一项、也没有「成绩总表」按钮**（成绩总表从导航或比赛列表每行的「成绩」进） |
| `POST /admin/new`、`POST /admin/delete` | — | 新建 / 删除比赛 |
| `GET/POST /admin/groups` | 名单分组 | 建/改/删分组（一批学生可反复用于不同考试） |
| `POST /admin/roster` | — | 导入名单（选分组或粘贴姓名）→ **随机分配考号**；追加或重建 |
| `POST /admin/reshuffle` | — | 整场重新随机分配考号（有人提交时按钮不出现） |
| `POST /admin/accounts` | — | 提前把本场账号都建好（后台串行，不点也行） |
| `GET /admin/print?c=` | 考号表 | 本场专用考试链接 + 考号↔姓名对照（可直接打印）+ 发给学生时的提醒清单 |
| `GET /admin/problem`、`POST /admin/problem` | 新建题目 | **一个表单**（multipart）：选完出题文件夹/zip 就**在浏览器里就地识别**（本地读文件、**不上传**），标题/题面/标程自动填进表单，页面上给一行识别结果（几组评测数据 / 几个大样例文件 / 几组题目样例）；**点「建题」时才把整个文件夹上传**，服务端建题时**再认一遍、以它为准**。**英文名（默认）**可留空，**题目编号由系统分配**、标程可直接编辑、题面可预览。建题时也可以**单独传大样例**（表单里的 ⑤，不参与评测、学生可下载）；**页面上没有"给已有题目单独设置大样例"那一块了**（按需求删掉：大样例在建题时一起传） |
| `POST /admin/scan` | — | **只用于题面渲染**（`render=1`）：新建题目页的「预览」与题目列表的「查看题面」。**不再承接文件夹上传**（识别改在浏览器里做了；老页面/书签真传了会被告知去新建题目页识别） |
| `POST /admin/selftest` | — | 自己测试：拿代码跑一遍这道题的全部测试点，返回 JSON（逐点结果 + 最慢点用时；建题时记下了时限的题还给占时限的比例，**超过 50% 会预警**）。入口在「题目列表」每行 |
| `GET /admin/problems` | **题目列表**（新增） | 题库全貌：**题目编号 / 英文名** / 标题 / 测试点 / 时限内存 / 大样例 + 「查看题面」「自己测试」「删除」。表格是**固定布局 + 按列限宽**（长标题省略号截断，全文在 `title` 里悬停可看），**不出现横向滚动条**；「操作」列不参与截断（宁可换行也不裁按钮） |
| `POST /admin/problem`（非 multipart） | **删除题目（假删除）／恢复／彻底删除** | `action=delete&pid=…` 是**假删除**：只在 `problem_info.json` 里打一个 `deleted` 记号，**评测站题目、题面缓存、大样例、编号登记全部保留** —— 所以**题面和历史提交记录照样能看**；列表页把它收进「已删除的题目」（可查看题面）。**一个容器 exec 都不用，实测 0.01 秒返回**（真删要 mongosh + `hydrooj cli` + 刷题库缓存，实测 7 秒 —— 慢的就是这个，所以默认改假删除）。`action=restore&pid=…` 放回列表（瞬间，因为什么都没删）。`action=purge&pid=…` 才是真删：评测站题目 + `problem_codes.json` + `problem_info.json` + `statements/<pid>.md` + `samples/<pid>/` 一起清（不可恢复）。三者都**拒绝动还在某场比赛题目表里的题**（那一场的 `exam.json` 指着它），提示里点名是哪几场第几题；假删除的题也**不进配题候选**（`/api/problems` 过滤掉），要加进比赛先恢复 |
| `GET /admin/scores?c=` | 成绩总表 | 名次、逐题得分与判分结果、未交标注；点分数进某个学生的提交详情 |
| `GET /admin/student?c=&k=` | 提交详情 | 总分/名次、**可点的目录树**（标出个人信息文件交没交）、逐题判分 + **测试点明细三层**（状态条 / 得分构成 / 逐点表） |
| `GET /admin/testcase?c=&k=&n=&t=` | — | 取某个测试点的详情（JSON，给提交详情的悬浮窗用） |
| `GET /admin/file?c=&k=&f=` / `&dl=1` | 学生文件 | 看/下载学生提交的某个文件（代码带行号预览，显示大小与"这一题判分是否用了它"） |
| `POST /admin/exam`、`POST /admin/release` | — | 单独保存本场题目 / 发布·收回成绩、开放·关闭提交；`release` 还承接两个表单动作：`action=save_all`（本场管理底部那个**唯一的「保存」**：本场设置 + 名单 + 题目一次提交）与 `action=settings`（只存本场设置：级别 / 时长 / 考号前缀） |
| `GET /api/problems` | — | 题库清单（配题下拉用，管理端鉴权） |
| `POST /api/problemset/import`、`GET /api/problemset/report`、`GET /docs/problemset` | — | 题单导入接口与文档（见《[题目单导入接口](../csp_exam/题目单导入接口.md)》） |

> **「新建题目」这一页本轮的三处删减**（细节见第五节准备流程与第九节模块地图）：
> ① **不再有「先识别一遍」这一步** —— 识别改在**浏览器里**做（选完文件夹就自动认、文件不上传），
> `POST /admin/scan` **只剩题面渲染**（`render=1`：新建题目页的「预览」 + 题目列表的「查看题面」）；
> ② **不再有「导入后拿标程自测一遍」** —— 建题不再自动拿标程跑数据，要验数据/时限去「题目列表」
> 每行的「自己测试」（`POST /admin/selftest`，返回 JSON）；
> ③ **不再有「覆盖已有题目」** —— 站点上已有同标识题目时建题**直接失败**，提示
> 「站点上已经有题目 X 了。要替换请先到「题目列表」把旧的那道删掉，再回来建」
> （`core/problems.create_problem`，`overwrite=False` 写死）。
> `scan_token` 那套（`data/scan/` 暂存区 + `_save_scan`/`_load_scan`/`_drop_scan`）**已整段删掉**，
> 所以建题失败时页面只回显**服务端认出来的结构**与填过的字段，**重试要重新选一次出题文件夹**。

## 三、三种赛制

新建比赛时三选一。**三种赛制的提交方式是一样的**：学生交以考号命名的文件夹（上传文件）。
差异只剩下面两列（**赛中零反馈**三种赛制都一样，不算差异）：

| 赛制 | 程序怎么写 | 怎么计分 | 适用 |
|---|---|---|---|
| **OI** | **标准输入输出**（`cin`/`cout`、`scanf`/`printf`，不需要 freopen） | 每题**最后一次**提交 | 国内 OI/NOIP |
| **IOI** | **标准输入输出** | 每题**最高分** | IOI / 国际赛 |
| **CSP** | 代码必须 **freopen** 读写 `<题目英文名>.in` / `<题目英文名>.out` | 每题**最后一次**提交 | CSP-J/S 复赛 |

**赛中三种赛制都看不到分**：一律等老师在管理端点「公布成绩」之后，学生才能在「查成绩」页
看到自己的分数 —— IOI 也不例外（它以前是"交完立刻看分"）。

赛制定义集中在 `core/store.py` 的 `RULES`（一处改动，界面文案、判分逻辑、成绩显示全都跟着变）：

```python
"OI":  {"best_of": False, "freopen": False}
"IOI": {"best_of": True,  "freopen": False}
"CSP": {"best_of": False, "freopen": True}
```

三个赛制**都没有 `feedback` 键**：判分时按赛制分叉的只有 `freopen` 与 `best_of` 两个字段，
"给不给实时分"这件事已经不按赛制分了（见下一节）。

`judge_csp` 里**只有这两处按赛制分叉**：`freopen` 决定要不要给代码套 CSP 的文件 IO 垫片，
`best_of` 决定"覆盖还是取最高分"。这两条都必须显式从 `RULES` 里取 ——
线上踩过一次：统一入口时把 `best_of` 写死成 `False`，IOI 先交对（100 分）再交错就变成 0 分；
另一次是无条件套 freopen 垫片，OI 场写 `cin/cout` 的学生拿不到分（垫片会把评测机喂的
stdin 读空，标准输入输出的程序只能读到 EOF）。

### 学生端一律「公布前零反馈」（没有开关）

判分照常跑（老师要看成绩、要讲评），但**老师公布成绩之前，学生端看不到任何判定、分数、
逐点状态** —— 连"部分正确"这种状态都不给，也不提"正在判分"。三种赛制一视同仁。

| 阶段 | 学生看得到 | 看不到 |
|---|---|---|
| 老师公布前（`exam["released"]` 为假） | 距离考试结束的倒计时、每题「已提交 / 未提交」、自己交上去的文件（可点开核对） | 编译信息、测试点通过情况、任何分数（连"部分正确"都没有）、"正在判分"这类提示 |
| 老师点「公布成绩」后 | 「查成绩」页按考号看到逐题得分与总分 | — |

- **公布/收回都在管理端**：比赛列表每行就有「发布成绩 / 收回成绩」，本场管理页上的
  「公布成绩 / 关闭提交」也是同一套开关；公布后学生立刻可见，随时可以收回。
- **IOI 不再是例外**：它以前是赛制自带 `live` 反馈（交完立刻看分），现在同样要等公布。
- 老数据 `contests.json` 里残留的 `feedback_mode` 字段**一律忽略**（新代码不读它），
  不需要迁移脚本去清理。

### 计分口径：按测试点给分，不捆绑

| | 以前 | 现在 |
|---|---|---|
| 计分单位 | **子任务**（子任务里有一个点没过，整个子任务 0 分） | **测试点**（每点固定分值，过几个给几个） |
| 举例 | 20 个点 4 个子任务，子任务 3 过了 1/4 个点 → **0 分** | 同情况 → **拿到那 1 个点的 5 分** |
| 题面里的子任务表 | 决定给不给分 | **只是数据范围的分组说明**，不影响计分 |

- 每点的分值 = 满分 ÷ 测试点数，除不尽时余数摊给前面几个点（`grading._point_scores`）：
  100 分 20 个点 → 每点 5 分；100 分 3 个点 → 34/33/33。这样"全部通过 = 满分"严格成立。
- 总分 = 通过点的分值之和（`grading._apply_result`）；评测机自己算的总分不采信
  （它的口径和这里的按点给分不一定一致），没有逐点数据时才退回评测机的总分。
- **部分分文案**：评测机内部只有 AC/WA 两种状态，照抄会出现"17 分显示答案错误"，
  所以显示层统一走 `graded_text()`：满分→答案正确，中间分→**部分正确（17/100）**，
  0 分才叫答案错误。**学生端在老师公布成绩前连状态都不给**（只有「已提交 / 未提交」），
  公布后才带数字（见上一节）。
- 学生端「考生须知」把这个口径写给了学生：题面里那张子任务表是把测试点按数据范围分了组，
  **不是"整段全过才给分"**，多过一个点就多一截分。

## 四、数据模型

全在 `csp-exam/data/` 下（备份就备份这个目录）：

```
data/
├── admin_key.txt            # 管理密钥（唯一的"管理员密码"）
├── groups.json              # 名单分组：[{gid, name, students:[姓名...], at}]
├── contests.json            # 比赛索引，每场：
│                            #   {id, title, rule, open, released, prefix,
│                            #    level, duration_min, created_at}
│                            #   老数据里可能残留 feedback_mode 字段，新代码不读它
├── problem_catalog.json     # 题库清单缓存（配题搜索用，来自评测站）
├── problem_codes.json       # 题库每道题的**题目编号**与**默认英文名**登记：
│                            #   {items: {题库标识: {code, name, title, at}}}
│                            #   code = T00001 形式的题目编号；name = 建题/导入时填的默认英文名
├── problem_info.json        # 建题时记下的测试点数 / 时限 / 内存 / 标程（题目列表页用）
├── students.json            # 老版本的全局考号池，**只在新旧数据迁移时读**，不再写入
├── statements/<pid>.md      # 题面缓存（6 小时过期）
├── samples/<题库标识>/       # 大样例与题目样例（学生可下载）
│   ├── manifest.json        #   清单：哪些文件、什么用途、多大
│   └── 大样例.in / 大样例.out / 样例1.in …
├── contests/<比赛id>/
│   ├── exam.json            # 本场：{title, notice, open, released, prefix, problems:[…]}
│   │                        #   每题 {no, pid, title, code, name, full}
│   │                        #   code = **题目编号**（T00004，老师侧）
│   │                        #   name = **英文名**（candy，学生侧；学生只看到它）
│   ├── roster.json          # 本场名单：{考号: {name, uname, pw, uid, at}}
│   ├── results.json         # 本场成绩：{考号: {problems, picked, missing_sources, …}}
│   ├── cases/<考号>/<英文名>-<点号>.txt  # 逐点内容超限时的转存（见下）
│   └── uploads/<考号>/…      # 学生提交的原始文件（保持上传时的目录结构）
└── _backup_旧单场/           # 早期"只有一场比赛"时的数据（迁移后留档，可删）
```

### 考号

格式 **`<前缀>-<级别字母><5 位随机数>`**，例如 `GD-S10029`、`GD-J07915`：

- 级别字母 `J` 入门级 / `S` 提高级，同时决定比赛默认时长（J 210 分钟 / S 240 分钟）；
- 5 位数字是 `00001`~`99999` 里的**纯随机数**（`Random.SystemRandom`，不用普通 `random`），
  **不是** `1..人数` 的排列；
- 同一场里不重号（撞号就重取）；不同场次各发各的；
- 已经在名单里的人再导入一次**不会换号**（幂等）；追加的新人拿没被占用的号；
- 改级别等于重发本场考号，所以**有人提交后禁止改级别**（`_apply_settings` 直接拒绝）。

**为什么改成纯随机**（见第七节）：老做法是"把 `1..N` 打乱后分配"，号码本身还是连续的
（会出现 1、2、3 这种小号），学生能推断出考场总人数、也能大概猜到别人手里是什么号。
纯随机之后，号码与姓名、名单顺序、机位、上一场全都无关，猜不到别人。

姓名与考号的对应关系存在**每场的 roster.json** 里，不在全局。评测站账号名是
`<比赛id>-<考号>`（如 `c1-GD-S10029`），这样历史提交不会串人。

### 题目编号与英文名（两个概念，别混）

这是本系统最容易搞混的一处，2026-09 的改造把它彻底拆开了：

| 概念 | 字段 | 谁用 | 格式 | 在哪设置 | 作用 |
|---|---|---|---|---|---|
| **题目编号** | `code` | **老师** | `T` + 5 位数字（`T00004`） | **建题/导入时系统分配，不能改** | 定位查找（「T00004 那道题」）；老师在界面上用它认题 |
| **英文名** | `name` | **学生** | `candy`、`m02`（小写字母/数字/下划线） | 建题时给个默认值 + **本场配题时可改** | 学生建文件夹、命名源文件、写 `freopen("candy.in")` |

**读取入口只有两个**（`core/store.py`）：

```python
store.number_of(prob)   # 题目编号（老师侧）：number → code（必须是 T+5 位）→ ""
store.code_of(prob)     # 英文名（学生侧）：name → code → slug → p{题号}
```

- **`code_of` 会跳过看起来是题目编号的值**（`T00001`）：本模型的 `code` 里存的是老师侧的编号，
  那种值绝不能当学生看到的名字。所以"没填英文名"的题不会把 `T00004` 漏给学生。
- **最后兜底是 `p{题号}` 而不是 `T{题号}`**（`p1`、`p2`…）：`T1` 长得就像题目编号，学生会当成编号；
  `p1` 一看就是"还没起英文名"的占位，老师在本场管理里填上即可。
- **同一场里英文名不能重名**（重名 = 同一个文件夹），保存时查重，重的自动加成 `candy_2` 并在提示里说明；
  不合法的值（大写、短横、中文…）会被拒绝并回退，同样在保存提示里点名。
- **题目编号跟着题走**：同一道题加进哪场比赛、排第几个，编号都不变（键是题库标识 pid）；
  重复导入（题单导入勾了 `overwrite` 时也一样）都不会换号。英文名则是**按场次**的：同一道题在不同场次可以叫不同的名字。
- 分配与登记都在 `core/problems.py`：`next_number()`（现有最大序号 +1）、
  `assign_number(pid, title, name)`（已有编号就沿用，老值 `T1`/`candy` 会**自动升级**成 `T0000x`）、
  `name_of_pid(pid)`（默认英文名）。落盘 `data/problem_codes.json`。
- **题库标识（分类号 `G01`）老师不再接触**，选题按标题搜；`exam.json` 里也不再写老字段 `slug`
  （迁移时它的值被搬到 `name`，键本身删掉）。

> 为什么拆？老师嘴里说的是「T00004 那道题」（要一个**唯一、稳定、可查**的编号），
> 而学生手里要的是**能当文件名用的小写名字**（`candy`）。以前一个字段兼两职：
> 老师改名就动手学生的文件夹名，改场次顺序也会变；拆开之后老师随便改英文名，
> 编号永远稳，学生换场次也不用重新记编号。

### 成绩条目（results.json）

顶层（`{考号: …}`）除 `problems` 外还有：`picked`（判分选中的文件）、`missing_sources`
（没找到代码的题 / 个人信息文件缺失等提示）、`judging`、`submitted_at`；老记录里可能还留着
`structure_ok` / `structure_picked` / `structure_text` 这些**早期目录结构校验**的字段（只读不写）。

每一题（`problems` 的键是 `T{题号}` = "本场第几题"，**不是**题目编号 —— 题目编号是 `T00004`
那种带 5 位数字的）的完整记录：

```jsonc
"T1": {
  "score": 100, "status": 1, "status_text": "答案正确",   // 计分成绩（IOI 是历史最高分）
  "attempt_score": 0, "attempt_status_text": "答案错误",   // 本次提交的真实结果
  "attempt_at": "…", "attempt_record_id": "…",            // 本次的时间与评测记录
  "improved": false, "prev_score": 100,                    // 是否刷新了最好成绩
  "tries": 3, "time": 24, "memory": 17100,                 // 提交次数、用时、内存
  "file": "candy/candy.cpp", "hint": "未检测到 freopen 调用…",  // 判分选中的文件、检查提示
  "record_id": "…",                                        // 计分成绩对应的评测记录
  "testcases": [                                           // 逐点明细（按点给分后新增）
    {"no": "01", "status": 1, "status_text": "答案正确",
     "time": 3, "memory": 17528, "score": 5,
     "input": "", "output": "", "answer": "",
     "truncated": false, "truncated_fields": [], "has_content": false,
     "subtask": "1", "message": ""}
  ],
  "compile_error": "…", "judge_texts": "…"                 // 只有编译错误/系统错误时才有
}
```

`testcases[]` 的约定（`hydro_client.parse_testcases` + `grading._pack_cases`）：

- `no` 是补零字符串（`"01"`）；`time`/`memory` 取不到是 `null`（页面显示 `-`），不是 0；
- `input` / `output` / `answer` 永远是字符串，**两道限长**：解析时按 4KB 截断（`CASE_TEXT_LIMIT`），
  落盘时超 8KB 的整个点转存到 `data/contests/<cid>/cases/<考号>/<英文名>-<点号>.txt`
  （单块最多写 256KB），`results.json` 里只留前 4KB 并标 `truncated` / `detail_file`。
  一道题最多落 100 条逐点记录。不这么做，一道 20 点 × 200KB 的题能把成绩文件撑到十几兆；
- `has_content` 区分"学生没输出"和"这条记录里根本没存内容"——页面才不会把两者都说成"没有输出"；
- 老记录 / 编译错误 / 系统错误 / 还没评完 → `testcases` 是空数组（页面据此给不同的说明）。

> 为什么把"计分成绩"和"本次结果"分开存？IOI 赛制下交一份更差的代码不能覆盖分数，
> 但**提交次数和最近一次结果要如实记录**。早期实现直接在"保留最高分"分支里 return，
> 结果既没记次数、`judging` 标志还永久卡住（成绩表一直显示判题中）。
> IOI 保留最高分时，`testcases` 跟着**计分的那次**提交走，不是最近一次。

## 五、一次比赛的全流程

### 1. 准备（管理员，各做一次）
```
建分组（名单存起来）  →  新建比赛（赛制 + 级别 + 时长）
                     →  建题目（选整个出题文件夹，浏览器里就地识别、点「建题」才上传；
                              建完到「题目列表」点「自己测试」验数据与时限）
```

### 2. 发号（每场一次）
```
从分组导入 / 粘贴名单  →  系统随机分配考号  →  打印考号表（含本场链接与提醒清单）
```
- 考号 = `<前缀>-<级别字母><5 位纯随机数>`（`store.assign_kaohaos`），纯随机、场内不重号；
- 已在名单里的人再导入一次不会换号（幂等）；追加新人拿没被占用的号；
- 整场重排（`reshuffle`）只在**还没人提交**时允许 —— 否则成绩会对错人；
- 考号表上印的链接是本场专用入口：`http://<服务器>:8080/enter?c=<比赛id>`。

### 3. 考试（学生）
```
打开本场链接 → 输考号 → 比赛页（看倒计时/题面/大样例）
            → 交整个考号文件夹（三种赛制都一样）→ 交卷回执：文件结构检查清单（不给判分信息）
```
- 学生端会话绑定考场：拿 A 场的会话访问 B 场会被送回 B 场登录页；考号不在本场名单 → 403。
- 不带考场编号直接输考号时：只在一场出现就自动进入；出现在多场则列出各场链接让他选。
- 可以**反复提交**，每次提交整个文件夹覆盖上一次（OI/CSP 按最后一次计分，IOI 取最高分）。

### 4. 判分（后台线程，最多 3 个并行）
```
POST /upload
  → wrapper.pick_sources()   每题的代码文件对上题目；顺带检查个人信息文件
  → 落盘 uploads/<考号>/…、results.json 记 picked / missing_sources
  → 起线程 grading.safe_judge_csp()
       逐题：CSP 套 freopen 垫片 → hydro.submit() → wait_records() → _apply_result()
```
- **不做目录结构校验**（也不整份退回）：交上来的文件由 `wrapper.pick_sources`
  宽松匹配到各题，匹配不到的题就是"没交这道题"（0 分）。也就是说
  **没有"整份提交被退回"这回事**了，但"文件夹名/freopen 文件名写错 = 这题 0 分"
  的真实语义仍然保留。匹配阶梯：`<英文名>/<英文名>.cpp` → `<英文名>/其它源码`（但文件名不能属于别的题）
  → 任意目录下的 `<英文名>.cpp` → 以英文名开头的唯一文件 → 只有一题又只交一个文件时兜底用它。
- **大小写**：**一律严格区分**（`pick_sources(..., strict=True)`，交卷回执同样按严格口径检查），
  更贴近真实考场（`m02.cpp` 与 `M02` 不互相匹配，并在回执里说明）。
- **广东考区的个人信息文件**：考号目录下应交一个以**本人姓名**命名的 `.txt`
  （内容含姓名/性别/年级/地区/学校/辅导老师/提交的程序）。系统**只检查交没交**、写进
  `missing_sources` 与交卷回执，**不参与判分**。
- **CSP 的 freopen 包装**：Hydro 不支持"题目级文件输入输出"（`redirect` 没实现、`filename`
  会被后端丢掉），所以 `wrapper.py` 在提交前给 C/C++ 代码拼一段垫片：启动时把判题机喂进来的
  stdin 落成 `<英文名>.in` 并把 stdin 读空，结束时把学生写到 `<英文名>.out` 的内容转发回 stdout。
  学生视角与真实复赛一致：写了 `freopen` 的能读到数据，忘写或写错文件名的拿 0 分。
  **只有 CSP 套这个垫片**，OI/IOI 原样提交（见第三节）。
- **账号按需创建**：判分前确保该考号在评测站有账号（`ensure_account`）。不采用"导入名单就给
  全班开号"，因为一个账号要启动一整套 Hydro 进程，一次给 40 人开会把 2 核机器压垮
  （真踩过，见《运维手册·故障排查》）。
- 账号重名（删比赛后重建导致考号重号）时会把密码重置成名册里的，避免"学生永远登录不上"。
- 兜底：`safe_judge_csp` 把整个判分过程包一层，任何异常都落日志并清掉 `judging` 标志，
  不让提交永远停在"判题中"。

### 5. 出成绩（管理员）
```
成绩总表（逐题得分/判分结果/未交/名次）
  → 点进「提交详情」（可点目录树 + 逐题判分 + 测试点明细三层 + 代码）
  → 公布成绩
```
- 未公布时学生只看到「已提交 / 未提交」（没有判定、没有分数）；公布后才带逐题得分与总分。
- 三种赛制**一视同仁**：IOI 也不再实时给分，同样要等老师公布。
- 「提交详情」的逐点表里，**每行的状态可以点**：弹窗一屏给判定/用时/内存/得分、
  一句话结论、输入、学生输出、标准答案。

## 六、与 Hydro 的边界（这些是硬约束）

| 事项 | 结论 | 做法 |
|---|---|---|
| 判题 | 用 Hydro 的 go-judge 沙箱 | 提交 → 记录 → 读判定 |
| 文件 IO 题目 | **不支持** | 提交前包装选手代码（`wrapper.py`），保住"忘写 freopen = 0 分"的真实语义 |
| 学生身份 | 每个（场次,考号）一个账号 | `hydrooj cli user create`；名字带场次前缀，避免跨场同名 |
| 限时/内存 | 写在题目包的 `testdata/config.yaml` | 只写 `problem.yaml` 的 config 字段对已存在的题不生效（踩过） |
| 逐点明细的**判定/用时/内存** | 从评测记录读 | `record.testCases[i]` 有 `status/score/time/memory` |
| 逐点明细的**输入 / 标准答案** | 评测记录里**没有**，从题目数据文件读 | `testCases[i].id`（1 起）对应题目数据文件的 `1.in` / `1.out`；题目文档 `data[].etag` 是 base64 的容器内路径，映射到宿主机 `HYDRO_DIR/data/file/…` |
| 逐点明细的**学生输出** | **补不回来** | 评测机比完就丢。页面上明写"评测机没有保存这一点的内容"，不再显示成"学生没有输出" |
| 题面 | 从评测站读（mongo 的 `content` 字段） | 带本地缓存 `data/statements/<pid>.md`（6 小时过期），学生端自己渲染 Markdown + **本地 KaTeX 渲染公式** |
| 附加文件（大样例） | **不用** Hydro 的 | 它的附加文件只从 `data/sample/` 来且**会同时当成评测数据**，污染判分；所以大样例存在考试服务这边 |

> 逐点内容这条边界是**实测出来的**：Hydro 的评测记录里 `testCases[i]` 只有
> `{id, subtaskId, status, score, time, memory, message}`，**不存内容**。所以"点状态看
> 输入/学生输出/标准答案"这个功能最后落在"输入与标准答案从题目数据文件读、学生输出补不了并明写"上，
> 而不是硬做成"学生没有输出"。

## 七、关键设计决策与取舍

1. **考号按场次随机分配，而且是纯随机数**（而不是全局固定、也不是 `1..N` 打乱）：
   学生猜不到别人的号，同名同姓/跨班重名不冲突，更接近真实考试。老做法"把 `1..N` 打乱后分配"
   号码仍是连续的，能反推考场规模、也能猜号，所以改成从 `00001~99999` 里随机取（场内查重）。
   代价是每场都要学生用**本场链接**进入，所以必须有考号表与专用入口。
2. **学生登录不要密码**：面向中小学生的实操考试，多一道密码就多一堆"登不上"。
   考号 + 本场链接已经足够（并能在名单里核对）。
3. **三种赛制的提交方式统一成一种**（上传考号文件夹）：学生只学一套操作，
   赛制差异收敛到"程序怎么写 / 怎么计分"两件事上（赛中一律零反馈，见第三节）。
4. **按测试点给分（每个点单独算）**：学生"多过一个点就多一截分"，不会出现"同一组里
   别的点没过、已经拿到的点也整段归零"的挫败感；对老师也更好讲评——分数直接对应到
   具体哪几个点。题面里的子任务表保留，作用降级为"数据范围的分组说明"。
5. **题目编号跟题走、英文名按场次走**（改造后拆成两个概念，见第四节）：同一道题在任何场次都是
   同一个**题目编号**（`T00004`，老师认题用），老师改不动它；而**英文名**（`candy`，学生看到的
   文件夹名/freopen 名）是老师在本场配题时定的、可以按场次不同。这样老师随便调名字都不会
   影响"这是哪道题"，学生换场次也不用重新记编号。
6. **学生端只有一种反馈口径：公布前零反馈**（没有"反馈模式"开关）：判分照常跑（老师要看
   成绩、要讲评），但学生端在老师点「公布成绩」之前拿不到任何判定与分数，三种赛制一视同仁。
   少一个开关，就少一处"老师和学生看到的不是同一套规则"的歧义。
7. **总分实时求和**（`store.entry_total`）而不信任存下来的 `total`：早期数据迁移过一批记录，
   出现过"每题 17+0+70 而总分 0"的名次错乱。按题目重算永远是准的。
8. **账号按需创建 + 串行限速**：见第五.4；另给"提前建好账号"按钮，考试前可以预热。
9. **所有判分结果都落盘**（哪怕这次更差）：否则 IOI"保留最高分"分支会漏记提交次数、
   `judging` 标志永久卡住（成绩表一直显示"判题中"）。
10. **管理端只看不改明细**：成绩、目录树、代码都是"读"，唯一的"写"是公布/开关比赛与
    本场设置，避免管理员误操作改坏一名学生的成绩。
11. **不删除第三方模块、只做界面精简**：Hydro 是第三方程序，模块删不干净也升不了级，
    所以用"服务端关权限 + 界面隐藏"实现"对外不可见"（见 `/root/csp-ui`）。
12. **验收脚本进仓库**（`csp-exam/tests/` 与开发机的 `build/`）：每改一处都先跑一遍断言，
    这些脚本本身就是"系统该怎么表现"的可执行说明。

## 八、已知限制

- 考号相当于口令：知道别人考号 + 本场链接就能看到/覆盖他的提交（真实考试里考号也是公开的）。
- 只支持 C / C++ 的自动包装（其他语言能提交但不会做 freopen 适配）。
- **逐点明细拿不到"学生输出"**（评测机不保存）：能看的是判定、用时、内存、得分、
  该点的输入与标准答案。见第六节。
- 老记录（本轮改造之前判的）没有 `testcases`，提交详情页会说明"这一题没有逐点数据"。
- 题面公式由**本地 KaTeX**（`web/static/katex/`，约 1.3MB，含字体）渲染，学生机不需要外网 CDN；
  万一脚本没加载成功，页面会退回显示原始 `$…$`，不影响阅读。
- 评测站的管理员密码明文放在服务器 `/root/hydro-admin-password.txt`（服务器上的 root 本就能做任何事）。
- 网站是 HTTP，没有 TLS；建议只在校园网/内网使用，或后续加反向代理上 HTTPS。
- 判分机重启后需要重新注册判题会话（已用 `hydro-judge-guard.service` 自动处理）。
- 倒计时的**截止时刻**只有比赛时长（`duration_min`）可用，没有"开考时刻"字段：
  按「显式截止 → 开考时刻 + 时长 → 建场时刻 + 时长（仅当还没过）」的顺序推导；
  一个都推不出来时只显示时长、页面上写"以监考指令为准"（**绝不从打开页面开始倒计**）。

## 九、模块地图（`csp_exam/`）

代码按「业务核心 / HTTP 页面」分两层，细节见《[架构](架构.md)》：

| 层 | 文件 | 职责 |
|---|---|---|
| 核心 | `core/store.py` | 数据层：分组/比赛/名册/成绩/大样例清单的读写与规则（`RULES`、`LEVEL_MINUTES`）、纯随机发号、**题目编号（`number_of`）与英文名（`code_of`）的读取**、总分求和 |
| 核心 | `core/grading.py` | 判分调度与成绩落库：`judge_csp`（三赛制共用）、`safe_judge_csp`、`_apply_result`、按点算分（`_point_scores`）、逐点落盘（`_pack_cases`）、部分分文案 |
| 核心 | `core/wrapper.py` | freopen 垫片（`wrap`）、源文件匹配（`pick_sources`）、个人信息文件检查（`find_person_file`）、大小写严格模式 |
| 核心 | `core/hydro_client.py` | 与评测站对接：建账号（限速串行）、登录提交、读判定与逐点明细（`parse_testcases`）、补输入与标准答案（`read_problem_case`）、取题面、查题库 |
| 核心 | `core/problems.py` | 建题目：识别出题工程结构、配对数据、**分配题目编号**（`assign_number` / `next_number` / `load_codes`）、默认英文名（`name_of_pid`）、生成题目包、大样例存档 |
| 核心 | `core/importer.py` | 题单批量导入（zip/目录 → 多道题），CLI + HTTP 接口 |
| 核心 | `core/markdown.py`、`core/security.py`、`core/util.py` | 题面 Markdown→HTML、签名与 Cookie、日志与格式化 |
| 页面 | `web/server.py` | 路由（`_route_get` / `_route_post`）+ `Handler` 组装 + multipart 解析 + 静态资源 + `main()` |
| 页面 | `web/student_pages.py` | 学生端全部页面：入口、我的考试、比赛页、题面、考生须知、交卷回执、查成绩、大样例、文件预览 |
| 页面 | `web/admin_pages.py` | 管理端全部页面：比赛/名单/成绩/提交详情/测试点明细/题目列表/建题目/题单导入 |
| 页面 | `web/ui.py` | 共用 HTML 与 CSS（页面外壳、目录树、代码预览、赛制/级别徽章、倒计时条、悬浮窗、校验清单） |
| 页面 | `web/urls.py`、`web/multipart.py` | 链接拼装、zip/multipart 辅助 |
| 页面 | `web/static/contest.js`、`web/static/katex/` | 倒计时与悬浮窗脚本（**由 `ui.page()` 内联进页面**，不走静态路由）、本地 KaTeX |
| 配置 | `config.py` | 唯一配置来源（端口、路径、上传上限、判分并行数） |
| 自测 | `tests/selftest_*.py` | 6 套纯逻辑自测（142 项断言，不需要 docker） |
| 工具 | `tools/run_selftests.py`、`tools/deploy.sh`、`tools/make_problem_set.py`、`tools/migrate_v2.py` | 自测入口、开发机上一键部署、原创题生成、**data/ 迁移（比赛字段 + 考号改名 + 题目编号升级/英文名搬运）** |
