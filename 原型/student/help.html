二、目录结构（最重要）

题目编号由系统自动给出，你不用猜也不用记
第 1 题 → T1、第 2 题 → T2、第 3 题 → T3⋯⋯ 本场题目表里每题都标着编号，比赛页也能看到。
文件夹名、源文件名、freopen 的文件名，三处都用同一个编号。

在给定磁盘驱动器的根目录下，建立一个以自己考号命名的目录，所有提交文件都放在它里面：

D:\GD-S48213\ ← 考号目录，建在盘符根目录下 ├── 学生56.txt ← 个人信息文件（文件名＝你的名字） ├── T1\ │ └── T1.cpp ← 第 1 题的代码（编号 T1） ├── T2\ │ └── T2.cpp ← 第 2 题的代码（编号 T2） └── T3\ └── T3.cpp ← 第 3 题的代码（编号 T3）
命名红线：写错一个字符，这一题就是 0 分
  • _ 与 - 的区别：GD-S48213 不是 GD_S00001
  • 大小写严格区分：T1 不能写成 t1 或 Tl；后缀必须小写 .cpp
  • 文件夹名不得出现空格（包括前后）
  • 三层名字必须一致：考号文件夹 → 题目编号子文件夹 → 题目编号.cpp
  • 不要交 .in / .out / .exe 等多余文件

五、怎么算分

按测试点给分，过几个给几分——不捆绑。

20 个测试点每个 5 分。过了 9 个就是 45 分；第 9 个点属于哪个子任务、 那个子任务里的其他点过没过，都不影响你已经拿到的这 5 分。

题面里那张「子任务」表，是把测试点按数据范围分了个组，告诉你每段数据值多少分——

  • 它只是分组说明，方便你看出自己的能力边界（比如"小数据能过、大数据 TLE"）
  • 它不是「整个子任务全过才给分」——多过一个点就多一截分

所以做题时不要因为"反正这个子任务过不全"就放弃： 能把暴力分的点拿到手，就先拿到手。

六、编译环境（Windows 与 NOI Linux 的坑）

最终成绩以 CCF 在 NOI Linux 2.0 及指定评测工具下的结果为准。编译问题由考生负责， 因环境差异提出的申诉概不受理。

在 Windows 上这样写到 NOI Linux 会怎样应该改成
__int64无法编译long long
%I64d无法编译%lld 或 cin/cout
CRLF 换行一般无影响，但不建议手工处理文件保持原样即可
文件名大小写随便写找不到文件严格按系统给的编号

本平台用 Linux 上的 g++ 评测，与考场同向；但你在本机用的编辑器与考场不同， 关键写法请自己确认。
